# RFC：系统策略样式下的统一模板配置与审批加载

日期：2026-10-15。状态：实现及隔离验收通过，18003 发布待执行。实现基点 `539a026`，包含已经发布的范围字段改动；应用后端发布基点为 `fddc532`。本次不修改 DSH、Broker、ActPlane 引擎、原生工作区或会话流程。

## 1. 统一入口与最小界面改造

系统保留“系统策略 / 生成记录”两个页签。原“策略与模板”链接兼容进入同一系统策略页。`UnifiedPolicyLibrary` 沿用 `SystemPolicyLibrary` 的表格、搜索、分类、全部策略 / 已配置、勾选提审和详情样式。父模板可折叠；子配置只列实际策略名称、所有 / 具体 Agent、详情，参数和状态放到详情。默认展开第一组已有配置，避免首屏堆叠。

策略助手仅保留在 Agent 页。选择所有 Agent 或一个具体实例后，助手填写模板参数并保存到与手工相同的目录；不新增系统页助手按钮，不接入 Jev。重名实例在范围选项中附加短实例标识，后台始终使用完整实例 ID，不能按产品名称绑定。

## 2. 版本化模板与历史记录

已发布 v1 模板合同保留为历史版本，已有配置和审批不重写。v2 才开放 system / agent 两种范围，要求具体策略名称；系统预设的操作与处置作为受服务端枚举校验的参数。模板仍限定匹配方式、DSL 渲染和允许字段，助手不能添加规则或自由 DSL。原模板覆盖不足继续报错，修改 / 删除访问组的实际影响继续要求明确核对。

新增与编辑模板子配置复用 `TemplateConfigurationDialog`，回填准确的已保存模板版本及参数合同。既有系统配置、用户导入的完整 DSL 使用原编辑器保留匹配方式、动作、原文、ID 和审批历史。目录按已有身份聚合，未复制到第二个可修改副本；兼容记录仍写原存储，新模板记录写版本化配置服务。单个配置只有一个权威写路径，不实施破坏性数据迁移。

所有 Agent 指当前及以后接入的受控实例。指定 Agent 绑定精确实例，共享执行域仍影响该域内的所有会话；界面不展示工作区为新配置范围。历史局部配置保持归属，不能以 Agent 范围重新解释或批量加载。

## 3. 一致的审批与加载合同

手工保存 / 助手生成 → 草案 → 校验并提交统一审批 → 人工批准 → 人工单独应用 → Broker / ActPlane 加载并读取真实绑定回执。保存、勾选、生成、编译及批准均不加载。

新增批量接口 `POST /api/policy-template-configurations/proposals` 接收单一 scope_id、配置 ID / revision、基准 hash / revision、操作、覆盖确认和幂等键。支持同一范围内的新模板与既有系统配置混合提交，保留其他已应用文档；拒绝跨 Agent 混选、范围改变、失效版本、局部配置扩大及未确认的写删覆盖。批准和应用仍通过原统一审批服务，候选哈希、批准回执、目标基线、资源及编译事实必须一致。

Agent 页新增的全局填参 API 为 `POST /api/policy-template-configurations/generate`，scope_id 与 scope 显式校验。全局场景没有虚构某个 Agent 的工作区资源，模型只获得明确要求、用户本次材料、已发布模板及系统约束。未运行实例不显示内核生效，批准后的基线在下一次受控启动核验加载。

旧 confirm 兼容入口改为只记录批准，返回 `application_required=true`。原已应用请求可返回真实历史应用状态，但不能重新加载；新请求必须调用独立 apply，并匹配批准回执。兼容层不再连续调用 approve 和 apply。停用同样先提审、批准、再应用。

## 4. 验收与发布边界

后端 1317 项通过，包含真实 ActPlane parser/compiler、统一审批、跨目标、漂移、历史兼容及新批量配置测试；其中特权加载 I/O 使用隔离适配器，不是新增内核拦截实测。前端 305 项通过，生产构建通过。浏览器使用只读代理核对真实配置名称、继承范围、详情编辑器、精确目标和折叠，不写入正式策略。

发布仅切换 18003 API / UI，保留 Broker PID、Agent 权限与 DSL 快照、DSH 文件和 18000 / 18004。发布前快照、私有 SQLite / UI 备份、源文件哈希和并发任务检查通过后才切换；API 停止超时 3 秒，避免触发 Broker 心跳失效；异常恢复原 API / UI。正式配置不作为测试数据加载。
