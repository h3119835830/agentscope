# AgentScope 启动前工作台、Pi 会话与加载审计

日期：2026-10-04。范围：`/opt/agentscope` 第二层；第三层仅删除顶部介绍。普通采购、销售、库存、财务与 Hermes 仓库均不涉及。

## 页面与职责

第二层顶部采用三个共用当前任务的页签：任务准备与 Pi Agent、策略审核与启动加载、记录与审计。任务选择和新建入口在紧凑工具栏；GitHub 与固定场景在新建对话框内选择。候选完整审查移至第二页签，输入材料、工具记录、DSL 与诊断按需展开。三个面板保持挂载，切换保留表单；任务、页签、新建表单通过 sessionStorage 恢复。第二、第三层内容区不再重复层级、大标题与介绍，面包屑和执行面连接状态保留。

## 会话合同

- `GET /api/tasks/{id}/pi/conversation` 返回任务会话版本、公开轮次、作业状态、候选、版本绑定和允许展示的工具记录；历史流式快照仅返回每轮最后一条，完整增量仍可按游标查询。
- `POST /api/tasks/{id}/pi/messages` 接受 `content`、`request_id`、`expected_revision`。事务保证任务内单轮、请求幂等和会话版本比较；同请求不同消息拒绝。原任务目标变更须新建任务。
- `GET /api/tasks/{id}/pi/jobs/{job}/events?after=N` 查询增量公开事件；`POST .../cancel` 标记中断、撤销该轮凭据并恢复启动前状态。任务启动后工作台只读。
- Pi 锁定 `@earendil-works/pi-coding-agent@1.0.1`，使用 SDK 的 `createAgentSession` 与 `SessionManager.inMemory`。每轮恢复持久化的原生用户消息、公开 assistant 消息与 SDK 压缩条目，调用 `session.prompt`；不是拼接历史提示词。工具事实每轮重新读取及校验。
- 每轮继续在 bwrap 隔离进程内执行，只有七个既有任务绑定工具；仓库、数据库、oracle、任务文件系统不挂载。预算为 180 秒、40 次工具调用、初次校验加至多两次修复。无批准、加载或执行任务工具。
- 持久化用户输入、公开文本、允许展示的工具输入输出、压缩摘要与不可变轮次快照。模型思考块不转存，模型密钥仅在隔离进程环境，临时 HOME 在结束或中断后清理，生成凭据每轮撤销。公开文本中的常见凭据表达进行遮蔽。
- SDK 压缩记录同时保存未被摘要覆盖的保留消息，恢复时通过原生摘要条目与原生消息重新建立上下文，避免仅存 summary 丢失最新需求；保留消息仍严格过滤为用户输入和公开文本。
- 当前候选引用使用独立 ID/hash 与 Draft 对象，避免把正式提案外层误作校验输入。解释回合可以没有候选；新候选必须由真实校验、提交工具落库，旧候选与旧批准记录保留。

## GitHub 适配与版本

普通 GitHub 任务惰性登记固定 commit、原任务、有效 DSH 配置、基础限制与受控资产。只读取固定 commit 的受跟踪 UTF-8 小文件，跳过符号链接、二进制、`.env*`、node_modules，单文件上限 100KB、总量 2MB。未登记资产不能被规则自行扩展引用。项目文档是证据，不授予放宽权限。新增规则执行继续仅支持现有 write/unlink 阻断，语义要求留在 guidance。

补充要求登记为轮次输入来源；每轮冻结可见来源 ID、基础场景 hash、会话版本、上一个候选引用。构建和批准使用该候选所属轮次的上下文，而不是后来新增的消息。旧手工 `task_start` 版本不因新增普通 GitHub Pi 会话而追溯失效；固定场景继续原有强制绑定合同。编译、批准、加载和启动状态来自后端。加载前核对批准版本、策略包 hash、任务 commit、Git HEAD、已登记初始资产与有效 DSH 配置。

## 加载审计

`POST /api/tasks/{id}/launch` 兼容无 body 调用，新增可选 `request_id`、`expected_version_id`，成功返回 `startup_run_id`。每次新请求在预检前冻结任务、场景、输入、候选、轮次、编译、批准与包信息。重试另建尝试；重复请求返回已有结果，失败请求保留已有错误。

加载过程将 `startup_runs.deployment_id` 与已有部署记录在同一事务关联，不按时间猜测属于哪个请求。清理关联限定于该部署的生命周期，拒绝尝试不继承后来成功重试的结束结果。

`GET /api/startup-runs` 支持任务、场景、结果、搜索和数据库分页；`GET /api/startup-runs/{id}` 返回完整快照及真实回执。旧部署以 `legacy:{id}` 展示“历史记录”，缺项为未记录。服务重启将未完成尝试标为中断、实际状态待核实，绝不自动重新加载。

SQLite 增量创建 `pi_conversations`、`pi_turns`、`pi_events`、`startup_runs` 及索引；现有任务、历史策略、批准版本、部署表数据保留。

验收与已复现问题见同日 REVIEW、BUG；取舍见 ADR。

## 记录折叠补充

任务和审计列表按仓库、完整 commit、任务名称（含固定场景名）分组，只展示一个主条目；较早记录默认折叠。任务组优先展示当前选中的实例，否则展示最新实例。工具栏每组一个入口，“任务记录”可查看其他实例及原任务要求。不同目标的原任务、候选、批准和回执独立存储、独立查询，不合并权限或会话。

加载审计在原分页结果内分组，显示各组最新回执，其他加载记录按需展开。总数仍是实际记录数，“本页组数”只指当前页；精确任务筛选保留各任务 ID，通过分组选项区分实例。超过四组的其余条目折叠；较早 Pi 对话默认折叠，只展开最新轮次。这些是前端展示调整，接口、存储及第三层运行时合同保持原样。
