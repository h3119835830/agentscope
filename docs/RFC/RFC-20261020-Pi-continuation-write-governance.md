# RFC：Pi 多轮依据延续与最小目录写权限申请

日期：2026-10-20。状态：实现待发布验收，不代表 RQ5 全链路通过。

## 已确认的问题

旧界面只传最近三轮需求、问题和“已起草 N 项配置”摘要。服务端没有父请求绑定，
每次 WorkspacePolicyAgent 都重新初始化，因此已读场景正文、执行路径与候选参数丢失。
同一登记根中的旧 task.md 仍有读取权限，但不是本轮场景；不能靠加强场景提示词修复。

## 延续合同

- 生成增加可选 `parent_request_id`；指向服务端已完成的不可变生成记录。
- 服务端核对 Agent、配置作用域、参考工作区、阶段与 generation_basis
  （资源、运行代次、策略、系统 DSL、Agent DSL、模板目录）。
- 最多恢复最近三轮真实需求、问题、缺口及冻结候选参数；不信任浏览器对旧回复的摘要。
- 重新验证父请求累计引用的读取回执，包括当前读取权限、身份、根/文件身份与内容指纹；
  恢复正文与执行路径，继续保留“不可信参考资料”角色，不能提升为审批或执行指令。
- 目录结果返回真实 execution_path，不依据项目同名或 task.md 中的绝对路径猜测挂载。
- 累计文件数、正文大小和 80 秒期限仍适用。重复读取已核验文件可幂等返回同一正文。
- 旧记录无完整 generation_basis 时仅展示，不自动续用；“开始新场景”显式断开父指针，
  不删除旧记录。资料漂移不会静默回退成无绑定生成。
- 此改动恢复事实上下文，并不使模型选择变成权威事实；候选仍须人工核对来源与目标。

## 写权限治理

系统策略页选择准确 Agent 后，可申请现有子目录写权限。接口只追加候选授权，
保留原本地规则、网络设置、测试禁止及系统 DSL；不允许资源根、不创建目录、不删除限制。
沿用现有冻结基线、幂等键、人工审批与显式应用合同；批准不等于加载。
显式应用仍按原生命周期暂停并重建该 Agent 执行进程，全部会话受影响。
Pi 没有调用此人工入口的工具能力，不能自批或自行应用。

## 重要：原生能力限制不能伪装解决

本版本保留每个资源根仅一个连续写入例外，以及执行匹配路径最多 63 字节的限制。
原生 ActPlane Clause.unless 为单个 Cond，不能将两个并列允许区间用两条 block 规则表达为并集。
RQ5 长路径和同一资源内“源码＋产物”两个范围可能被拒绝；禁止截短路径、扩大共同父目录、
新增 allow 抵消 deny，或更改 ActPlane ABI。要成功执行该布局，需要另行确定受治理的短路径/
独立资源映射方案，不能把申请入口完成宣称为该场景扩权已完成。

本轮不修改 Broker、ActPlane、数据库历史记录或运行时自动收紧实现。
