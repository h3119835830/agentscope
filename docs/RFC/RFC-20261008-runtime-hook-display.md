# RFC：运行时 Hook 展示恢复

状态：已实现并完成桌面功能验收，2026-10-08。

运行时页面恢复可见的 Hook 触发点、处理链及实际触发记录。历史回放使用独立只读档案投影，不连接当前受管执行器，不调用模型、Broker、连接检查或权限加载。

`GET /api/tasks/{task_id}/archive/runtime-hooks` 返回当前机制说明与该任务保存的实际触发记录；支持有界分页。机制说明明确标注为当前代码定义，不代表旧任务冻结的配置或实际触发证据。记录按保存的作业、请求身份组织，多个策略语句不能重复算成多次触发。

实际记录只投影已保存的触发名称、身份、时间、作业、请求、上下文修订、轮次和 observations 的公开类型、序号及哈希。未知或损坏的材料显示未记录，不默认推定为真实用户消息，不借用当前任务状态补造。

前端沿用工作台样式：运行时入口直接可见；来源和处理链采用紧凑说明；实际触发采用字段与记录形式，细节按需展开。读取失败、空记录、分页、切换任务后的旧请求均须正确处理。

本次只恢复观察与解释能力，不修改 Hook 执行、Agent 上下文、人工审核、策略编译或权限生效逻辑。

合同使用 `history_only=true`、`historical=true`、`live=false`；运行中的任务也读取已保存记录，可手动刷新，不宣称连续实时流。`mechanism.source=current_definition`、`historical_configuration=false`；`events`、`sequence`、`evidence_refs` 均为字符串数组。列表最多每页 200 条，默认 50 条；游标绑定任务及 Hook 分类，按保存时间和作业编号稳定排序。

`trigger.observations` 只表示该次评估保存的上下文快照，不能把每个快照条目都解释为本轮新触发。同请求产生多个作业时保留各次评估及关联请求编号；多个策略语句共享一个作业时只显示一次触发。未知来源、歧义证据、损坏上下文及缺失观测均保留明确的缺失标记。
