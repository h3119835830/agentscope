# RFC：按原生能力重推策略执行映射

2026-10-14 后续收敛决定：固定配置收敛为系统与 Agent，后续按真实域运行时新增；本文绑定、共享影响与生命周期合同保留，四层所有权部分已取代。 见 [当前合同](RFC-20261014-AgentScope-agent-baseline-runtime-policy.md)。历史验收及既有批准范围不变，本轮仅文档修订。

日期：2026-10-14。状态：采纳为后续设计合同；ExecutionUnit/PolicyBinding 尚未按本文完整实现或运行验收。本次是文档审计与修订，不包含应用代码修改、DSH 启动、策略加载或部署。

## 1. 重推范围与保留项

当前固定配置归属为系统 → Agent；工作区/会话是上下文与来源，后续按真实域提出运行时增量。人工审批、生成 Agent 只提案、上层强制约束不可被下层放宽、无可信局部绑定不得回退为 Agent 应用，全部保留。原四层 RFC 已明确“四层配置不等于四个进程/域”，不能将整套架构描述为错误。

撤销原四层 RFC §4 和 ADR 第 4 项中默认“一原生会话一个 DSH worker”的选型。启动连接、原生主体、执行单元和执行机制分别建模；先验证各 Agent 的已有能力，再确定局部策略可以落实到哪些操作。不能通过改写 DSH 工具实现、注入新工具 worker 或案例提示词来满足架构图。

本次同步修订：[总体 RFC](RFC-20261011-AgentScope-policy-control-architecture.md)、[四层 RFC](RFC-20261012-AgentScope-four-layer-policy.md)、[四层 ADR](../ADR/ADR-20261012-AgentScope-four-layer-policy.md)、[会话面板 RFC](RFC-20261014-AgentScope-session-security-workbench.md)、[会话入口 ADR](../ADR/ADR-20261014-AgentScope-session-security-entry.md)及[热更新提案](RFC-20261014-AgentScope-hot-policy-lifecycle-proposal.md)。历史验收事实保留，各次通过范围不扩大。

## 2. 推导所依据的事实

本次复核当前应用工作树 `agentscope-session-security-20261014` 的 vendored ActPlane 源码，而非仅引用另一份 `/opt` 快照：

| 事实 | 代码锚点 | 推论与限制 |
|---|---|---|
| cap_task 为进程标识到单一 u32 域标识的映射 | `actplane/bpf/capability.bpf.h:94–99,522–526` | 同一引擎实例中，一个进程同一时刻只有一个直接活动域 |
| 匹配沿域的祖先链查询 | 同文件 `529–557` | 一个直接域可继承父域约束，不是两个并列会话域同时归属 |
| fork 复制父进程域绑定 | 同文件 `572–576` | 多一个子进程 PID 并不自动产生独立策略 |
| child domain 安装更新 cap_task[pid] | `actplane/bpf/src/lib.rs:648–686` | 可信重新绑定是整个进程的变化，不自动区分并发会话 |
| 重要进程钩子使用 TGID | `actplane/bpf/process.bpf.c:2260,2457` 等 | 不把同进程的线程或 async 会话 ID 当作已支持的隔离身份 |
| Broker 记录 executor_shared；当前局部能力返回不支持 | `backend/broker/instance_runtime.py:486,833–834`；`backend/agentscope_app/instances/policy_targets.py:32–36` | 实例保护不能改称原生工作区/会话独立保护 |
| 现有 DSL 组合读取 system 和实例层 | `backend/agentscope_app/instances/dsl_policy.py:45–47` | 文档增加四层模型不等于已实现四层加载 |

源文件摘要、修订前条款定位和进程身份快照见[审计证据](../REVIEW/evidence/rfc-execution-binding-audit-20261014/audit.json)。实际运行二进制位于 `/var/lib/agentscope-scope-demo/bin/actplane`；本次没有建立从上述源码到该二进制的可复现构建映射，也未新增内核行为验收。因此以上是源码模型事实，不能当作当前部署全部行为的证明。

[原生启动调研](RFC-20261014-AgentScope-agent-launch-adapter-research.md)发现 DSH Web、SDK/ACP 等入口可以在同一运行时保存多个逻辑会话；Hermes 的不同入口也有不同执行拓扑。产品名、独立 profile、session Map、工作区目录或工具标签均不足以证明独占进程或完整 I/O 边界。安装产物与源码快照不一致时，先核对实际入口。已有 DSH 集成的私有 profile 插件和 sandboxPolicy 配置耦合须明确记录，不能声称从未改变原生运行配置；本次不新加或移除这些配置。

## 3. 共性结构和身份

| 对象 | 最小合同 | 权威与边界 |
|---|---|---|
| Connection | launch argv、cwd、受控环境引用、网页/终端打开方式、启动或附着所有权 | AgentScope 启动原生入口；用户输入不是可信执行拓扑证明 |
| AgentInstance | instance_id、连接版本、运行代次 | DSH/Hermes 是类型，不能代替一个登记实例 |
| NativeSubject | 原生 workspace/session 标识、来源、归属和生命周期代次 | 由已核验适配器读取；不通过名称、cwd、PID 猜归属 |
| ExecutionUnit | host/boot、进程开始身份、进程树或共享池成员、可监督边界、所有权、代次 | 是真实执行范围；cgroup 或 PID 本身不证明独占与全部操作覆盖 |
| EnforcementCapability | 机制、覆盖操作、身份粒度、原生取消/恢复能力、证据、限制 | unknown/unsupported/supported 分开；每种机制独立验收 |
| PolicyBinding | Subject ↔ Unit 的关系、机制投影、成员版本、engine_ref/domain_ref（ActPlane 机制适用）、已加载版本和证据 | 可多对一、一对多、尚未解析；禁止默认一会话一 PID |

`engine_ref` 固定 host/boot、watch 进程开始身份、受保护 map/pin 实例及引擎配置版本；ActPlane 域键为 `(engine_ref, domain_id)`，不能将 domain 数字当作全局身份。不同 watcher 可有不同 map 命名空间，同一 PID 上叠加多个 watcher 仍共同约束该进程，不会得到按会话选择规则的能力。

会话恢复、原生内部 ID 轮换或跨工作区迁移重新核验映射。显示层的稳定会话标识与原生内部执行标识可以分别记录，不能默默把新 ID 赋予旧局部授权。跨 cwd 不改变安全主体；未来会话加入共享单元须经过准入校验。

## 4. 两层基线与运行时增量到实际执行的过程

1. 固定逻辑目标、系统/Agent 批准基线与适用运行时变化，生成 DesiredPolicy。系统内置保护归系统层 `system_builtin` 分类，内部存储位置不构成第五个客户配置域。
2. 读取可信 NativeSubject、ExecutionUnit 和能力证据，按每种机制计算 ExecutionProjection。原生工具授权可以覆盖部分操作；不自动等于内核文件访问、后台任务或外部代理受控。
3. 展开执行单元全部共享主体及规则变化、暂停、终止的影响闭包，核验兼容性与目标权限。
4. 人工审批冻结候选摘要、基线、逻辑目标、实际影响闭包、绑定和成员代次。应用前重新校验；漂移失效，不复用旧批准。
5. 按已验证机制应用，分别记录编译、加载、当前活动绑定、真实阻断、反馈和任务效用。恢复/热更新/完整重建的选择取决于能力，不预设每个会话重启一个 worker。

对于已明确批准的同实例同域代次未来会话，正常新增逻辑会话不额外制造授权门禁；按当前基线/运行时合同解释成员准入，执行器、域身份、代次或超出批准范围的变化仍须复核。

共享闭包按真实物理执行身份展开，可跨 Connection/AgentInstance，不以当前页面选中的实例截断。发现无法确认所有权或未经授权的其他主体时，不取得其控制权，不宣称局部应用可用。

### 4.1 共享单元的必要条件

若 S1/S2 共享同一进程，对同一文件的同一次可观察 read 事件分别要求拒绝/允许，当前进程域无法仅凭逻辑 session_id 选择处置。需要已经存在且经验证的更细原生授权边界、覆盖全部相关操作的独立执行边界，或显式返回局部应用不支持。

对同一机制，相同规范化投影及相同状态/能力要求可作为保守等价依据；这只是兼容性条件，不代替已有批准、共享成员准入和完整影响检查。不能仅凭 DSL 文本、规则数量或目录名判断。语义未证明、SMT unknown、状态依赖或覆盖未知时拒绝。禁止静默采用最严格并集，也禁止采用最宽松合并：前者改变其他会话授权，后者丢失保护。扩大到共享集合须生成准确范围的新候选并重新审批。

在共享域中禁止 `/workspace-A/private`，B 会话访问同一路径也可能被拒绝。这是对象范围限制，不是只约束 A 会话的主体隔离。文件路径规则应与主体绑定分开展示和验收。

### 4.2 继承和热更新边界

可以把两层基线与适用运行时约束编译成一个完整包，也可使用已验证的真实父域链。域祖先深度、source 选择、scope_id 权限元数据与对象包含关系各自校验；数字大小不能证明目录包含，深度超限不得静默压掉规则。

[热策略提案](RFC-20261014-AgentScope-hot-policy-lifecycle-proposal.md)继续作为未实现方案保留。epoch/规则版本变化只解决更新方式，不增加会话身份粒度；热更新前同样检查共享范围和可用性闭包。状态、旧 FD、mmap、连接及规则移除后的资源撤销另行验收。

## 5. 生命周期与用户操作

| 用户操作 | 目标和允许方式 | 共享单元必须显示的边界 |
|---|---|---|
| 取消当前任务 | 优先调用已有原生会话取消能力，核验完成状态 | 取消请求送达不证明后台任务、旧句柄和外部执行已结束 |
| 结束逻辑会话 | 更新原生生命周期并核验未完成执行 | 不能因逻辑会话结束而 kill 整个共享服务 |
| 停用本层规则 | 新候选、人工批准、重新计算有效策略 | 保留上层强制保护；局部不可应用则拒绝，不退成 Agent 停用 |
| 停止执行单元 | 核对所有权、共享成员和全部后代后停止 | 只有可信独占边界才可宣称仅影响当前会话；共享停止展示真实中断范围 |
| 系统保护故障 | 按明确的 fail-closed 合同回收受控单元 | 不把整个共享服务被回收记录为单会话取消成功 |

不承诺对任意原生共享进程即时独立撤销 OS 资源。需要停止共享单元才可完成严格撤销时，必须按真实影响另行授权，或依照既有明确系统故障合同执行。无法验证撤销完整性时显示未知/未支持，不能显示安全退出已完成。

## 6. 会话 DSL 可视化合同

沿用会话安全面板的折叠详情和统一审批入口，不新增一套专属编辑器或四套审批器。面板至少区分：

- 系统/Agent 基线和实际域运行时规则，来源会话/工作区另列，含 locked 与可编辑权限。
- 根据基线与适用运行时变化得到的目标规则及原始 DSL；草稿、批准版本与当前活动版本分开。
- 对应机制的实际加载 DSL/投影，包含执行单元、域身份、共享会话范围和核验时间。
- 每条规则覆盖哪些操作，哪些只能配置但暂不可应用，哪些行为指导没有强制执行机制。

目标与实际无法对应时显示差异原因，不能通过规则数量“0”、继承已校验或保存成功推断无保护/已保护。无可信会话归因的内核事件只属于执行单元，不能分摊成该会话命中。未来视觉实现继续遵守[已有界面约定](../design/agentscope-ui-design.md)；本轮没有修改 UI。

## 7. 分阶段实施和验收

先补齐原生入口能力表和只读执行拓扑，再实现统一身份/绑定及影响解析；随后完善两层基线、真实域运行时变更和不支持时的明确拒绝；最后只对已验证机制实现局部正向应用、更新和撤销。具体选用现有原生授权、原生独占 worker/沙箱或其他执行边界，另立实现决策，不在本 RFC 预选 DSH 工具进程。

[四层 RFC A01–A12](RFC-20261012-AgentScope-four-layer-policy.md)保留为历史；A03/A04 的固定工作区/会话层目标不再必需。下列绑定边界仍供适用能力验收参考，当前固定交付门槛按新合同 N01–N10；均不得计为本次运行通过。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A13 | 同 PID、同路径、并发 S1/S2 的处置冲突 | 拒绝局部应用；包、绑定和其他会话权限不变 |
| A14 | fork、孙进程和已验证原生独占边界 | 默认继承同域；只有真实绑定后才承认不同域/隔离 |
| A15 | 共享域热更新 | epoch 变化不改变粒度；局部冲突仍拒绝 |
| A16 | 相同 domain 数字、不同引擎/boot/进程代次 | 不串用回执；共享成员漂移使旧批准失效 |
| A17 | 取消 S1，S2 仍在共享原生服务运行 | 原生取消覆盖被核验；不得误杀服务或虚报独立撤销 |
| A18 | W2 访问 W1 规则中的同一路径 | 验证主体范围；对象规则不得冒充工作区隔离 |
| A19 | DSH/Hermes 原生流程回归 | 工作区添加、会话创建/恢复、上下文、工具、历史和并发保持；无专门提示词修补 |
| A20 | 批准后拓扑、所有权或可用性闭包变化 | 应用前失效；不能沿用旧确认 |

局部能力不足的拒绝验收只证明门禁有效，不证明当前基线与运行时正向管控已完成。完整验收必须同时给出可信主体/绑定、真实 allow/block、后台/共享代理覆盖、原生流程效用及当前发布版本证据。
