## 需求与落点

老师要求用户打开任务或会话后，能清楚看到其当前安全约束，像 App 权限页一样通过勾选、复选和文字配置约束；展示范围包含 DSL、系统控制及通用安全约束，Agent 也能动态提出配置。参观者需要能够直接查看的安全检查、配置与执行结果。

推荐升级现有“Agent连接 → 会话”，保留系统和 Agent 的配置所有权、统一审批和任务历史。会话目录聚合所有已接入且有权读取的会话，提供 Agent 产品筛选和实例定位；不能把“全部会话”解释为未接入 Agent 或未经授权的会话。2026-10-14 真实页面已显示 18 条聚合记录，主要缺口在会话配置视角和通用约束投影，而非完全没有会话目录。

## 界面方案

默认采用“会话权限面板”：左侧选择会话，右侧集中显示当前安全约束、归属、执行方式及状态；旁路提供“全会话安全对照”，用于查看不同会话的约束差异。二者读取同一会话安全视图，不能各建一套配置存储。窄屏转为会话目录和详情的顺序导航。

当前约束表默认展示，不把全部继承规则折叠到首屏之外。DSL、编译规则和内核证据按需展开。当前约束和候选变更分区，未应用候选不计为保护。配置归属分系统、Agent；运行时变化另按实际域展示，工作区/会话作为来源；执行方式分内核规则、权威执行控制、普通业务接口校验、行为指导和建议，其中业务接口校验仅在受信适配器实际返回证据时展示，不擅自更改普通业务接口。

文件、网络、工具或审批门等支持结构化表单的约束使用勾选、复选、路径和条件字段。行为指导使用自然语言文本，不为其伪造 OS DSL 或强制执行状态。复杂 DSL 仍保留高级编辑与精确规则映射，结构化编辑器只能处理已支持的语法子集；无法无损映射的现有 DSL 保持原文，只读展示或进入高级编辑，不能静默重写。

“安全检查”只读汇总已登记范围、继承基线、来源和绑定、执行能力、配置冲突及过期候选，不执行危险探针，不根据没有命中记录推断安全；未核验或信息不完整必须显示未知。真实 allow/block 探针放在隔离测试任务中单独执行。

## 变更与停用

在会话入口起草或停用实际域运行时规则 → 保存候选 → 校验真实域与能力 → 查看变更、共享范围及继承影响 → 人工批准 → 显式应用 → 核验回执。开关只改变候选，不直接改变运行权限。取消编辑丢弃未保存输入；撤回候选保留历史；已应用规则停用是新的审批变更。

系统或 Agent 继承规则只读，并提供所属配置入口。用户从会话发起上层修改时必须明确展示其实际影响；不得把整个 Agent 的变更写成仅影响当前会话。Agent 动态配置复用相同候选和审批合同，Agent 不能自行批准、扩大权限或调用加载器。会话取消/结束、规则停用和执行单元停止分别建模；仅在独占执行单元及后代覆盖已证明时才可终止 cgroup/子树。共享服务使用原生会话接口并核验实际取消/撤销覆盖，不能杀整个服务后声称只结束当前会话。

## 统一安全视图

会话身份使用精确 instance_id、session_id 及可信 workspace_id；运行证据另带 generation、domain、加载包摘要和读取时间。每条约束保留原始 constraint_id、owner、目标、来源引用、语义、enforcement_kind、verification_state、版本和已有权威证据引用。此视图是只读投影，不能成为第二套授权库。另列系统/Agent 基线、来源本会话的运行时变化、实际域有效增量、目标规则与执行单元实际加载规则；域证据带 engine_ref/shared_subjects/机制覆盖，禁止把逻辑四层节点计数当作四个独立内核域。

当前生效状态以服务端当前绑定和权威回执为准。系统/Agent 配置、managed 任务、通用指导可由各自适配器汇总；未接入的机制明确标明能力不足。普通业务合同及数据库不为此视图改变。聚合接口需要分页、部分失败及未知计数语义，按实例缓存配置和绑定证据，避免为每个会话重复编译或调用加载器；缓存不得制造新鲜保护结论。

## 验收条件

1. 进入任意已接入会话，首屏可读出当前约束、对象、操作、处置、归属、执行方式和核验状态；历史记录不冒充当前保护。
2. 系统继承规则可查看，不能作为会话本地规则删除；上层修改明确显示全部受影响对象。
3. 同一表面能表达内核规则、权威工具/审批控制及行为指导，指导不被标成强制生效。
4. 表单及 DSL 支持的语法子集往返后语义等价，不丢否定、例外、条件和既有规则。
5. 编辑、切换会话和安全检查无授权副作用；草案按精确目标隔离，切换时没有旧数据串入。
6. 批准时运行保持不变，显式应用后才核验新配置；拒绝、撤回、停用、版本漂移及并发处理有可追溯结果。
7. 共享域增量以 S1/S2 同域一致生效、审批明确全部影响验收；未声明可信子域时不承诺会话差异权限。选择 S1 不得改写实际域范围。
8. 选一个真实安全任务，走通 UI 配置、审批、应用、危险动作拒绝、反馈、合法任务完成和审计；独立命令域实验不能代替本项。

## 第一阶段实际接口与数据合同

实现工作树为 `/home/happy/projects/agentscope-session-security-20261014`，基于已发布的 c7ddc59，并保留验收期间新发布的 `/opt/agentscope-approval-recovery-20261014-143959` 审批重新校验功能。部署脚本按该运行版本的逐文件摘要核对基线，遇到再次漂移拒绝覆盖。

既有 `GET /api/agent-instances/{instance}/sessions/{session}/policies` 增加 `security: SessionSecurity/1`，保留原 records、加载回执、工具 Trace 和内核归因合同。security 汇总平台底线、资源默认边界、实际合成网络范围、适用系统规则、Agent 本地结构化规则、加载 DSL 和受管任务记录。行为指导明确非强制；工具规则只声明准入配置，不把它当作已发生的内核拦截。配置存在而缺少 DSL 加载映射时返回不完整记录；空列表不能证明没有保护。

新增管理员 `POST /api/agent-instances/{instance}/sessions/{session}/security/proposals`，接受 scope、operation、basis_hash、constraint_id、rule 或 network、request_key、acknowledge_scope。仅 system/agent 能转为原权威控制器的候选；workspace/session 明确拒绝，不回退扩大。scope=system 修改共享系统配置；scope=agent 修改此实例全部会话的基线。平台与默认边界不可直接停用；网络仅配置现有 model_only/disabled 模式。复杂 DSL 在所属配置编辑；会话面板停用 DSL 时明确移除整个文档，并保留其他文档。

basis_hash 固定精确实例/会话、运行代次、资源、结构化配置及系统/实例 DSL 内容与版本；提交时重新核验，配置变化返回冲突。身份及约束归属从服务端读取，不接受客户端自报执行能力。提交只保存候选，批准和应用复用统一审批中心，后者仍由现有 Broker/控制器负责。

新增 AI 控制面元数据表 session_security_requests，按 (instance_id,request_key) 保存 session_id、请求摘要、原审批引用和幂等返回值，支持刷新后恢复从本会话提交的待处理候选。该表不保存新的权限状态，不授予批准或加载能力。旧库增量建表，旧审批和策略不改写。

coverage_complete 仅描述已接入配置源是否取得完整记录，不代表所有外部机制或所有操作均已验证。原生会话局部执行、工作区局部执行和未接入外部业务约束保留能力不足提示。读检查不运行破坏性探针；验收探针只在独立测试实例执行。

控制台原有 records 对启动生成规则的过滤保持兼容，新增 security.evidence_records 提供这些规则的详情，并按精确 session_id 过滤命中。文件或运行资源不存在时，新候选入口返回明确 409 路径冲突，不误报 Agent 控制连接不可达；失败不建立候选或请求关联。第一阶段实施和剩余验收边界见 [交付评审](../REVIEW/REVIEW-20261014-AgentScope-session-security-delivery.md)。

## 策略域计数与能力语义补充

策略域与安全配置使用相同 SessionSecurity/1.controls 汇总系统、Agent、工作区和会话四层归属，系统内置保护计入系统层，计数表示已接入约束，不等同于独立内核域数量。空系统层显示“无额外约束，继续继承上层约束”；原生 workspace/session 显示独立应用暂不支持，不解释为用户停用。配置源不完整时 count=null、known_count 为已取得记录数，不把未知计为零。公开控制台保留技术身份隐藏边界，原始接口仍可返回绑定证据；两者使用同一投影函数，不通过记录过滤重新计算数量。

## 系统内置保护归并

平台底线不是第五个策略作用域。受控环境对控制目录、凭据和不可变启动规则的保护属于系统层。当前安全投影以 scope=system 返回，固定保护记录使用 kind=system_builtin；不可变启动证据仍保留原始来源与编译身份，仅在安全视图附加 system_builtin=true。归属筛选、计数和继承关系统一为 system→agent→workspace→session 四层，系统内置保护继续只读。

该归并不建立新系统策略文档，不改变 Broker 的隔离挂载、非特权启动、固定规则、审批或存储。不存在独立 platform 策略库、审批控制器或可配置第五层；历史 source_ref=platform.no-publish 为执行证据标识，保持兼容，不用于声明额外策略域。
