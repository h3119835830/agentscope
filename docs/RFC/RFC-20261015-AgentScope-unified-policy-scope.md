# AgentScope 统一策略入口与作用范围

日期：2026-10-15。范围：前端信息组织；不改变执行器、内核规则、授权或数据库合同。

## 问题与目标

原 Agent 页把“Agent 长期基线”和“工作区策略”作为两套入口。用户需要一个配置入口，以字段区分“全部受控 Agent / 指定 Agent”，工作区用于理解场景。安全目标身份、参考资料和规则匹配对象应分别表达。

## 页面与合同

Agent 页的作用范围字段选择 `system` 或 `agent`。选择指定 Agent 时再按精确实例 ID 选择目标，提供策略助手、已配置策略、参考工作区。选择全部受控 Agent 时在同一模块复用 SystemPolicyLibrary；原系统管理入口继续使用同一组件和 API，不复制配置数据。

| 产品字段 | 实际含义 | 现有接口 |
|---|---|---|
| 全部受控 Agent | 系统约束，所有受控实例继承 | /api/security/system/policy-library 与现有审批接口 |
| 指定 Agent | 精确实例的全部工作区、会话继承 | /api/agent-instances/{id}/template-configurations/generate 与模板子配置接口 |
| 保护对象 | 规则匹配的文件、目录、程序或网络对象 | 已发布模板的参数校验与物化 |
| 参考工作区 | 所属 Agent 的已登记资料目录 | 现有 workspaces / files 只读接口 |

改变字段只改变页面读取和配置目标，不创建审批、不下发、不启动或停止 Agent。新模板助手固定提交 `scope=agent, workspace_id=null`；切换实例卸载旧助手，保留精确实例隔离。全部范围复用现有人工系统配置；本次不新增模型自动生成全局策略能力。

## 工作区与历史兼容

不再提供新工作区策略入口。限制某个项目文件可以在指定 Agent 策略的保护对象参数中填写该文件或目录；这表示实例规则匹配对象，不宣称具备独立工作区执行域。

旧 URL 的 `policyScope=workspace` 保留只读历史视图，按原 target/workspace 读取；不挂载生成、编辑、停用或提交控制。新建指定 Agent 配置是明确的新操作，清除旧工作区上下文；不迁移历史文档、审批或加载记录。后端工作区合同仍保留兼容，不靠前端变更扩大其应用资格。

参考工作区目前只列目录和文件元信息。浏览不会自动发送正文给模板助手；用户可在补充参考材料中提供文本。今后若接入正文读取，应复用受限读取、敏感资料过滤、证据冻结与新鲜度校验，并独立保留资料来源；不得把参考目录当作应用范围或授权来源。

## 审批与执行

配置表展示作用范围；审批和应用继续分别由人工确认。参数生成、保存、提交、批准、加载和内核拦截仍是不同事实。本次不更改系统/实例执行层级、来源绑定、工作区 ExecutionBinding 要求、策略组合或停用行为。

## 发布

只发布构建后的前端静态资产，保留旧资产并原子切换 index.html。不重启任何服务。发布前后核对 API、Broker 进程身份，受控 Agent 的 PID/generation/domain/策略和系统策略版本，以及 18000/18004；若变化则恢复旧入口并保留证据，不恢复权限或自动启动 Agent。
