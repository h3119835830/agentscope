# RFC：执行快照的真实短路径与启动恢复

日期：2026-10-08。状态：实施中、待真实 Pi/DSH 验收。本文件记录本轮实施合同，不表示新任务、DSH 或内核执行已经验收完成。

## 问题与职责

原执行快照使用 `/s/<16 位 task_id>/r`。仅压缩项目外层目录后，已登记的 `transaction-service/verification/rate_limiter.py` 目标仍长 73 UTF-8 字节。真实 Pi 候选因此无法完整表达其提出的保护，最终提交 needs_clarification；其他规则编译通过不代表任务可以加载。

ActPlane 当前模式缓冲区大小为 64 字节，末尾保留 NUL，实际最多表示 63 字节。AgentScope 的共享上限由 64 修正为 63，64 字节及以上的目标在生成合同内明确拒绝。本轮不修改执行引擎 ABI，不接受截断、父目录扩大保护或不可核验的路径替代。

AgentScope 负责分配并冻结执行快照与来源映射；Pi 负责提出新候选；人工确认与可信控制面加载分别记录；DSH 在核验后的实际执行目录完成任务。路径变短不产生新权限，也不证明候选的语义、适用条件或任务结果正确。

## 布局与持久分配

| 对象 | 合同 |
|---|---|
| 逻辑任务 | 保留完整 16 位 task_id；API、凭据、策略、BPF pin、cgroup 与审计仍以该身份关联 |
| 常规快照 | 能满足路径预算时兼容既有目录与项目根映射，不批量移动旧任务 |
| 超长快照 | 分配 `/s/<两字符 base62>/r`，需要缩短的项目外层根使用单字母别名，例如 `/s/Ab/r/p` |
| 项目内部 | package、tests、文件名及原始文件字节不因布局处理而改变；原来源目录保留 |
| 临时与输出 | 与 r 同属该实际任务根，分别为 tmp、output；既有输出授权规则继续适用 |

短根是实际创建的 canonical 目录，不是符号链接或 bind 别名。现有沙箱对同一物理绝对路径的隔离挂载继续适用，不利用挂载路径差异规避规则长度。当前 20 个来源资产在紧凑布局下的最长目标为 63 字节；其他项目若仍超限，明确报告，不能默默改变内部布局。

`snapshot_roots` 保存完整任务身份、真实根、根键、工作区、布局模式、状态及设备号/inode。两字符 base62 命名空间有 3844 个槽，大小写区分，耗尽明确失败。短别名公开可见，不承担认证或授权职责。

分配使用独立 SQLite 事务：先永久提交 reservation，再排他创建文件系统目录，最后在另一事务发布任务与上下文。主任务复制、校验或入库失败不释放占位；失败保留 tombstone。既有文件系统对象及历史任务引用的根均视为占用，不能接管、覆盖或在丢失后重用。目录创建使用排他、no-follow 与身份核验，不以 exist_ok 覆盖已有对象。

设备号/inode 和存储关联进入新上下文 hash。确认及实际加载前核验 task、workspace、output、reservation 和真实根身份；目录丢失、替换、符号链接或跨任务配对不一致时拒绝。结束任务仍撤销执行域、凭据与临时授权，保留任务目录及永久占位；不增加自动删除或回收槽位流程。

## 冻结映射与失败恢复

原始任务文本、来源字节与来源 manifest 不变。新 TaskContext 冻结来源目录、项目原相对路径、真实 mapped_path，以及资产证明的 `/workspace/<project>` 逻辑路径映射。以最长前缀匹配消除项目根与总工作区的歧义；Pi 和 DSH 使用同一份映射。无法唯一绑定的逻辑路径不赋权、不猜测。DSL 目标只使用登记的真实 canonical 路径。

旧失败任务的 context、proposal、工具结果和原失败证据保持不变。既有启动恢复流程创建新的关联任务及快照，保留 startup_recovery_origin；不能把新 DSL 填回旧候选。重复同一恢复请求复用已关联 child，不能反复创建任务或消耗槽位。

除已失败、中断、取消的启动作业外，completed 作业若绑定服务端真实提交的 needs_clarification 候选，也可作为尚未授权的启动失败证据进入恢复。仍须核对 task/job/context、正文 hash 与校验摘要、真实未解决缺口，并满足零加载版本、无执行绑定、无有效执行凭据等既有条件。completed 只描述生成作业结束，不等于候选可执行。

来源实例、代次、原生 workspace、manifest、任务目标、已接受约束及平台底线必须保持关联。原生 DSH 来源在没有打开会话时允许 SID 为空；这不是受管会话身份。受管 DSH 仍须使用其实际绑定 SID，不能借原生空 SID 跳过核验或继承执行授权。

恢复只启动新的 Pi 生成。新候选经过校验后仍等待人工确认；确认、加载、进程/domain/cgroup 核验和实际文件权限结果分别留证。oracle、评测器、预期答案及私有推理不进入 Pi/DSH 输入；本轮来源仍为已登记的 20 个项目资产。

## 验收与当前边界

需覆盖常规布局兼容、两字符根并发与冲突、3844 槽耗尽、事务失败后的永久占位、丢失/替换根拒绝、来源原件 hash 与内部相对名不变、同一恢复请求复用、跨任务/跨实例/过期关联拒绝，以及确认前无加载。

真实验收另需新的 Pi 候选、人工确认回执、实际 DSH 会话及 PID/domain/cgroup、对应进程域内的合法/违规文件操作、63 字节边界与近邻目标的独立探针、源及保护资产完整性、结束后的撤权证据。构建或单元测试通过不能替代这些证据。

当前尚无本轮新 DSH/kernel 完成证据。实现与回归进行中；既有启动恢复文档中的历史验收结果不延伸为本轮短根验收结论。

## 生成失败重试与证据接线合同

validate_policy_draft 在语义预算前进行只读目标证据预检，diagnostic_details.code=target_evidence_incomplete，issues 按 atom_index/target 聚合当前任务实际登记的 candidate_sources（source_id/read_receipt_verified）与 required_action（read_then_cite 或 update_atom_evidence_ids）。服务端不自动添加引用或修改草稿。完成接线后仍经现有上下文、authority、hash、canonical 路径、对象范围、历史来源与编译校验；3 次语义预算和 40 次总工具预算保留。

既有 POST /api/managed/tasks/{task_id}/start 支持尚未授权、绑定或加载的终止生成失败，在原任务/冻结上下文下重生作业。必须核验旧 job 的 kind、task 关联及 failed/interrupted/cancelled 状态，无同任务活跃作业；核验 unbound、源文件、运行配置与执行根身份后才能 enqueue。新作业 retry_of 及事件 previous_job_id 指向旧作业，旧错误与回执保留。重试不创建新任务或快照，也不确认或加载权限。

以上为本轮整改合同，专项与真实重试结果在 REVIEW/BUG 单独记录，不能从合同文字推断已完成验收。

## 待确认候选的事实性退回

新增 POST /api/managed/tasks/{task_id}/startup/regenerate 接收 expected_context_hash、expected_proposal_hash、reason(3—2000 字符)，只作用于当前待确认、零版本、无授权或绑定的已完成生成候选。需核验 exact job/task/proposal 关联、正文与校验摘要 hash、冻结来源和 runtime/存储/文件，以及无活动生成作业。旧候选保留，不直接编辑或自动批准。

内部 enqueue_bootstrap 将 review_feedback 与 retry_of 在创建作业的同一 INSERT 中保存，再唤醒 worker；普通 bootstrap HTTP 不接受任意反馈。新 job 的 get_task_context 只读投影 policy_review_feedback，核验当前 job/task/context 及旧 proposal 正文摘要。反馈 authority=control_plane_factual_review、role=factual_generation_review、scope_authorization=false，不成为 task/platform 来源，不改变固定 TaskContext hash、权限要求或原任务文本。

成功 enqueue 后发布新 startup_job 与 return_for_revision 评审事件；失败保持原待确认状态。新候选仍经完整校验与人工确认，生成中或评审退回不能加载权限。接口及真实回传验收待 REVIEW/BUG 记载。

## 路径匹配能力与覆盖回执

能力接口须明确裸绝对路径是 exact（目录节点也不递归）；尾 /** 是该目录后代 prefix，不包括目录节点本身；需要两者时由 Pi 显式提出，控制服务不自动补规则。所有实际 pattern 仍受共享63 UTF-8字节上限约束。

validate 的 registered_asset_coverage 只读投影当前 draft atoms 对同任务、hash有效登记资产的字面匹配，区分 exact/descendants，列出 source_id/path/命中数；目录节点没有登记文件命中时如实0。它不是 runtime enforcement proof，不进入 proposal/TaskContext，不改变 hash、authority、编译、规则或当前 Scope，也不由 statement 推断或补写策略。语义必要对象完整性仍须独立评审与人工准入，真实 kernel 探针另行验证。
