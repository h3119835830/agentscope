# RFC：历史策略语句与 DSL 对应展示

状态：已实施，后端与桌面验收通过；最终回放界面验收另见 20261008-task-replay REVIEW。

任务档案的运行前、运行时策略以实际策略语句为主内容，生成作业、审核和权限变化作为关联信息。一个作业的多条语句分别可查，使用原有逐句 ID；失败或没有登记语句的作业保留占位记录，不补造模型输出。

档案策略列表增加独立的语句视图，原作业视图保留。任务、阶段和视图均约束分页游标。逐句详情只在“对应 DSL”展示该句有证据关联的编译子句；完整候选包包含平台和继承规则，独立折叠并明确其候选、历史语义。旧记录缺少可靠映射时显示未记录，不能退回整包冒充逐句 DSL。

语义指导和内容规则不产生 OS DSL。扩权可能通过解除拒绝或调整执行范围实现，展示权威快照中的前后权限及有来源的 DSL 差异；不存在新拒绝子句，不等于扩权没有发生。没有保存前版本编译材料时，不重新构造历史规则。

所有接口继续只读聚合现有任务材料，不调用 Pi、Broker、DSH，不改变审批、加载、有效 Scope、凭据或进程。历史候选、历史加载回执与当前生效状态保持区分。

接口合同：`GET /api/tasks/{task_id}/archive/policies?stage=startup|runtime&view=jobs|statements`，默认 jobs 保留。分页游标绑定任务、阶段和视图。逐句详情保留原子项 ID；缺失或 hash 不一致的子项返回不可用，不回退父作业。`compilation.scope=statement`，完整候选包位于 `bundle_compilation.scope=candidate_bundle`。

逐句映射为已登记目标与编译子句的关联，不声称模型逐操作精确归因。output 差异须核对公开授权来源、固定任务输出能力、前态版本/hash 与前后布尔权限。前态 DSL 仅来自同任务、同版本且策略 hash 一致的已保存编译材料；无法核验就显示未记录。
