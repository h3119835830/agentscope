# AgentScope 原文权限到执行规则的合同

2026-10-11，适用于登记 Agent 的策略助手生成链路。

## 问题与职责

历史需求“只读取 sales.csv 以获取报告数据，不写入、追加或覆盖该文件。”原文与对象绑定均正确，但模型生成的 PolicyIR 同时包含 block write、block open、block unlink。编译只能证明规则可执行，无法证明满足原文。

核对 actplane-ifc-compiler/src/dsl/lower.rs：open/read 均为 OP_OPEN（读访问组），write/unlink 均为 OP_WRITE（修改访问组）。BPF file_open 按 O_ACCMODE、O_CREAT、O_TRUNC 分派读/修改检查，file_permission 覆盖描述符读写，file_truncate 覆盖截断。禁止修改无需额外禁止读访问组。此前把 open 仅描述为 file_open hook 的能力合同不够精确。

## 新链路

原始不可变文档 → 单候选完整性复核 → 服务端对象适配 → 源动作提取 → 独立源动作复核 → 确定性访问组映射 → PolicyIR/DSL → 源权限一致性校验 → 静态编译 → 待人工审批。

源动作阶段读取原文引用、支持引用和已复核的中英文表述/分类，仅附工作区和已核验对象映射；不传复核猜测、后端能力局限、旧 IR 或编译诊断。SourceDescription 明确 action、forbid/permit、对象、来源条件、例外、证据与 unresolved。完整性复核单条接口保留复合需求为一个候选；文档批量抽取仍可拆分原子语句。场景推荐同样仅接收工作区与项目证据，不再把内部 ABI/事件能力传给推荐模型，避免把执行层术语混入用户建议。

代码将 read/open 映射到 file_read；modify/write/append/overwrite/create/delete/rename 映射到 file_mutate；access 展开两组；execute/connect 保留对应访问组。相对对象仅通过已经核验的 target_requests→verified_targets 绑定，不按文件名猜路径。同一访问组、对象、效果、条件、例外和参数的重复限制合并，原始动作证据仍完整保留。

代码把 file_read 限制转换为 read，把 file_mutate 限制转换为 write，使用现有 renderer 生成 DSL。登记 Agent 路径不再调用模型拼装 hook 组合；旧任务/历史仓库转换暂保留原实现。本合同没有“只读”或某个文件名的匹配分支、提示词示例或隐式授权。

## 校验与审批接口

冻结原文摘要、环境摘要、源动作、规范访问合同和两次结构化调用元数据。验证原始动作到规范访问组映射、全部限制与 IR 的对应，以及 permit 操作与限制是否冲突。条件、处置、例外、参数和路径均参与比较；不确定的权限交集保守阻止。只读意图产生修改限制，读取不被本候选阻止；permit 不能扩大或覆盖继承权限。

候选详情、统一加载资格与历史人工审核再次校验合同和 DSL 渲染一致性。缺少新版合同的历史候选必须重新生成。生成结果提供 submission_blockers，表示提交前校验，不包含“尚未人工审核”这一待审批事实；load_blockers 仍保留人工批准要求。页面据此显示待重新生成并移除提交入口。

本轮不自动修改已加载策略，不审批或应用产品候选。确定性转换失败时不通过重复模型生成或重复编译修补；需要修订原文/环境后产生新批次。

## 能力边界

当前 ABI 不能区分写入与删除访问组；如果原文同时禁止写入但要求保留删除，合同冲突，拒绝生成。复杂私有来源标签和无法表示的条件需要独立绑定或澄清，不回退到未校验模型 IR。条件不同的权限保留/限制交集采用保守校验，可能要求人工改写。

源动作提取仍依赖模型，结构校验不等于自然语言语义的形式化证明，人工审批继续存在。本轮独立执行进程验收不是 DSH/RQ5 任务闭环，也不覆盖 mmap、旧描述符、硬链接等完整攻击矩阵。
