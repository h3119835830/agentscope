# RFC DSL 规则归一化与重叠校验

日期：2026-10-07。状态：实施中，完整验收未通过。

AgentScope 在候选编译与加载之间增加确定性的规则分析。策略语句独立留档，完全等价的简单文件阻断规则共享执行条款，范围包含和部分重叠先报告关系。Pi 提出候选，控制面分析，Broker 校验并加载；DSH 继续只执行任务并接收操作反馈。

## 论文依据与工程范围

ActPlane 在事件到达时评估规则并应用匹配效果，子域继承父域约束，运行时增量不能削弱继承策略。论文描述编译和权限校验，没有规定等价去重或路径包含消冗余算法。[论文第 3.3 节](https://arxiv.org/html/2606.25189v2#S3.SS3)、[第 3.4 节](https://arxiv.org/html/2606.25189v2#S3.SS4)、[第 4 节](https://arxiv.org/html/2606.25189v2#S4)

以下归一化、来源映射和界面关系标签属于本项目设计。首版不修改 ActPlane 的规则求值语义，不采用最新规则覆盖、允许优先或按效果强弱删除规则。

## 当前代码与接入位置

实现目录：WSL `/opt/agentscope-history-v1`。`managed/controller.py` 的 `validate_candidate` 先校验证据、授权目标、启动底线及版本，再对保护列表做集合归一化并调用共享构建服务。运行前由 `bootstrap/validation.py` 接入相同服务。`managed/records.py` 按已编译条款投影单句片段及跨包加载引用，展示整理本身不承担执行去重。

已新增 `backend/agentscope_app/services/policy_normalization.py`，由运行前和运行时的策略包构建共同调用。关系分析使用编译器解析及降级后的字段，不能用 DSL 字符串相似度决定安全等价。

流程为：读取与证据校验 → 原始候选解析及能力检查 → 规则分析 → 生成规范策略包 → 再编译和完整性校验 → Broker 加载 → 进程域与操作核验。

必须先检查原始候选，防止去重掩盖未知语法、不支持的条款、非法路径或重复规则名。原始候选及其诊断保留，规范包单独保存。后续接入通用 DSL 时复用同一分析服务，不能只在受管文件保护列表上去重便声称通用完成。

## 三类数据

| 数据 | 身份和用途 | 保存规则 |
|---|---|---|
| 策略语句记录 | 原句、类型、上下文、来源哈希、读取回执 | 每条语句保留，不因重复删除 |
| 逻辑规则 | 具体操作、对象、条件、权限来源及生命周期 | 多条语句可引用同一条规则 |
| 编译条款 | 本次包内 clause ID、DSL、编译和加载回执 | 与包哈希、版本及域关联，不能跨包只凭数字 ID 引用 |

一条规则可以被多条语句引用；一条语句也可以需要 write 和 unlink 等多条规则。原句与目标绑定仍要通过证据校验，识别注释不会自动产生权限。

## 归一化身份

逻辑规则键采用带版本的规范 JSON 的 SHA256。实际字段为分析 schema 版本、引擎二进制哈希、task、已登记工作区绝对路径、权限分区、固定 task-lifetime 生命周期、操作、目标类型/目标/参数、效果和完整编译语义元数据。权限分区为 startup、runtime 及各 platform 规则名；只复用此受管任务生命周期内的无门控简单规则。项目映射与证据变化另由上下文 revision、读取回执和内容哈希检查；不同条件、标签绑定、例外、门控及转换仍保留在身份或判定为不可复用。

规则名、原因文本和证据列表不作为执行语义的替代品，另存到来源映射。不同原因不能被丢弃；反馈需要能列出所有对应策略语句。跨任务、跨权限层、不同撤销权或生命周期的规则不共享可变规则身份。

首版仅消除同一权限分区内、同生命周期、无时间门、无 lineage 门、无转换副作用、标签绑定一致、目标精确一致的简单 file block 条款。write 与 unlink 始终是不同操作。其他规则即使看起来相同，也先保留并标记待分析。

路径通过已登记的 Linux 映射处理，区分大小写、精确文件和目录模式；拒绝越出映射的 `..`。不把 `realpath`、符号链接或 inode 相同当作规则等价依据，不擅自把不同 glob 语法化成同一模式。链接别名与重命名替换继续由沙箱及内核探针验收。

## 关系判定与动作

| 关系 | 例子 | 首版动作 |
|---|---|---|
| 完全等价 | 两条无门控的 block write 指向同一精确文件，其余身份一致 | 共享一条执行条款，保留两条来源 |
| 已有规则满足 | 本轮再次要求保留同一文件 | 引用当前规则，记评估完成，不重复加载 |
| 启动底线已满足 | 运行时重述启动前已保护对象 | 只建立底线引用，不把底线迁移成运行时规则 |
| 范围包含 | `config/**` 与 `config/app.json`，其他条件相同 | 标记覆盖关系，保留两条执行规则 |
| 部分重叠 | 两个模式有交集，但双方范围不同 | 标记重叠，保留；不给无法证明的包含结论 |
| 条件或效果不同 | 同文件，不同门控或 block 与 notify | 分别保留，不按路径合并 |
| 意图冲突 | 任务要求修改启动底线禁止修改的文件 | 保留底线，记录冲突及暂停原因，等待可执行替代方案 |
| 无法判定 | 复杂 glob、时间状态或未支持的表达式 | 保留，标记未判定；必需约束无法执行时暂停 |

范围包含分析首版只对编译器实际支持且语义已验证的精确路径和目录子树做判断，并给出判定依据。更复杂模式返回 unknown。即便目标范围包含，条件、权限来源或生命周期不同也不能据此删除规则。

扩权是权限变更，不是去重。普通指导语句不能变成扩权授权；启动安全底线不能通过重命名、合并、调整例外或满足继承门控来绕过。

## 启动与运行时合同

运行前在必读来源、证据和原始候选通过校验后构建规范包；必须完成编译、加载与进程域核验，才能放行 DSH。启动底线清单独立封存，规范化不改变其身份、撤销权或保护范围。

运行时沿用现有真实消息、公开上下文变化、内核拒绝和已验证反馈 hook。冻结任务、会话、上下文 revision、当前策略版本、底线哈希和引擎能力后评估。仅改变来源关联或数组顺序、重复项时，规范执行集合不变：新增评估和来源关系，校验当前绑定后恢复，不生成新加载版本、不重启 DSH。

新增限制沿用现有暂停、静止工具子进程、装载和核验流程。需要扩权时仍需明确确认、重建完整包与新域，并恢复原生会话。语义判断和身份归一化不能跳过既有授权、必读材料及过期候选校验。

有效权限摘要、规范 DSL 哈希和来源清单哈希分别保存。摘要相同只能说明规则集合未变，不能单独证明包已加载、域仍存活或证据仍有效。加载回执绑定任务、基线、版本、权限差异、规范包哈希与来源清单，不能拿旧回执应用变化后的包。候选过期需要重新评估，但已明确授予且条件仍成立的授权继续有效；仅增加重复来源不要求用户再次确认。超出原授权范围或授权被撤回时，扩权继续等待明确确认。

应用前通过任务锁和版本比较再次核对冻结字段。Broker 校验服务端生成的规范包、底线清单、完整编译结果及哈希，拒绝客户端自行声称的去重结论。加载失败继续暂停，不以旧回执标记新包生效。

## 持久化与接口

已新增不可变 `policy_normalization_runs` 和 `policy_statement_rule_links`。前者保存输入与输出包哈希、分析器版本、基础版本、能力哈希、结果及诊断；后者关联逐句记录、逻辑规则、包内 clause ID 和关系依据。原始 proposal、DSL 和加载事件不覆盖。数据库初始化只添加表和索引，不改写旧候选、包或回执；重复初始化和旧任务 legacy 选择已经测试。

现有管理员只读记录接口已增加 `normalization` 字段。旧记录返回 `legacy_unanalysed`，不能追补“已去重”。新状态不会扩展 Pi 或 DSH 的权限，也不向 DSH 暴露策略包。

## 界面与审计

保留现有左侧导航和运行前、运行时、执行审计分页。列表仍一条语句一条记录，仅补充“新增规则”“复用规则”“底线已覆盖”“范围重叠”“待澄清”标签。复用规则时不能同时标为“本轮新增并加载”。

详情沿用语句、上下文、DSL、加载四个分页。DSL 页只显示本句对应条款、关系依据和可跳转的相关记录；多条规则用标签切换。不得回退展示整包 DSL。加载页分别展示首次实际加载、本轮评估和当前绑定。

审计按包哈希、版本和域解析内核 rule ID，再关联全部来源语句。一次内核事件只保存一次，多个来源通过关联列表展示；同一工具引起的多个真实 OS 事件不能被去重成一个事件。反馈给 DSH 的仅是当前操作对象、原因和合规替代方式，管理员可以查看完整来源。

## 实施与验收顺序

| 阶段 | 交付与通过条件 |
|---|---|
| 一 只分析 | 持久化关系报告、原始及规范身份；不改变执行包。关系判定与人工冻结预期一致 |
| 二 简单等价复用 | 同权限分区的简单 file block 去重；数组顺序和重复项不产生虚假限制或新加载；重复规则名仍拒绝 |
| 三 来源与界面 | 来源不丢失，逐句 DSL 正确，历史未分析标识、跨页和跨包规则 ID 均正确；DSH 看不到控制资料 |
| 四 实际执行回归 | 旧包和规范包对冻结操作矩阵产生相同允许、拒绝、反馈关系及保护对象状态；完成并发、重启和过期确认验收 |

必要用例包括：完全重复、不同操作、权限层和生命周期不同、目录覆盖文件、相邻合法文件、不同条件及例外、时间门失效、不同效果、启动底线重述、移除重复来源后的规则保留、跨包数字 ID 复用、引擎升级、来源哈希变化、并发候选、超限与加载失败。

内核回归用独立测试工作区覆盖直接写、删除、重命名替换、链接别名、已打开 FD 与 mmap；验证受保护完整性、审计和反馈送达。真实 DSH 多轮与同域探针分别统计正确拦截、误拦截、漏拦截和正确放行，Agent 未尝试单独列出。不得把分析报告、编译通过或“已加载”当作内核等价验收结果。

首版通过前不启用范围包含消冗余。后续只有证明条件、状态、撤销、审计与反馈行为均保留，才另行设计更广泛的优化。

## 当前运行合同与验收状态

启动上下文明确分为 Pi 的安全编译材料与 DSH 的任务执行材料。DSH 入场消息仅含原任务、公开项目文件和路径映射、任务约束及公开运行环境；不包含编译能力说明、候选、确认策略或控制面记录 ID。探针代码由固定 root relay 经 stdin 送入低权限同域进程，DSH 不获准读取后台探针源码。

### 受管 relay 的启动次序

Broker 启动仅含内联 bootstrap 的 root relay；bootstrap 不读取 AgentScope 仓库代码。Broker 将该次精确 PID 登记到控制进程表后，以 root-only 一次性握手释放 relay；握手有 owner/mode/no-follow/nonce 校验与超时。relay 随后读取任务运行器，DSH 以低权限子进程启动，不能继承该 PID 例外。原生会话、实际域和固定 OS 探针全部核验后才放行任务。

## 包持久化表示

不可变报告保存原始 YAML 字符串、原始/规范 DSL、原始/规范哈希、引擎哈希和分析器版本。规范 YAML 可由报告的原始 YAML 与 normalized_dsl 使用固定序列化器无损重建，并核对 bundle_hash；实际已加载规范 YAML 另存 active_bundle 及 Broker 的只读 policy.yaml。最终批次逐包重建与哈希检查独立执行。报告及加载实例 ID 分开，加载实例增加 load_version 与父包引用后重新计算报告身份。

## 独立进程所有权与探针合同

新受管任务的root relay在Broker登记精确PID后、释放启动握手前进入任务专属cgroup。加载回执新增process_cgroup/cgroup_inode，管理员状态增加cgroup_verified。重复评估同时核验原有内核域及任务组绑定。收紧、扩权和结束时独立冻结并终止任务组，核验空组；继承策略域仍是规则求值的权威，不用cgroup替代DSL。

固定探针的ready pipe在cap_task实际绑定和cgroup身份核验后才释放，管理员回执增加probe_binding。缺失不能算允许或内核成功；不能给DSH增加任何控制面读取例外。线程按TGID共享策略身份，避免TID条目堆积和PID重用污染。
