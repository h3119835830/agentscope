# 第三步：工作区场景接入 Agent 策略助手

日期：2026-10-11。状态：源码实现及隔离环境验收通过；未发布到 18003，未执行内核应用。

## 职责与流程

入口为 Agent → 策略助手。用户选择已核验的真实受控 Agent 和原生会话，点击读取场景。服务端冻结受限项目文本，使用既有 DeepSeek JSON 提供方进行无工具场景分析，返回摘要、建议和逐字文件引用。采用建议只填入对话输入框；生成策略复用环境适配、PolicyIR、ActPlane 编译及候选挑选；提交候选进入统一审批。只有既有人工批准路径可以改变权限。本轮没有增加 Pi 执行工具或新的策略加载入口。

读取作业与旧任务场景识别职责不同：旧模块生成任务草稿，本模块为当前 Agent 会话生成可挑选的策略建议。共用 registry.scan_tree 的描述符相对读取、项目排除规则及 scene_read.public_text 的文本清理，保留旧任务采用合同；不创建工作区登记或任务。

## 接口合同

- POST `/api/agent-instances/{id}/policy-scenes`：仅接受 session_id、服务端 context_hash、request_key；同一实例的幂等键不能改绑会话。
- GET 同路径：session_id 必填，返回该实例及会话的最近读取记录。
- GET 同路径 `/{read_id}`：排队、运行、完成、失败或中断状态；摘要、建议、文件名、current 与 read_only。产品 GET 对应 `/api/console/agents/{id}/policy-scenes[/{read_id}]`，沿用管理员认证和保留记录可见性检查。
- history 输入的 agent_context 增加可选 scene_id；仍不接受客户端文件路径、内容、运行身份或资源映射。人工自由描述可不绑定场景。
- scene_binding 固定读取记录、来源摘要、结果摘要和文件清单摘要，进入现有环境绑定。生成前后、候选选择、DSL 保存校验及批准前复核。文件或连接变化时，审批投影失效并提示回到助手重新读取。

## 读取与信任边界

根目录只能来自 agent_context.snapshot 核验的原生会话执行目录及宿主映射。从 / 开始使用目录描述符和 O_NOFOLLOW 逐段打开，拒绝符号链接；不暴露任意文件读取 API。文本扩展名白名单包含任务说明、文档、常见配置和代码，200 文件、单文件 128 KiB、合计 512 KiB；目录遍历另有深度和条目上限。超限明确失败，不静默截断并宣称完整读取。

排除 .env、凭据/私钥命名、运行私有目录、构建依赖及既有 oracle/evaluator 保留材料。模型只接收冻结并清理的 UTF-8 文本及当前后端能力；项目内容始终是不可信证据，不能提供批准权。返回建议必须引用本次已读文本的逐字片段；这证明引用可定位，不证明模型语义必然正确。清理采用既有启发式规则，不能宣称识别任意嵌入式秘密，操作者仍需控制允许读取的项目内容。

读取前后检查环境及文件清单，不能宣称原目录是文件系统事务快照。当前共享执行器和跨会话应用边界保持原实现，第四步另行收敛。编译通过、人工批准、加载、活跃绑定和内核命中继续作为不同事实。

## 后续架构方向（2026-10-11）

本文件保留第三步已实现的 Agent+会话场景读取合同。用户后续确认策略生成主要集中在 Agent 基线和工作区策略，目标见 [总体 RFC](RFC-20261011-AgentScope-policy-control-architecture.md)。后续 Agent 基线不强制选择会话；工作区策略绑定真实实例与工作区身份，会话只提供可选补充上下文。本节不改写上文现有接口的 session_id 必填事实，也不宣称第三步已经具备 workspace 作用域或独立工作区执行域。
