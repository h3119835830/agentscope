# 子配置记录行操作与审批关联（2026-10-16）

系统策略模板子配置仍为六列，最后一列改为“操作”，直接提供详情、提交审批、查看审批、停用。提交与停用打开小型核对弹窗后复用 /api/policy-template-configurations/proposals；停用仅发送 operation=disable，不调用批准或应用端点。由用户在审批中心批准后，再显式应用。

记录能力由当前配置状态控制：草案可提审，已有待审批 / 已批准待应用 / 正在应用变更时禁止重复提交与停用；尚未应用或不支持的历史局部配置禁用停用；无关联审批则禁用查看审批并说明原因。批量勾选使用同一可提交条件。

GET 策略库及模板配置投影新增 approval_id、approval_revision、approval_current。关联通过既有配置绑定表中的准确 ID、版本和 instance_dsl_proposals.scope_id 完成，不匹配名称或当前选中 Agent。优先关联当前版本；仅有历史版本时允许打开其原审批，同时当前草案保持 draft/library，不套用旧批准状态。无数据库迁移或审批写入合同变化。

旧系统配置补充 applied_configuration 的实际已应用名称、配置参数。停用核对展示实际已应用版本和参数，同时请求仍冻结当前库版本和策略基线；后端按文档 ID 移除该配置，其他配置及未应用草案保留。加载、授权校验、审批收据、执行边界不变。
