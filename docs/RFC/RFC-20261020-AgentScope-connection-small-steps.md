## 打开入口（第二个独立步骤）

用户已确认继续单独修复：保留打开入口，先检查现有进程；需要重新启动时由用户确认，不自动重启。本步骤不能以 `gate=open` 推断进程仍在，也不能将未知状态改成已加载。

列表和配置抽屉的未知受控连接提供“打开”，先调用已有 `/open`。入口不可用后调用 `/check`，仅准确受控目标且无明确运行/启动中状态时提供重启确认。弹窗说明共享会话中断风险，默认焦点为取消。点击确认后重新核对实例、运行代次、策略及启动配置；发生变化或检查失败则不启动。同一实例恢复可打开时直接复用。明确未运行的“启动并打开”保留原流程。

不修改后端 `/start` 合同或增加服务端 CAS；前端检查不是原子授权，最终启动仍依赖现有后端串行生命周期与保护校验。确认期间极窄并发窗口的服务端条件请求不在本次范围内，不宣称已实现。
