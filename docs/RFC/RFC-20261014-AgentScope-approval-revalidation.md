# AgentScope 失效审批重新校验合同

日期：2026-10-14。范围：AgentScope 控制台和管理 API。应用始终由管理员显式确认；原 Broker、内核引擎、Agent 执行器、原总览及公告不修改。

## 状态与职责

配置库保存、候选校验、批准、应用和执行核验独立。旧审批冻结配置版本和执行基线；源配置版本改变时，即使正文相同，也不自动恢复旧批准。重新校验保留原记录，读取并展示当前采用的版本、内容差异、当前策略基线和实际目标，创建独立待审批候选。新候选仍需先批准、再核对范围并单独应用。当前生效文档和运行代次在重新校验、批准时均不改变。

## 管理 API

- GET /api/console/approvals/{id}/revalidation 只读预览，返回 plan_hash、版本/内容对照、准确范围和实例数量。执行身份和完整合并文档留在服务端。
- POST /api/console/approvals/{id}/revalidate 接受 plan_hash、request_key。生命周期锁内复核预览，配置、基线或目标漂移返回 409；不调用 approve、apply、start、stop 或加载接口。编译失败保留新失败候选，不制造通过。
- 同 source_id/request_key/plan_hash 返回同一新候选；同键不同内容拒绝。policy_approval_revalidations 保存源记录、预览指纹、请求内容和新候选关联，写审计。新候选不继承旧批准回执。
- 创建中断时，rv: 请求命名空间下未完成来源关联的候选不能被批准，直接旧 DSL confirm 也拒绝；不能再从这个未完成子候选跳过来源绑定。允许按原请求重试，或回到原记录重新读取。

## 合并与范围

系统配置库候选采用当前所选资产的精确版本，展示原版本和当前版本差异；使用既有 library.propose 合并，保留其余生效系统文档及继承关系。归档资产不自动恢复，原停用目标不存在时不盲目重复移除。

手工 Agent/System DSL 从旧基线提取新增、更新和移除的文档差量，合入当前基线。只有当前目标文档仍等于旧值或候选值才自动合并，其他文档保留；冲突或旧基线证据缺失时返回所属配置人工编辑。候选文档在预览和编译前使用同一 canonical_documents 顺序，避免 next_dsl_hash 因排序差异产生假漂移。校验中目标变化时，新子候选保持不可批准。

生成绑定的候选要求回策略助手重新读取材料并生成；不能删 generation_binding 或替换来源来让旧候选通过。局部工作区/会话执行能力仍由服务器判定，返回精确所属页面，不扩大到 Agent。失败加载的 blocked/paused 状态不由重新校验自动解除。

## 页面与发布

失效详情显示具体配置版本变化，增加“重新校验”。预览对照需用户勾选核对后才发送创建请求，按钮明确“校验并生成新候选”；新旧记录互相链接。已批准的候选再次勾选确认，点击“应用策略”才执行加载。共享预览缺少本地恢复回调时，跳到审批中心对应记录；不出现无响应按钮。

以 c7ddc59 当前运行合同为整合基线，API/UI overlay 保留 Broker 及现有执行状态。正式只创建用户要求的新待审批候选，不批准、不应用。隔离 18187 验证完整链路和真实内核行为。
