# RFC：系统策略配置库与统一根层载入

日期：2026-10-11。状态：用户已确认层级；交互预览已实现，运行服务集成待后续。基线：9a2a291。

## 需求与职责

用户选择系统策略、人工确认后，应统一载入所有受控 Agent 的根层。选择具体 Agent 的配置属于下一层 Agent 策略，继承系统约束并追加。系统库与当前运行策略是两类状态，保存、勾选、编译、确认、逐目标加载、运行核验分别记录。

前端负责配置表达、保留原始 DSL、预览差异与影响；可信服务端负责实际启动身份、命名空间隔离、编译能力、基准版本、审批与加载结果。原生 Agent 凭据不能访问人工配置/确认接口。

## 本次实现

独立预览位于 `docs/prototype/system-policy-studio/`。包含 12 类候选、文件后缀/名称/路径/目录、程序、IPv4 目标、跨事件来源配置；三种动作；路径试算；原始 DSL 草案；统一影响预览。仅浏览器本地保存，不调用任何生产写接口。

当前运行代码存在其他未提交工作，因此预览在独立 `codex/system-policy-ui-20261011` 工作树完成。未覆盖原工作树、未替换 18003 服务。

## 集成接口合同（设计，尚未实现）

1. 读取系统配置库：文档 ID、版本、原始 DSL、可编辑结构、来源、配置状态；另读已应用版本，避免混淆。
2. 校验候选：请求包含精确文档版本、系统基准版本、勾选条目；服务端读取所有受控 Agent 及其当前身份/能力，合成独立命名空间并真实编译。
3. 预览结果：保留/新增/更新/删除差异、每个 Agent 的影响、能力阻塞、编译映射、候选摘要哈希与时效。系统目标固定为全体，不能由前端传入子集来规避继承。
4. 人工确认：核对候选哈希和基准版本；确认后再次核对。任何能力不满足不能静默跳过所选规则。所有目标的结果逐项回执，不用单一成功徽章掩盖部分失败。
5. 应用与运行核验：沿用加载失败暂停机制；停止 Agent 保持停止，后续启动前继承当前系统规则。新增连接在受控启动前继承。不要承诺跨进程原子切换，必须明确加载过程与失败状态。
6. 下层 Agent 策略只能添加约束，不能重命名/覆盖系统标签与规则以解除继承。取消勾选不代表删除已应用规则；删除要有明确差异与独立确认。

## ActPlane 语义核对

依据 `actplane/docs/rule-language.md`、`crates/actplane-ifc-compiler/src/dsl/lower.rs`、`bpf/src/lib.rs` 与 `backend/dsl-adapter/src/main.rs`。

- `.env` 后缀表单生成 `**/*.env`，匹配 `/.env`、`/a/.env`、`/a/production.env`；不匹配 `.env.local`。同名文件表单生成 `**/.env`。
- 目录同时生成目录节点和后代匹配。未知实际目录不得用演示路径替代。
- block 在支持的拦截点拒绝操作；notify 记录并允许继续；kill 终止命中进程，不能默认称为事前阻断。
- 信息流配置保留标签 source 与条件，不压平成文件权限。AGENT source 必须基于真实受控身份合成。
- 当前固定运行 profile 尚未启用文件后缀能力。编译器能生成规则，不代表当前引擎可加载。能力展示最终应由服务端按运行版本返回。

参考：[ActPlane 规则语言](https://github.com/eunomia-bpf/ActPlane/blob/master/docs/rule-language.md)。本地 RQ1 corpus 是候选集，607 条编译研究导出与 721 条去重候选不能混称为已加载系统策略。
