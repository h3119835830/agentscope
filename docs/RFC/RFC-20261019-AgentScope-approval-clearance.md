# 审批记录清理与恢复

状态：已实现。清理只管理审批列表可见性，不改变原始审批、配置、执行或审计。

## 界面

审批页增加“清理当前结果”和“清理所选”。当前结果严格限定为当前状态页签及搜索条件匹配的记录，所选严格限定为当前可见结果中的勾选记录。沿用批量预览与一次确认，逐项显示结果。

“已清理记录”可按原状态和搜索条件查看记录，支持恢复所选或当前结果。恢复后回到对应状态列表，原审批状态保持不变。刷新后清理标记仍保留，不能通过清理停用已应用策略。

## 服务端合同

- `GET /api/console/approvals` 默认排除有效清理标记对应记录，`?cleared=true` 返回已清理记录，并提供 `cleared_count`。
- 列表与详情补充 `can_clear`、`cleared`、`can_restore`、`cleared_at`、`clearance_hash`。原审批详情和配置引用仍可读取。
- `POST /api/console/approvals/{id}/clear` 与 `/restore` 要求管理员身份，参数为 `expected_hash` 和 `request_key`，禁止额外参数。服务端核对当前内容、状态、范围及可见性版本，不接受客户端宣称的可清理状态。

复用 `console_retained_records`，以独立的 `approval` 种类记录可见性版本、内容指纹和最近请求指纹。保留恢复后的版本标记，旧请求不能在恢复后再次清理。标记写入和审计事件同一事务提交。没有新增数据库表，没有物理删除原记录。

## 约束

允许清理已应用、已拒绝、需重新校验、校验未通过、应用未完成和暂不能应用记录。待审批、待应用、正在应用均拒绝清理，需先处理原变更；清理不代替拒绝、撤回或停用。

只在当前内容指纹匹配且记录仍处于可清理状态时收起记录。旧记录若恢复为待审批等可操作状态，会重新显示，不能隐藏新的审批工作。批准、应用和生成快照的权威状态不受列表清理影响。
