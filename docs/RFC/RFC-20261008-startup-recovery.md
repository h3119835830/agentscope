# RFC：启动策略失败的恢复入口

状态：已实现并完成本轮验收，2026-10-08。范围为尚未加载策略、未建立执行会话的启动生成失败任务。

## 职责与证据合同

旧任务保留固定 TaskContext、失败 Pi 作业和审计。恢复使用新的执行快照与 Pi 候选，并持久保存来源任务和恢复任务的关联。不得将新任务候选或 DSL 填回旧任务，也不将原失败作业改为成功。

恢复须保持来源实例及代次、已注册工作区、文件 manifest、原始任务目标、全部已接受约束、声明约束、澄清证据、平台与执行底线一致。仅目录相同不足以关联。路径通过原始资产身份精确映射到新快照；澄清证据使用新任务命名空间，不再次消费场景采用回执。

## 接口

`GET /api/managed/tasks/{task_id}/startup/recovery` 仅读取控制数据库中的诊断、可恢复性、候选及关联状态，不调用模型、Broker、工具或连接检查。

`POST` 同一路径接受 `action=reuse|rebuild`、`expected_context_hash`、`expected_manifest_hash`；reuse 额外要求显式候选任务与候选 hash。服务端检查来源、阶段及 CAS，拒绝过期、跨任务和约束不匹配请求。startup_recoveries 以原任务为唯一键，串行归并并发及重复请求；初始化或入队失败后继续关联的同一恢复任务，避免重复创建。

rebuild 从服务端可信旧上下文创建短路径快照并启动生成；reuse 仅持久保存验证通过、仍待人工确认的候选关联。生成中、已准备、生成失败、待审核分别返回。已有关联不等于已加载策略。

## 校验与权限边界

服务端候选正文存于 proposal_json，校验与编译摘要存于 validation_json，摘要按生产提交合同不重复保存正文。恢复检查正文 digest、context/task/job 关联、摘要中的 proposal_hash、validated 状态及 compiler.ok。旧格式如含重复正文，额外检查其一致性。

恢复不会批准规则、生成任务执行凭据、加载策略、启动 DSH 或改变有效权限。人工确认和加载流程保持独立。来源变更、已有执行版本或身份代次变更时阻塞并说明原因。

## 工作台

保留原工作台运行前、运行时、执行监控、执行审计模式。运行前只渲染一份紧凑策略记录，保留确认、来源文件、Pi 工具结果与版本折叠内容。错误用简短诊断和详情折叠展示；选中语句的 DSL 抽屉只显示相应编译子句。

恢复状态串行每次读取结束后间隔 3 秒刷新；页面切换后忽略旧响应，读取失败撤销旧候选操作状态。恢复导航留在工作台运行前子页，清除无关 archive 任务选择。
