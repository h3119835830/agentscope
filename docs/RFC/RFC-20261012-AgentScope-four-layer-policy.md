## 1. 原方案结论与历史事实

原方案采用系统 → Agent → 工作区 → 会话四层配置；该固定层级现由系统/Agent 基线与真实域运行时增量取代，保留本文用于追溯推导。生成材料、应用范围、授权主体和内核绑定是四个不同维度，不能由文件类型、生成时机或导航位置互相推导。

2026-10-11 的真实 DSH 验收在同一个原生会话执行了 23 项 OS 检查，并核对 7 条内核阻断记录；提案实际提交至实例级 DSL 接口。因此“全部工作区与会话”符合当时应用合同，不能把验收称为会话级隔离。选中会话、使用 `/w/0/sales.csv`、使用真实 node 来源均不能改变 Agent 作用域。详见 [BUG](../BUG/BUG-20261012-AgentScope-policy-scope-and-evidence.md) 和 [审计](../research/20261012-four-layer-policy/source-audit.md)。

2026-10-12 当次审计基点为 AgentScope `fc4e9d5368fecc713830738a7ad5896dcfd00fd8`。四个关键后端文件与当时 18003 发布目录的只读摘要一致；这只是当时的版本核对。当次没有应用候选、启动任务、重启服务或进行新的内核验收。现有源码只组合 system 与 instance DSL；原生会话共用实例执行器；managed 独立任务链路不等同于任意原生会话隔离。

## 2. 原四层配置与责任（历史）

| 层 | 主要材料 | 权威目标 | 继承和生命周期 |
|---|---|---|---|
| 系统 | 管理员配置、共同安全要求 | 纳入受控执行的登记实例集合 | 当前与未来受控执行继承；观测连接不冒充受保护 |
| Agent | 独立 Agent 职责/安全规范、明确引用的 MD | 一个真实 instance_id | 此实例的工作区与会话继承，不按 DSH/Hermes 产品名批量扩散 |
| 工作区 | 仓库规范、项目文件、场景证据 | (instance_id, workspace_id) | 该工作区所属受控会话及未来所属会话继承；其他工作区不受影响 |
| 会话 | 当前任务、运行事件、权限请求 | (instance_id, workspace_id, session_id) | 当前原生会话的受控执行与后代；其他会话和未来新会话不继承 |

保护 Broker、策略、审计和控制通道的不可停用约束归系统层的 system_builtin 分类；其实现可位于可信启动/内核保护层，但不增加第五个客户配置作用域。运行时任务/子 Agent 以 parent_binding 继承会话约束，不能凭自报 parent_id 获得委托权。

独立 Agent 规范和仓库 AGENTS.md/CLAUDE.md 都可作为材料。Agent 规范默认进入 Agent 候选；仓库材料默认进入工作区候选。材料可以跨来源引用，但生成前必须固定目标。将工作区或会话发现推广到更高层时，新建候选、重新解析目标、展示全部影响并重新审批，不能原地修改 scope 或复用旧确认。

“运行时生成”只表示 origin，默认目标为当前可信会话/任务；不构成第五个全局配置层。模板、人工配置及生成建议都使用相同的目标和审批合同。

## 3. 合同与数据流

### 3.1 四类独立信息

| 对象 | 最小必要事实 | 权威来源 |
|---|---|---|
| scope/target | system、agent、workspace、session 之一，相关实例/工作区/会话身份 | 可信登记与归属解析器 |
| origin/context_ref | manual、template、agent_document、scene、runtime；冻结的材料摘要和引用 | 受限上下文采集、原生事件及生成记录 |
| authority | 策略所有者、确认主体、上层强制约束、批准内容和影响快照 | 控制面审批记录 |
| binding | host/boot、进程身份、generation、domain、cgroup、有效包及编译摘要 | Broker/内核回执，客户端不得替代 |

输入只接受身份选择和需求，不接受客户端提供的“已验证 PID”、任意 source、工作区正文或 manifest 作为可信事实。实际项目路径是资源映射的证据，不替代 workspace_id；相同路径、挂载别名 `/w/0`、basename 或 cwd 不能生成工作区身份。工作区与会话必须经原生注册或可信适配器验证归属；能力不足保持待补充。

Agent 基线生成不强制选择会话。工作区生成不强制运行会话；适配器暂只能通过会话获得工作区事实时，明确记录此采集限制。会话运行时生成必须有可信会话身份、当前执行绑定和上层基线。

### 3.2 统一生成和审批

```mermaid
flowchart LR
    U[用户选择目标与材料] --> T[可信身份和读取范围解析]
    T --> C[冻结材料与上层基线]
    C --> G[策略生成 Agent]
    G --> V[源动作语义与路径及能力校验]
    V --> P[固定目标的候选]
    P --> A[统一人工审批]
    A --> B[Broker 应用编排]
    B --> K[ActPlane 编译加载与绑定核验]
    K --> E[实际执行与处置证据]
    E --> G
```

生成 Agent 不持有 Broker、策略确认或审计改写能力。外部材料始终是证据；文档内“忽略系统限制”“批准此规则”等内容不获得控制权。保留当前源动作抽取、独立复核、确定性权限映射与 DSL 校验；不增加只读、文件名或案例专用提示词。材料、否定、例外、目标和环境变更应使候选失效，而不是用旧 IR 自动修补。

所有变更，包括收紧、扩权、移除本层规则和推广范围，均需人工确认。保存、编译、提交、批准、加载、当前绑定核验、内核命中、实际阻止与反馈送达分别记录。待审批/拒绝/失败不改变现有授权；审批绑定候选摘要、上层基线、目标集合与上下文摘要。应用前再次核对，重复请求幂等返回原结果。

上层已应用的强制安全规则在后代中作为 locked 约束保留；局部 preserve/permit 只表示不增加本候选限制，不能放宽继承规则。策略所有者可以经新的审批版本修改自己层的规则，再重新应用受影响后代。可选模板/目录默认值是未选资产，不能与 ActPlane YAML 的可禁用 default binding 混为一谈。

## 4. 执行映射、共享边界与生命周期（2026-10-14 修订）

### 4.1 先解析执行单元，不预设每会话一个 worker

撤销原首版“一原生受控会话一个 DSH worker”的既定选型。原生创建/恢复、上下文、并发、工具、后台执行及跨入口历史语义未验证前，不拆分或替换 DSH 工具实现，不新增 profile 注入来强行满足结构图。已有原生 worker、沙箱或授权接口是待核验能力，不能按产品名假定存在。

AgentInstance 是登记身份，Workspace/Session 是可信原生主体，ExecutionUnit 是实际可监督的执行边界，PolicyBinding 记录二者的映射与覆盖操作。映射可一对多、多对一或暂不可解析；同一进程池服务多个会话时必须显式保存共享成员。路径、cwd、工具调用标签只可作为相应证据，不自动成为独立边界。

Connection 负责原生 argv、cwd、环境、打开方式及启动/附着所有权；NativeAdapter 负责原生身份、能力与执行拓扑；统一策略控制器负责四层组合、审批、影响解析和调用相应机制。后续新增 Agent 复用这些合同，不复用某产品的内部工具实现或专用提示词。

### 4.2 ActPlane 域身份与继承

在同一个 ActPlane 引擎实例中，cap_task 是进程 PID/TGID 到一个当前 domain_id 的映射；进程可以受控重新绑定，但同一时刻只有一个直接活动域。域可以有父域，规则匹配沿实际祖先链进行；因此进程可以继承多层约束，不能同时归属两个并列会话域。fork 默认继承父进程域，不因子进程 PID 不同就获得独立策略。

域身份至少使用 engine_ref + domain_id，其中 engine_ref 固定 host/boot、watch 进程开始身份、受保护 map/pin 实例及引擎配置版本。不同 watcher 可能有独立 map 命名空间，单独数字相同不表示同域；同一 PID 上叠加多个 watcher 也不会自动区分会话，只会增加共同执行的约束和生命周期风险。

四层配置可由可信编译器组合成目标执行单元的完整有效包，也可在已验证的真实父域拓扑中继承；四层不要求四个进程或四个域。source 程序选择、域身份、scope_id 权限元数据和文件对象范围分别校验。scope_id 数值比较不证明目录包含。域祖先查询有有界深度；当前审计普通/legacy 路径为 8/1，运行能力仍以对应部署 profile 为准，不能承诺无限委托或压掉超限规则。

### 4.3 共享执行单元的兼容性门禁

分别计算每个目标会话的四层目标策略，再按 enforcement_kind 投影到对应机制。ActPlane 只承担其支持的内核操作；原生工具授权、网络过滤、挂载和行为指导分别记录能力与证据。

若多个会话共享一个执行单元，在相同可观察事件条件下却要求不同内核处置，不能在该单元内独立应用。例如同 PID 对同一文件的 read，S1 要禁止、S2 要允许，现有进程域无法仅凭逻辑 session_id 区分。

共享策略必须有可信兼容性证据和覆盖/影响核验。相同规范化内核投影与相同状态/能力要求可作为保守等价依据；语义等价未证明、SMT unknown 或状态条件未知时保持不可应用。不能把禁止取并集后限制全部会话，也不能采用宽松结果失去保护；不能只比较自然语言、路径名、rule 数量或文档名称。确需扩大影响时新建对应范围候选，重新审批，不能回退为 Agent 策略。

对象限制不等于主体隔离：在共享域禁止访问 W1 的路径，W2 会话访问该路径同样可能被拦截，不能因此宣称规则只作用于 W1 会话。验收必须包含其他工作区对同一目标路径的交叉访问。

### 4.4 应用影响闭包与执行方式

审批/应用同时冻结逻辑目标、原生身份和成员版本、全部执行单元、各单元的共享主体、机制覆盖、实际规则变化范围以及暂停/终止的可用性影响闭包。任何变化重新校验。局部提案不能把共享成员藏在审批范围之外。

应用方式由已核验机制决定，可为原生授权配置、独立执行单元的完整包重建，或另案实现并验收的版本化热更新；不默认重建每个原生会话。热更新改变同一域的规则版本，不产生新的会话区分能力。某条规则能编译不代表可以按请求作用域加载。

应用失败按实际受影响执行单元门控，回执如实列出共享影响。只有可信独占边界存在时，才能承诺只暂停/终止当前会话而其他会话继续。系统保护丢失时既有 fail-closed 可回收整个受控单元，但不得把此事件描述为单会话操作成功。

### 4.5 取消、结束、停用与资源回收

取消会话中的任务、结束逻辑会话、停用本层规则、停止执行单元是四种操作。共享服务中的取消优先调用已有原生会话取消接口，并核验其覆盖；“已发送取消请求”不等于后台执行和旧句柄已经回收。

只有证明某个运行单元/进程子树为该会话独占，且全部相关后代被覆盖时，才可用终止 cgroup/子树完成独立撤销。对共享 cgroup 不能 kill 后称为只结束一个 session。严格撤销需要停止共享单元时，必须按真实影响另行授权或依照已明确的系统故障合同执行，不能隐瞒其他会话中断。

停用会话规则不移除上层保护。FD、mmap、已建立连接、后台工具和共享守护进程分别验收，不把原生 cancel、规则删除或换域直接当作全部撤销证明。共享代理/远程执行器没有可信合同则不声明被本进程域覆盖。

会话恢复与身份轮换、跨工作区迁移须重新核验目标和继承；新 session_id 不自动继承旧局部配置。跨 cwd 不自动改变归属。未来会话进入已有执行单元前，先核验批准基线、成员变化与共享策略兼容性，不能等首次违规后再补绑定。

## 5. 原接口、存储和兼容建议（历史，不按本节新增四套目标）

| 接口族 | 保留/新增的合同 |
|---|---|
| 现有 system 与 instance DSL proposal/confirm | 保留现有明确作用域和幂等行为；不承接 workspace/session 候选；既有 Agent 规则不自动迁移或缩小 |
| history inputs/generations | 第一阶段已新增服务端冻结的生成目标：新 agent_context 默认为 session，场景 bind 为 workspace；已加载旧 Agent 文档保留历史范围，缺目标的旧候选禁止新导入；session_id 不能代替独立执行绑定 |
| 新增 workspace DSL 接口族 | 建议位于 `/api/agent-instances/{id}/workspaces/{wid}/dsl`，提供读取、提案、确认/拒绝；归属及独立绑定能力在提交/应用时都校验 |
| 新增 session DSL 接口族 | 建议位于 `/api/agent-instances/{id}/sessions/{sid}/dsl`，冻结 workspace 归属及会话生命周期，禁止共享执行器上静默扩大 |
| console approvals | 复用统一决策；投影精确目标、继承层、影响成员、执行能力和应用回执；新增字段兼容现有客户端，不修改旧审批的历史目标 |

持久化需要工作区策略版本、会话局部版本、继承基线快照、候选/批准关联，以及 Connection、NativeSubject、ExecutionUnit、PolicyBinding 和机制覆盖。Binding 按主体/单元关系及代次保存，不预设一会话一个 PID；域引用包含 engine_ref，回执区分目标策略摘要与实际加载包摘要。复用统一候选/审批与应用编排，不按四个页面建立四套审核器。迁移时现有 system/instance 文档保留原范围；缺失新 scope 元数据的旧记录按其原接口解释，禁止靠生成会话反推并改写历史授权。

目标策略摘要包括四层版本/内容及逻辑目标；实际加载包摘要另包含机制投影、源身份、engine_ref/domain、能力清单、编译产物、状态版本及绑定代次。审批同时记录逻辑目标和物理/可用性影响闭包。parent 更新后，相关候选失效；当前后代由受控协调器重新核验/迁移，新会话先取得最新批准基线再启动。应用中断必须有可恢复的阶段回执，不能把跨进程操作描述为数据库原子事务。

## 6. 原界面落点（历史）

沿用 [界面约定](../design/agentscope-ui-design.md)，不增加四层编号徽章或四套导航。系统入口管理系统策略；Agent 助手先选择“Agent 基线/工作区”并按需选原生目标和材料；会话页管理当前运行时候选与继承详情。列表使用记录表、详情按需展开，统一跳转审批中心。

场景建议默认提交工作区；运行时建议默认提交会话。界面在起草、提交和确认处显示同一实际范围，不只在说明小字中提示扩大影响。审批详情展示继承配置与本次局部变更；无法局部应用时说明缺少哪一种可信执行/原生授权能力，不展示可应用按钮，也不一律要求用户拆进程。工作区只显示可信原生名称和实际项目路径，无可信信息则不伪造名称。此处允许目标选择，未恢复旧工作区目录/详情导航。

E1–E13、RQ 编号、内部模型诊断留在研究附件，不进入客户模板标题。系统调用匹配与工具 Trace 分开；无可信关联的内核事件只可表示执行域证据，不补造会话/工具归因。

会话安全视图分别列出本会话新增配置、上层继承配置、按四层计算的目标规则和当前执行单元实际加载规则。每条显示机制、覆盖操作、共享范围及核验状态；保留原始 DSL 和加载 DSL 的对应关系，编译/配置存在不等于已生效。无可信会话归因的事件只属于执行单元，不算本会话命中。

| A01 | 无运行会话生成 Agent 基线 | 固定实例和上层基线；不伪造 PID/domain |
| A02 | 仓库 MD 与独立规范分别生成 | 证据与目标独立，仓库默认 workspace，推广需新审批 |
| A03 | 同工作区 S1/S2，仅批准 S1 局部只读 | S1 可读不可改；S2 原可写仍可写；PID/domain 与事件不串用 |
| A04 | 同 Agent 的 W1/W2 | W1 规则不改变 W2 执行；chdir 不逃离 W1 主体 |
| A05 | A/B 两 Agent 共享仓库 | 共享路径不共享授权；仅批准 A 不改变 B |
| A06 | 子进程、孙进程、嵌套子 Agent | 保留父约束；子域不能放宽；域深度超限显式失败 |
| A07 | 生成、提交、拒绝、确认漂移与重试 | 未批准权限/绑定/有效包不变；漂移拒绝；重复确认幂等 |
| A08 | 上层 locked 与局部 permit/假 gate | 不能绕过；确认程序名不能冒充可信人工批准 |
| A09 | 会话结束、后台进程、PID 复用与恢复 | 后代回收；新身份重新核验；未来新会话不继承局部规则 |
| A10 | 共享执行器、缺工作区身份、容量不足 | 不支持局部应用且不回退扩大到 Agent |
| A11 | 应用失败、重启恢复、上层更新 | 门控真实影响闭包；独占边界才要求其他会话可用，共享影响如实报告；基线与回执重新核验 |
| A12 | OS 操作、反馈和任务结果 | root 内核记录、真实 allow/block、DSH 存活和任务效用分别验证 |

具体案例和命令准备见 [后续复现方案](../research/20261012-four-layer-policy/reproduction-plan.md)。A01–A12 在调研阶段仅作为待实施验收合同，均不计入该次通过数。

2026-10-12 实施更新：已实现目标冻结、独立局部审批和不支持时禁止应用，见[第一步 RFC](RFC-20261012-AgentScope-policy-targets-step1.md)及[验收](../acceptance/AgentScope-policy-targets-step1-20261012.md)。新生成不再沿用 legacy Agent 默认目标。当时选定的原生工作区／会话独立 worker 与加载器未实现；2026-10-14 已撤销默认 worker 选型，局部正向执行仍未验收，A03–A06 等内核隔离项仍待验收，不能由本轮 HTTP 拒绝结果替代。

## 2026-10-14 补充验收

A03–A06/A09 的局部正向验收须先证明相应机制覆盖和执行边界；仅返回能力不足不算局部能力完成。新增 A13 共享单元冲突拒绝且不取严格/宽松合并；A14 fork 默认同域、不同 PID 不冒充隔离；A15 热 epoch 变化不扩大能力；A16 engine_ref 区分同号域及共享成员漂移；A17 共享会话取消不误杀服务；A18 其他工作区访问相同路径的负向控制；A19 DSH 原生工作区/会话/上下文/工具及历史流程保持；A20 审批后拓扑或可用性闭包变化导致失效。详细推导与矩阵见本次重推 RFC。以上均为未实施验收要求。
