# AgentScope 统一状态与集中配置

日期：2026-10-20。范围：状态只读投影、显示身份、配置入口与证据展示。源码基线：隔离工作树 `agentscope-label-flow-20261020`，起点 `3e4e837`。本轮不切换正式服务，不重启受控 Agent。

## 产品职责

本表原有的 Agent/会话加载入口重复已在后续小步修改中收敛：本地 main 移除 Agent 加载页签，旧链接进入准确实例的会话目录。运行事件入口仍保留，后续另行收敛；本步未发布到主服务。详见 RFC-20261020-AgentScope-loaded-view-single-entry。

| 模块 | 唯一职责 |
| --- | --- |
| 总览 | 运行与加载核验概况、待处理事项、按需使用说明 |
| Agent连接 | 连接与资源登记、启动/停止、只读运行和加载核验 |
| Agent | 策略助手、真实运行事件（事件入口收敛留后续；不再提供重复加载页） |
| 系统 | 策略模板主表与子配置、标签管理、只读生成记录 |
| 审批 | 批准/拒绝、单独应用、失败恢复 |
| 会话 | 已加载策略、运行事件（内核命中/工具调用分开）、信息流 |
| 历史档案 | 旧任务和历史证据，只读 |

“全部受控 Agent / 指定 Agent”是作用范围，不是两套配置入口。工作区仅作为资料路径和历史归属；会话不构成新的执行隔离域。

## 权威链与状态合同

发布模板或手工 DSL → 保存不可变配置版本 → 生成候选/校验 → 审批决定 → 显式应用 → Broker/ActPlane 回执 → 观察器核验 → 只读产品投影。标签来源版本、原始 DSL、审批身份和既有执行器授权不改写。

新增 `instances/product_status.py`，复用现有记录，不建立状态数据库：

| 维度 | 产品状态 | 输入 |
| --- | --- | --- |
| 运行 | 未运行、启动中、运行中、执行暂停、启动失败、状态未知 | 观察器、可信启停事件、执行门 |
| 配置进度 | 草案、待审批、待应用、应用中、已应用、已拒绝、需重新校验、校验未通过、应用失败、暂不可应用 | 对应配置版本、审批及应用结果 |
| 当前加载 | 已加载、核验中、未核验、未运行、仅观测 | 当前运行身份与实际加载快照 |

Agent 列表/详情增量返回 `product_status: AgentStatus/1`，包含 `runtime`、`loading`。配置/审批增量返回 `configuration_status: ConfigurationProgress/1`。会话加载保留 `SessionLoadedPolicies/1`，增加 `loading_status`、`instance_id`、`observed_at`、`expires_at`。旧字段保留兼容，但不再用于普通页面的加载判定。

加载条件必须同时满足：

1. 观察器状态新鲜，沿用观察器 `TTL=8` 秒常量；返回观察时间和到期时间。
2. 实例、运行代次、PID、进程创建身份、boot/host、执行域，与 runtime 和 receipt binding 全部一致。
3. 实际加载的 bundle/DSL hash 一致，快照确实标为 loaded；受 Broker 准入监管的还要求保护回执新鲜。没有导入 DSL 的启动规则允许显式 `dsl_hash=null`，但必须各方均有该字段且一致，实际 bundle hash 仍须非空且一致；缺失字段不等于显式空值。
4. open/paused 只代表执行门，不能代替加载回执。接口不可达是未知，不是未运行。
5. 配置新版本不能替换旧加载快照；配置“已应用”也不是当前内核加载证明。

完整性与核验分开：身份可核验但编译清单缺失，显示“已核验 N 项 · 清单不完整”；只列映射完整的记录。旧 PID-only 回执继续可读，不能冒充当前加载。

`configuration_revision` 只在已加载文档与同范围不可变版本完整、唯一匹配时提供。多版本内容相同或旧回执材料缺失时返回空，不按最新版本或近似 DSL 推测。

前端共用 `ProductStatus`、`currentStatus/currentLoadedView`：到期自动降为未核验、清空当前加载行；请求失败、切换目标和旧请求回到页面时不能保留旧绿色。轮询串行并通过清理标志/请求序号隔离响应。

归档/停用是独立生命周期标记。归档不表示停止执行；停用标记仅来自已应用的移除结果。

## 身份与定位

显示“连接名称 · Agent 类型”；缺名/同名追加稳定实例短标识，发生短前缀冲突时扩展。PID 不用于区分实例。后台仍绑定完整实例 ID，不改写历史审批。

System 跳转携带 `policyScope`、`policyAgent`、`configurationId`，展开并定位对应子配置。目标失效不切换到其他 Agent 或全部 Agent。旧 Agent/连接编辑链接归一到系统；历史工作区链接仍只读，不扩大归属。

“全部范围”只是列表过滤。没有显式授权范围的新配置必须选目标；手工和助手仍共用原实例化、来源引用、版本、校验服务。

## 展示边界

- 保留主模板表+子配置记录。模板详情默认只读，维护模板为高级操作。
- 不可执行的模板不提供正常新增入口；高级可查看不可用模板，旧配置保留。
- 助手只有对话起草、只读结果和到系统查看；不管理提交、编辑、归档。
- 连接详情不嵌套策略编辑器；会话没有独立策略编辑/运行前生成按钮。
- 会话信息流的命中名称只从同加载回执的实际 rule ID/编译映射取得，标签来源名称不能当成命中策略名称；没有映射则明确“策略名称未记录”。
- 信息流筛选只列该范围实际事件中记录的标签。图仍按真实前驱回执构造，不根据路径、PID、时间拼边；进程默认用图内序号，PID 在技术证据。
- 当前代次是否历史按代次/会话历史身份判断，不使用与最新期望配置耦合的旧 `active`。
- PID、domain、hash、DSL、原始 JSON、验收统计放技术证据/高级入口。高级入口不等于服务端角色权限隔离。
- 高级 DSL 记录同样使用服务端配置进度；加载明细集中到会话的加载视图，不恢复旧 active/loaded 组合推断；总览和连接页保留核验摘要。
- 使用说明替代重复安全亮点/公告入口；共享域、未核验、应用影响、采集失败和缺口仍明确可见。

## 本期排除项

不实现自动运行时策略生成、单调增量热装载、会话子域隔离、网络覆盖扩展或多人分权。ActPlane 传播/拦截引擎代码不在本轮修改范围。正式切换/Agent 重启与远端推送均另行确认。
