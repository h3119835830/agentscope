# RFC：控制台首页安全场景公告

日期：2026-10-09。范围：正在运行的 AgentScope 控制台首页展示。

## 问题与行为

首页已有策略、任务和执行环境数据，但缺少能解释系统安全价值的具体场景。增加只读公告，默认展示一个案例，通过六个页签切换：脚本偷读凭证、链接越界写入、篡改验收证据、后台继续写入、跨任务越权、伪造扩权审批。

每个案例明确用户任务、工具层可见信息、隐藏风险和防护目标；新增价值、验证依据与能力边界进入折叠详情。公告整体可收起，不替代任务数据、审批入口或执行审计。

## 接口与安全边界

- `frontend/src/SecurityNotice.jsx` 是纯展示组件，无 API、凭据、策略加载、授权或进程操作；只在总览渲染。
- 数据为人工维护的场景说明，不能显示为真实告警、通过案例或当前保护状态。执行后端健康状态不参与公告结论。
- 对照对象限定为只看工具调用的审查视角，不能宣称所有工具审计都无法发现或只有 AgentScope 能防御。
- 内核场景仅针对已配置并实际覆盖的 Hook、对象与执行域；控制面审批与内核拦截分别验收。
- 已有 FD、可写映射、链接别名与后台进程属于独立验收项，不根据普通写入成功/拒绝推断全面支持。

## 验证与发布

运行现有前端回归、独立 Vite 构建，并在真实首页检查场景切换、折叠、键盘操作、导航和窄屏。构建必须来自独立工作区，避免打包另一项并行界面修改。发布只替换静态资源，先校验线上入口哈希、保留旧资源并原子替换入口；无需重启 API、Broker 或 DSH。

研究依据：[ActPlane §3、§5.3、§5.6](https://arxiv.org/html/2606.25189v2)、[OpenAgentSafety](https://arxiv.org/html/2507.06134v1)、[GhostApproval 原始研究](https://www.wiz.io/blog/ghostapproval-a-trust-boundary-gap-in-ai-coding-assistants)。后两类扩展场景是工程威胁建模，不借论文结果宣称本机效果。
