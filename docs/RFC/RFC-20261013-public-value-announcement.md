# 对外价值公告与原安全总览的内容合同

状态：已实现并完成正式阅读页验收。用户批准仅改公告，受众为导师与外部读者，原安全总览保持现状。初次整合基线 `9934dc3`，随后按用户要求在 `2f37aff` 基线上替换旧实验报告页面。

## 内容与入口

正文维护在 `research/value-reliability-20261012/announcement.md`，由 `scripts/build_value_announcement.py` 同时生成 `/value-announcement.html` 与 `/value-evidence.html`，两者字节一致。后者保留旧地址可用，但内容已替换为公告，不再展示六项本机实验表格，也不保留公告指回旧报告的按钮。围绕插件读取凭证、后台后代、路径实际对象、跨进程来源与测试完整性五个场景，按合法任务、隐藏行为、应用日志缺口、内核侧作用和具体价值展开。应用层任务记录与内核侧关键操作的两行图明确标注“机制示意”。研究附件继续保留实验环境、失败结果与适用边界。

旧报告原样归档到 `research/value-reliability-20261012/experiment-report.html`。`build_value_evidence.py` 仍维护研究报告与证据数据，但 HTML 只写入该技术附件路径，不能覆盖前台公告。公告 Markdown 正文与上一版相同，本次只调整页面出口和移除旧报告链接。

公告说明三种能力：命中事件可审计；操作返回与用户态规则解释可反馈；运行保护绑定和事件处置可监控。内核负责规则检查、处置及事件输出，用户态负责解释与展示；不把用户态说明冒充内核决策，也不把关键事件审计表述为全系统调用的无遗漏记录。来源场景限定为新连接，原生补充任务仅声称可见拒绝后合法读取继续。

## 发布合同

发布脚本 `scripts/publish_value_announcement.py --apply` 仅对两个公告 HTML 文件逐个原子替换，先保存旧文件及运行快照，校验两份文章一致且源文 meta 哈希相符，再核对两个 HTTP 地址的内容哈希。其他静态文件、服务身份、实例授权、DSL 修订与 18000/18004 监听必须不变。失败时只恢复仍为本次预期内容的目标文件，不覆盖并发修改。原总览 React 源码、入口 index、JS/CSS 及示意案例均不得改变；不得重启服务或操作 Agent。

桌面保留文章目录，窄屏单列阅读，章节可键盘跳转，打印样式保留。源文哈希在 meta 中，正文不展示部署编号、PID 或诊断 JSON。仅更新本地产品阅读页，没有发送给导师或发布到外部渠道。

验收与证据见 [REVIEW](../REVIEW/REVIEW-20261013-public-value-announcement.md)。本合同接续此前公告生成合同；原安全总览仍遵循其恢复合同。
