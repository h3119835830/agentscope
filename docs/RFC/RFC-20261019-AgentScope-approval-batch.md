# 审批记录的批量操作

状态：已实现。界面限定为审批模块，复用既有服务端合同。

## 操作与分类

待审批提供多选及批量批准，待应用提供多选及批量应用。需要处理包括 `stale`（需重新校验）、`invalid`（校验未通过）、`failed`（应用未完成）、`blocked`（暂不能应用），提供批量重新校验。已处理记录只读。全选限定为当前页签和搜索结果，切换页签或搜索清空选择，不能把不可见记录纳入操作。

需要处理页显示分类说明及每条记录的具体原因。可恢复的记录读取重新校验预览；不支持或读取失败的记录显示跳过原因，可按权威目标返回所属配置。重新校验创建新候选，不覆盖旧记录，不批准或加载，编译仍未通过的新候选如实显示校验未通过。

## 接口与确认

界面按记录读取 `GET /api/console/approvals/{id}`。重新校验另外读取 `GET .../{id}/revalidation`，展示原版本、本次采用版本和差异。预览没有写操作。

用户核对内容与范围后，一次确认批量操作。顺序调用既有 `POST .../{id}/approve`、`POST .../{id}/apply` 或 `POST .../{id}/revalidate`。每项拥有独立幂等键，批准携带候选指纹，应用另携带批准回执，重新校验携带预览计划指纹。

提交每项前再次读取，核对精确记录、范围、候选、基线和批准回执与用户看到的快照一致。变化时不替换成新内容执行。服务端继续执行权威校验与事务，界面检查不构成授权。按项读回结果，区别成功、失败、跳过及请求已提交但状态未读回。批量操作不具备跨记录原子性。

## 范围约束

沿用同一范围至多一项待应用变更的合同。一次选择多个相同范围的待审批候选时，该组都跳过并要求缩小选择，不能自行选其中一项批准。其他独立范围继续处理。系统范围应用可能使指定 Agent 候选失效，按原合同拒绝，不自动合并或重新批准。

批量应用与批量批准始终分开。没有新增批准并自动应用入口，也没有修改 DSH、Broker、ActPlane 或服务端审批接口。
