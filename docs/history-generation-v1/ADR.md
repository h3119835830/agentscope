# ADR：固定 LLM 生成流水线与共享 PolicyIR

日期：2026-10-04。状态：采纳。

1. 第一层固定无工具 LLM 流水线，第二层保持 Pi Agent。第一层阶段明确、可检查点重试，Pi 根据具体任务检索/决定适用性；不把两层的权限与职责合并。
2. 模型只生成 PolicyIR，程序确定性渲染 DSL。取代生产历史转换中的直接 DSL 文本生成；旧转换函数仅作为兼容入口保留，生产作业走结构化路径。Pi 共用渲染器，受控草案权限不扩大。
3. 完整性和本机适配是两个状态。源要求完整而缺部署参数时可入库；执行前必须新版本绑定、编译、重新审批。标记不能替代服务端凭据。
4. 二审读取原文完整上下文及多段证据，单条复核采用专门任务合同。通用语义上下文、模型输出 schema 与能力定义修复适用性问题，不添加 RQ5 场景特定修复提示词。悬空冒号引导语增加确定性阻断；没有句号的完整祈使短语保持允许。
5. 最终人工操作同时绑定语句和产物 hash；不在自动流水线阶段逐次人工审批。修改或适配不继承批准。
6. 通过独立工作树、数据库、端口和 Broker 验收，避免与当前启动前工作台并行开发或普通业务混合。此轮不推送远端。
7. 策略生成面向本次生成及审核，生成记录与审计承载历史和过程。当前对象由上层状态管理，历史默认只读，继续审核必须显式跳转。共用结果组件而不复制审核逻辑；新增只读分页查询，原执行/审批合同不变，历史内容不重新生成。

取舍：语义判断存在模型波动，二审不能替代人审；信息不足时保留待澄清与诊断。Pattern ABI 限制保留，超长路径阻断，不使用缩短规则范围来掩盖错误。内核探针证明已测试操作的效果，不宣称所有文件系统元数据行为、语义或内容均受保障。
