# AgentScope 策略对象与审批执行链解耦决策

2026-10-12 补充决策：四层配置、来源/目标分离、首版原生会话独立 worker 和所有变更人工确认以 [新 ADR](ADR-20261012-AgentScope-four-layer-policy.md) 为准；本文件保留此前决策记录，不将新目标描述为已实现。

日期：2026-10-11。状态：按用户确认采纳 Agent/工作区两条主要生成主线；新增作用域与生成合同待实现，既有源码进展分别记录。架构依据见 [RFC](../RFC/RFC-20261011-AgentScope-policy-control-architecture.md)。

## 1 以执行安全治理作为产品定位

AgentScope 负责把配置和场景建议连接到可信执行约束，并提供可复核回执。保留 ActPlane 技术归属，强调 AgentScope 控制面、场景编排和治理贡献。放弃以“所有恶意行为均可阻止”“任意自然语言都能进入内核”“底层内核机制全部原创”作为产品承诺。

取舍：功能承诺更具体，演示需要实际规则和证据，但避免把平台就绪或模型拒绝误作安全结果。

## 2 将作用范围与候选来源拆开

系统、Agent、工作区、会话表示作用范围；手工、模板、场景、运行时表示来源。主要生成目标为 Agent 基线和工作区策略。会话提供可选上下文及有可信执行绑定的局部增量；系统保留管理员共同配置入口。运行时建议提升为工作区、Agent 或系统规则时，创建新目标候选，重新校验和审批影响快照。停止把“启动前/运行时/历史”当作相互独立的策略存储和加载系统。

取舍：统一模型需要兼容适配，但避免一条候选在不同页面拥有不同权限与状态。

## 3 共用人工审批和可信应用编排

所有产品策略修改均先形成候选，由用户确认后应用，包括收紧。旧 restrictive 自动应用路径不符合当前合同，列为迁移项；不在本次文档 PR 中直接改变运行行为。紧急风险可暂停执行门，但暂停不意味着批准候选。

资产内容审核与执行授权仍是两个事实。历史语句通过审核只表示可以复用，不能跳过对目标、基线和影响范围的应用确认。

取舍：收紧需要一次人工决策，但避免无提示重启共享执行器、影响全部会话，以及绕开审批中心。

## 4 共用生成服务，复用场景采集能力

策略助手与模板入口共用候选生成服务，先固定 Agent 或工作区目标。Agent 基线使用真实实例身份、来源、资源、能力和继承基线，不强制选择会话。工作区策略使用 `(instance_id, workspace_id)` 的可信身份及项目上下文，会话仅按需引用。场景读取复用冻结清单、脱敏和只读能力；任务创建和策略生成分别消费，不互相强制触发。

此前运行助手只有环境元数据和用户需求；场景读取接入助手已有 [第三步源码进展](../RFC/RFC-20261011-AgentScope-agent-scene-step3.md)，不等于无会话生成、工作区策略存储或独立执行绑定已经实现。需要补齐时修正上下文与接口，不添加针对某条任务的特殊提示词。

取舍：需要明确场景采集用途和材料版本，但避免重复实现高权限文件读取器。

## 5 配置继承与运行域分开展示

目标配置关系为系统 → Agent 实例 → 工作区 → 会话/任务 → 受委托子 Agent。该顺序是 AgentScope 的产品映射，ActPlane 提供通用父子域；工作区目录本身不会自动创建域。跨 Agent 共用项目资产，由控制面组合进各自有效策略，不能构造多父内核域。

原生 DSH 实例当前共享执行器；只有可信绑定能证明局部执行范围。不能区分工作区来源时拒绝工作区级应用，不把候选自动转换为 Agent 策略。会话/工作区独立域作为后续能力建设，不由 UI 构造。

可执行文件匹配只用于来源标签，实例身份依赖运行代次、PID 开始时间、主机启动身份、域与策略哈希。解释器路径不能唯一代表一个 Agent。

取舍：新增工作区身份、版本与审批适配，但能明确同一 Agent 下不同项目的边界。配置继承图不能代替实际域绑定；可覆盖默认配置与不可移除强制底线分别处理。

## 6 保留产品投影与完整诊断接口的边界

客户会话视图只呈现可信关联到当前会话的事件。完整诊断接口可以保留共享执行器事件，但必须明确未归属状态，不能被新客户页面直接复用而跳过过滤。

当前产品投影隐藏 legacy-generated 策略，造成保护状态与策略空表并存。保留用户配置表的整洁，同时提供平台约束的可读只读摘要。展示隐藏不影响加载，不具有授权或隔离效果。

取舍：增加一份可读有效策略投影，但无需复制底层策略或创建第三套加载链。

## 7 先统一合同，再拆部署

保留模块化单体控制面与独立高权限 Broker。以身份上下文、策略资产、候选生成、审批应用、执行证据为代码边界，通过类型明确的内部接口协作。暂不按导航模块拆微服务。

取舍：降低当前发布与排错复杂度；未来可按场景采集/生成队列负载拆分，不改变策略授权合同。

## 8 发布事实由组件清单描述

当前 API、Broker、静态 UI 来自不同目录，部分为未提交叠加源码。以组件文件哈希和构建资产为当前事实，不以某个工作树 HEAD 代表全栈发布。后续发布清单至少记录源码提交及脏状态、编译器/引擎、前端制品和配置版本。

取舍：需要额外发布清单，但能解释“代码测试通过”“页面已发布”“策略已加载”之间的差异。

## 9 本次变更范围

本轮更新架构、决策、评审、问题与关联实施记录，补充文档验收证据。不修改 AgentScope 运行代码、ActPlane、数据库、服务配置或普通业务代码，不执行策略确认、加载、启停和部署。整改项保持开放，后续实施按相应阶段测试验收。

## 10 工作区身份与影响范围固定

工作区身份来自已核验原生元数据与精确会话归属，不从 cwd、挂载名或路径末级名称推造。默认工作区策略只作用于所选实例的所选工作区；同目录被多个 Agent 使用也不自动共享授权。候选、审批、幂等键和执行回执均固定实例、工作区、上下文及基线版本。切换目标必须重新适配候选；未来所属会话在执行前继承已批准版本。

取舍：原生元数据不足或执行器不支持局部绑定时，明确保留能力缺口，避免以扩大到全部会话换取表面上的应用成功。Agent 基线可以独立起草，工作区材料不因此成为必读输入。验收采用 [RFC A1–A12](../RFC/RFC-20261011-AgentScope-policy-control-architecture.md#11-agent工作区主线的后续验收合同)，本轮静态文档验收见 [REVIEW](../REVIEW/REVIEW-20261011-AgentScope-agent-workspace-policy.md)。
