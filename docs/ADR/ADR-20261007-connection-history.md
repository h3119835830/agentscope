# 连接历史采用追加观测与冻结任务来源关联

采纳追加式 SQLite 元数据事件；按实例聚合为一条历史入口，内部保留代次与过程。原因：内存 Observer 适合短时实时判断，无法支持服务重启或已结束实例的回查。

采纳后台稳定观测去重、手动检查逐次记录。这样能保留用户检查失败与成功的回执，同时避免每三秒生成无变化日志。持久化事务以数据库为去重基准，API 重启不会重复生成“首次连接”。代次变化比较最近非空的历史代次，短时未知不遮蔽重启。

历史查询只读，不用于 Observer.require、工作区读取授权或执行绑定恢复。实例历史显示“已核验接入”等当时状态，实时“已连接”仍须当前独立观测与 TTL。

任务关联优先使用创建任务时冻结的实例来源；执行实例与项目来源实例分别标识。连接详情直接打开原任务档案，任务档案可反查来源 / 执行连接。早期无事件的数据不伪造，也不因连接历史缺失而重跑任务。

不采纳保存原生会话 / 原始响应 / 凭据；不增加一键重连、策略加载或自动启动 Agent。存储故障不得改变在线观测事实。该选择不会修改普通业务接口或 ActPlane 权限执行合同。
