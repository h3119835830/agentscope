# ADR：四层配置与会话独立执行的边界

日期：2026-10-12。状态：采纳为目标设计；实现待后续任务。关联 [RFC](../RFC/RFC-20261012-AgentScope-four-layer-policy.md)。

## 采纳

1. 以 system → agent → workspace → session 组织客户配置，任务/子 Agent 继续委托。平台自保护另列可信底线；产品层名是 AgentScope 映射，不声称论文固定了这四层。
2. scope/target、origin/context_ref、authority、execution binding 分开存储。独立规范和仓库 MD 均可引用；仓库默认工作区，运行时默认当前会话，扩大范围必须新建候选和审批。
3. 工作区默认联合目标为 (instance_id, workspace_id)，会话额外绑定 session_id。共享仓库可复用资产，不自动跨 Agent 授权。原生工作区信息缺失时阻止局部应用，不按路径或名称猜身份。
4. 首版原生会话采用独立 DSH worker、cgroup 和 ActPlane 域；四层配置在控制面组合完整有效包，Broker 批准后门控、重建、核验和恢复。Agent 登记身份与运行绑定解耦；不要求每个配置层恰好对应一个内核域。
5. 上层强制规则对后代锁定；所有用户策略变更包括收紧仍需人工确认。拥有本层权威者可经新审批版本修改本层规则，不能把所有策略都描述为永久 append-only。可选资产与 ActPlane default binding 区分。
6. 借鉴 Progent 的任务/工具上下文组织和权限变化比较思路，保留当前确定性权限转换；不直接采用其全局可变策略对象、默认可跳过检查的入口或自动应用收紧。SMT 仅可用于已证明支持的规范合同，unknown/超时/不支持不得视为已证明收紧。
7. 借鉴 FIDES 的材料标签和 CaMeL 的非可信内容隔离，应用于生成上下文与授权依据分离；不将其工具/解释器策略当成 OS 覆盖。PCAS 的因果授权解释可作为后续增强，不引入第二个审批权威。

## 不采纳与取舍

仅修改界面“会话”标签不能改变实例级 DSL；按 cwd 或同一 node 可执行文件识别会话会串用；在一个共享 PID 上切换全局策略不能安全支持并发会话。可信工具标签改善归因，不等于主体隔离，因此不作为首版替代方案。

直接开放上游 MCP/control 的变更接口会绕开 AgentScope 人工审批与应用回执，不采纳。上游 scope_id 的数字比较和有界祖先查询不作为任意文件范围包含或无限层级的证明。上游示例中的 human-approve/confirm/redact 可执行名称不是产品批准或内容审查的权威回执。

独立 worker 增加模型/进程资源、原生恢复适配和生命周期管理成本；换来明确并发边界和可验收的作用域。对共享原生执行器保留实例级应用与局部建议，不牺牲范围准确性兼容局部写入。后续若原生适配器提供可证明的任务调度/独立工具执行绑定，可另立 ADR 评审替代方案。

本次不迁移既有已批准 Agent 规则、不回收验收连接、不改变当前权限。源码审计结论与运行验证分别记录；上游生成/实验来源缺口未补齐前，保留未核实结论，不能以论文指标为产品承诺。
