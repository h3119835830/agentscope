# ADR：DSL 文档为编辑单位，编译回执为运行依据

状态：采纳。关联同日 RFC、REVIEW、BUG。

1. 复用现有 Rust ActPlane AST，通过 backend/dsl-adapter 集成。避免以正则重写条件或在 Python 中维护另一套语法。源码不改动 actplane 子树；发布流程必须先构建此适配器，并部署到服务可执行的受保护路径。
2. 保留完整原始文档与逐 rule 说明；编辑任一记录时编辑所属文档，预览文档内全部受影响规则。旧编译生成 DSL 保持只读，不能反向猜测为用户原文。
3. 文档命名空间按 scope ID 和 document ID 确定，系统规则 locked，变换标签只在自身文档内可见。系统约束与 Agent 文档相加，不提供下层删除继承规则的操作。
4. DSL 内容／资源指纹与旧工具／挂载 policy_hash 分离。保存的加载回执包括实际包 hash、映射及 generation/domain/PID。编译通过不表示加载或当前绑定，稳定规则名也不能证明新修订已加载。
5. 原生会话共享进程时，不按时间猜测工具与系统调用因果关系。只有受信任工具标签与相同域、代次能关联；本次原生 DSH 未提供该标签，工具 Trace 与内核匹配独立展示。
6. 系统／Agent 变更均使用候选与手动确认。失败关闭执行门，恢复需重新校验确认；停止连接只更新保存配置，下次启动才加载。
7. 上下文标注为用户声明的具体依据，不宣称模型已解释自然语言。DSL 中未解决的模板占位符拒绝，能力以真实编译器 host/backend support 为准。例如 block exec 携带 argv 的预执行阻断在当前后端不支持，不能因语法正确而允许应用。
8. 内核采集范围是已采集的策略匹配事件，不是完整 syscall 审计或全量执行轨迹。浏览器页面标示数据覆盖范围、断连和缺失映射。当前规则详情最多展示最近 300 条已采集事件中的 20 条核验命中。
9. 当前 pinned engine 不支持动态加入文件 contains/suffix matcher。拒绝通过向 watch DSL 添加不可命中规则来“预留”：singleton 初始化使用空配置，不能获得这些能力。采用编译产物 ABI 能力检查，在候选阶段拒绝；明确路径／前缀继续支持。若以后升级引擎，应同时升级并核验 ABI 和能力合同，而非静默接受。
10. 单个 Agent 的应用失败不成为全局停止开关。启动与工具准入分别核对 system 和该 connection 两个范围；系统失败仍保持全局关闭。

11. 生产交互采用 Agent → 原生工作区 → 会话。产品名与当前 PID 作为用户识别线索，不把测试登记别名、内部连接 ID 或运行代次暴露为用户需要管理的概念。原生会话名称和实际路径照实保留。
12. PID 可在进程结束后复用，故它仅是当前进程的展示标识，不能替代持久配置主键或证据校验依据。底层继续按稳定 Agent 记录、原生会话 ID、generation/domain/hash 校验，避免重启后混入旧事件。退休的前端代次链接恢复为当前上下文。
