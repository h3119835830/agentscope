# ADR：模型解释源动作，代码映射执行权限

日期：2026-10-11。状态：采纳，适用于登记 Agent 策略生成。

此前由模型直接选取 open/read/write/unlink，静态编译无法识别“允许读取”被扩大成禁止读取。采纳证据化的源动作合同、独立完整性复核和确定性权限转换。动作理解与后端能力分离；代码承担路径绑定、ABI 访问组映射、规则合并、权限冲突和审批前一致性检查。

不采纳针对中文“只读”、sales.csv 或某类项目添加提示词补丁；不自动删掉所有 open 规则（会破坏禁止读取/访问）；不把编译通过作为语义或人工批准；不以第二次模型输出自称正确来放行。

源动作 review 是通用的完整性阶段，检查动作、否定、对象、条件和例外，不包含业务场景特例。检查点在 IR 之前冻结，后续步骤不允许借编译诊断改写原意。

代价：增加一次源动作提取和一次完整性复核，但替代登记 Agent 原先直接 IR 生成调用；复杂来源标签与难以证明的条件交集暂不支持。能力合同更新会使旧候选环境摘要失效，需重新生成；已经应用的文档不被自动撤销。源动作误读仍需人工确认及持续独立验收，不能声称模型已被形式化验证。

## 发布与验收决策补充（2026-10-11）

采纳与 18003 当前 because/Pi Skill 和审批定位提交合并后，仅发布 API/UI 的方案，保留现有 Broker/执行器，避免为生成逻辑修复更改既有权限。真实执行验收采用独立原生 DSH 连接和合成数据；仅批准该连接的测试权限与只读候选。生成、编译、待审批、批准、加载 receipt 和 OS 实际效果分开证明，不通过附加“只读”特例提示词修补行为。没有可信工具标签的内核事件维持执行域级未归因状态；不为演示填充会话归因。
