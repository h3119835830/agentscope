# ADR：策略助手调用参数合同，静态模板下保存独立子配置

日期：2026-10-14。状态：采纳。依据：用户明确授权“像手工配置一样调用接口填参数”，新增策略放在“策略与模板”，静态模板下保留已配置子记录。

采用服务端模板注册表、参数化配置接口和版本化子记录。手工表单与助手共用 materialize/保存合同；助手仅返回已发布模板引用与参数计划，不使用 computer use，不输出自由 DSL，不持有审批或加载工具。固定模板效果、目标层级和运行条件由后端校验，管理员原有手工 DSL 与历史研究接口保留，不作为新助手的能力。

父模板不因某次配置而改变。删除限制和修改限制分别成为父模板下的同级配置；更新单条配置追加版本，新增配置保留所有同级记录。该关系不是权限继承树，也不靠操作先后判断该启用哪个策略。配置和现有审批通过不可变版本、模板摘要、资源映射及文档摘要绑定；重新校验必须保留绑定。

保留现有 ActPlane 访问组。本轮不扩展内核 ABI，单独写入或删除意图的草案必须显示实际影响两者，并在提交时单独确认；不能因为界面出现两个子记录就宣称实现精确操作隔离。分离内核操作属于后续独立改动，需要钩子、ABI、编译器和真实允许/拒绝回归。

系统模板明确在系统范围配置；Agent 助手只读继承约束。独立工作区/会话执行能力没有完成时，不退化成整 Agent 加载。生成与保存无运行副作用；批准和应用仍分开由用户执行。停用是需审批的明确移除，删除只归档未应用配置并保留历史。

替代方案：让模型自由生成 DSL、让模型操纵网页、每次修改共享父模板、用事件先后掩盖共享访问组，均未采用。代价是新增模板需要发布合同，不能靠模型填参补出缺失的内核能力；历史自由 DSL 不自动猜测或归入模板。
