# 采用字段摘要与分页记录表展示任务档案

采纳：以字段摘要和记录表替代任务档案默认时间线及 JSON 详情。

原因：任务包含数十至数百条事件，用户需要按时间、类型、操作对象、结果、版本和来源查找记录。统一的长时间线和原始对象输出让字段含义、记录范围及核验结论难以识别。

决定：四个页签分离概览与三个阶段；分类、搜索、筛选和分页只操作档案的只读投影。单条记录打开字段详情，返回时保留筛选与页码，并恢复焦点。原始 JSON 仅作为可选技术详情保留。

取舍：不在浏览器自动翻译任意模型文本，不将未加载记录计入已搜索范围，不根据存储表、PID 或任务状态猜测动作来源。通用固定英文约束使用明确词条翻译，未识别文本保留原文。

本次不引入新的后端数据模型或权限入口，也不将 UI 验收解释为 DSH 功能修复或 ActPlane 内核强制执行的验收。

补充决定：将关键权限回执与全部记录区分，并使用相同字段表呈现，避免在最近 50 条高频探针中遗漏早先 v3/v4 的加载记录。历史域图和 DSL 在概览中折叠保留，不要求跳回工作台。请求失败或接口返回结构不完整时只影响折叠内容。

后续修订（2026-10-07）：四个含糊阶段页签的可发现性未满足用户验收，已改为任务概况、运行前策略、运行时策略、执行审计、结束结果。原阶段事件在内部折叠保留；以ADR-20261007-history-policy-audit.md的当前实现和验收为准，旧截图仅保留历史时点。
