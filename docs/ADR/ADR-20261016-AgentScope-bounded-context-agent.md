# 用受限多轮接口选择资料，替代必填参考路径

日期：2026-10-16。决策：采纳。范围：AgentScope 策略生成资料链路；不改变执行面和普通业务。

原流程已能安全读取指定文件，但将“先知道资料在哪”留给了用户，未实现按场景自主选正文。采用多轮策略 Agent：服务端给出准确实例的登记目录，模型自主调用目录/读取接口，真实成功和拒绝结果更新上下文，再填写已有模板。

不采用 computer use，不采用全项目预扫描，也不按场景硬编码若干文件名。前者违反用户要求且慢；全量扫描会扩大资料暴露和延迟；固定文件规则无法适配真实项目。采用现有 JSON 模型合同承载严格的工具调用计划，服务端仅执行两种只读操作，不向模型交付管理凭证、任意 shell 或 HTTP 能力。

目录先行、累计额度、固定降权读取进程和现有策略守门共同限制自主性。模型选择不等于访问授权；项目文本中的批准和模板声明不产生权限。保留拒绝反馈使 Agent 调整下一步，持续失败时明确终止，不通过放宽权限或增加针对某个场景的提示词掩盖问题。

每个子配置绑定全部资料回执，提审和应用重验；不因生成成功自动提审、批准或应用。旧手工回执 API 保留兼容，但主界面不再要求选目录/填路径。全部 Agent 范围没有单实例扫描工具。

取舍：多轮调用增加模型请求和延迟，所以设置总轮次、调用数及期限。当前读取守门可能比实际标签策略更严格；自主选择也不保证最少读取。真实测试中模型读取了业务说明、订单样本和员工名册，共 4 份合成文件，不能据此声称“只读取必要说明”或“已阻止所有敏感正文”。后续如需更强的数据最小化，应增加独立可验证机制，而非把提示词当安全边界。

实现及隔离验收详见 `REVIEW-20261016-AgentScope-autonomous-policy-context.md`；默认资料选择合同由同日 RFC 接续前一日手工选择方案。
