# Broker 执行保活与价值主张的取舍

状态：采纳。关联 RFC：RFC-20261012-execution-independence-value-evidence.md。

1. **取消控制台健康驱动的执行心跳。** 控制台离线且真实保护完整时，已批准任务继续；实际保护无法核验或 Broker 失联仍失败关闭。维持原行为会把正常发布变成全体任务终止；无条件离线继续则会掩盖保护失效，均不采纳。
2. **在已有 root Broker 签发工具准入。** 复用当前 gateway/token/批准规则，不新增独立权限服务器。代价是 Broker 的可信代码增加；以严格字段、精确代次、冻结规则、短期核验、容量限制、落盘先行及失败关闭约束。
3. **持久结果、暂不自动排队审批。** 结果属于已授权操作的事实；申请属于尚未授予的权限。控制台恢复后重试申请，不能把网络重试解释为自动批准。
4. **回执去重与执行去重分开。** 控制台收件凭据防止重复投影，Broker 调用墓碑防止重复执行。ACK 释放待发队列，不解除该代调用身份。Broker 重启不复活旧授权。
5. **读模型保持有界。** 总览 SQL 计数不逐条重新验证历史执行上下文；实际应用仍做新鲜目标、批准、编译、加载和域核验。总览数量是目录统计，不是可应用性证明。
6. **价值使用分级证据。** 确定性执行载荷用于测效果和内核强制；真实 DSH 用于检查 Agent 工作链；论文提供机制和外部实验背景。三个层次不能互换。传统沙箱同样有效的场景明确承认；只在来源相关的新连接对照中主张本轮观察到的增量，不作“首个 OS 安全”宣传。
7. **先升级执行面，再允许正常后续 API 发布。** Broker 本身升级需要一次受控实例换代；本轮必须记录旧/新代次和策略一致性。后续 API 更新可保留已有代次。不能从旧快照恢复权限，也不能自动重启历史上曾运行的全部 Agent。

未采纳：以提高 API 心跳宽限时间替代架构修复；给模型追加专门“不要绕过”提示词以掩盖能力缺口；把 connect 拒绝扩展成全部 send 覆盖；把进程启动当作可信测试成功；把共享 executor 的时间窗口当作精确会话归因。
