# 独立共享限制与明确确认

更新：界面与用户策略编排采用 [DSL 文档决策](ADR-20261010-actplane-dsl-sessions.md)。本文的旧权限格式继续用于底层挂载／工具准入兼容，不能替代用户 ActPlane DSL。

日期：2026-10-10。状态：采纳。替代 ADR-20261009-security-config-scopes 的系统页只读说明决定。

用户指出旧系统页实际是功能设计说明，不是可配置规则。采用独立持久化的共同限制，以及独立的 Agent 本层配置；复用现有有效策略与执行器加载合同，避免复制多份共享规则后无法判断来源和删除范围。

共享层只限制，不授予新的文件/工具权限。两层合并保留所有禁止，disabled 网络优先；授权由 Agent 本层管理。这样 Agent 删除自己的规则不能取消系统限制，文件规则不跨资源隐式授权。代价是系统页不能直接配置 allow，需要到当前 Agent 中授权。

系统变更一律显式确认，冻结受影响连接、资源、代次与 hash；不沿用单实例收紧自动应用，以免一次操作静默重建多个 Agent。先停止全部受影响执行器，再提交有效策略及重建原在线连接。任一失败保持 blocked；不将配置保存视为加载成功。

维持单控制 API 写入者，SQLite 原子租约准入。分布式/多 worker 生命周期协调、独立单次工具审批，以及未接管进程的保护均不在当前实现中。
