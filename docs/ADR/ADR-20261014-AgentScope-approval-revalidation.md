# ADR：失效审批创建新候选，保留版本与批准证据

日期：2026-10-14。状态：采纳。

1. 不把旧审批改回 pending，也不放宽配置库版本检查。相同正文的历史 v1/v2 仍是不同版本；已保存的审计事实不能被界面恢复动作改写。
2. 采用“只读预览→显式重新校验→新待审批→独立批准→显式应用”。预览选择当前源配置，清楚展示和旧候选的差异；用户可返回所属配置编辑。重新校验只调用现有编译/提案服务，不获得执行权限。
3. 不以旧候选全量覆盖当前生效文档。配置库候选合并明确选择；手工 DSL 使用可证明旧基线的差量合并。无法证明、冲突或原目标已移除时停止自动合并。
4. 预留恢复请求和新候选的持久关联；未完成关联的恢复候选在统一审批与旧 DSL 应用接口均拒绝，保证中断重试不成为审批捷径。记录保留并可回原请求恢复。
5. 保留能力边界：旧生成上下文需重读，局部执行不支持时返回精确页面，失败应用暂停不自动解除。代价是这些记录不能用一次重新校验强行变为可应用。

对应 RFC：RFC-20261014-AgentScope-approval-revalidation.md。原生模型任务反馈和业务语义不在本次验收范围。
