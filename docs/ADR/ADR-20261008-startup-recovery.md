# ADR：保留失败快照，通过显式关联恢复启动生成

状态：采纳，2026-10-08；代码与本轮验收完成。

旧任务的固定路径和上下文属于证据合同。原路径已不适配执行引擎 64 UTF-8 字节上限时，修改原 context、放宽编译器限制或把其他任务 DSL 复制回旧记录都会破坏关联。因此保留失败快照，在新快照生成候选，并保存显式恢复关联。

候选复用必须验证文件 manifest、真实目标、全部已接受约束与平台底线及实例身份代次；不按目录猜测。实际同源复验任务 ad7c53a17c334c7b 因 accepted_task_constraints 不同而未被关联；从原任务可信上下文重建的 4ca8082805f74c6c 完整继承了 5 条约束。这说明复用检查不能仅比较提示文本或仓库 hash。

每个原任务只维护一个可恢复目标，重复与并发采用持久 CAS；重试初始化和入队不再次创建子任务。源变化须重新读取场景，不能暗中修改约束或重新消费一次性采用回执。

采用生产落库合同核验：候选正文和验证摘要分开存储，正文 hash 与摘要 proposal_hash 必须相符。测试必须经真实工具 validate/submit 落库；禁止依赖人工构造的重复正文来代替接口验收。

UI 保留用户认可的原工作台记录与抽屉模式，移除整页嵌套造成的重复列表。无路径任务指导显示真实语句短摘要，长内容放详情。恢复不自动批准或执行，既有运行中恢复仍使用原执行器流程。

本轮未引入 Hook 模块或修改其独立开发分支，避免未验收功能进入本次恢复发布。
