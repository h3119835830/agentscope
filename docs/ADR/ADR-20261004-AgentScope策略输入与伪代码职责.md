# ADR：策略原句输入、伪代码展示与 DSL 执行职责

日期：2026-10-04。状态：采纳。

采用“原句 + 经核验上下文 → 结构化候选 → 确定性伪代码展示 + DSL 候选 → 编译 / 审批 / 加载”。无需手写伪代码作为输入；伪代码不被 ActPlane 执行。可执行 DSL 仍由已有独立模型转换器生成并编译审核，不将自然语言直接当作内核规则。

原句可以只登记和保留指导项。OS 无法判断的语义或内容要求保留空 DSL；文件路径、事件或范围不明时保留 requires_context / unresolved。普通文档抽取仍要求原证据和双语内容；显式手工及 RQ1 原句输入不以额外译文作为审核前置条件。

RQ1 原句目录与不可变转换语句分离。目录的“通过”不替代确切语句内容 hash 审批。目录预览通过结构化元数据渲染，不写入可加载产物库，effect=none。准备转换时重新核验固定来源，重复相同输入复用版本，不继承旧目录审批。

操作对象从通用 target_paths 输入核验为 verified_targets；相对路径和具体类型进入模型上下文。平台执行能力单独作为结构化合同，包含进程域继承与 OS 事件覆盖。这修复的是输入和运行时能力上下文，原翻译提示词未增加测试场景专用规则。

采集与审计作为独立二级模块；沿用现有持久化作业与审计表，新增分页公开投影，不重复建表。原 721 条状态、第二层已验收记录、普通业务代码均保持隔离。
