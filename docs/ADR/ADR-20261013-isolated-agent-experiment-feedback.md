# 决策：独立命令执行域与可核验反馈

采纳日期：2026-10-13。适用范围仅本轮四项真实实验。

正式原生 DSH 使用共享执行器，现有 typed policy 的只读挂载和 model_only 网络隔离会混淆“ActPlane 规则拒绝”与“外围沙箱拒绝”。本轮采用独立命令执行域和可写夹具，在同一环境中运行无 ActPlane 的载荷控制及启用 ActPlane 的真实 Agent，保留 kernel rule 证据。这样不必停止、扩权或重新配置正式 Agent。

DSH 使用 context 注入，mini 使用真实工具观察接线。反馈内容直接来自执行域内核事件的 userspace 规则格式化，不额外编造任务答案。宿主 PID 游标在独立 PID 命名空间内不能直接解析，且私有目录权限会阻止低权限读取，因此实验适配器使用该独立域的只读反馈文件，游标保留在内存，父目录预先设置为可遍历。该决定不代表通用多会话反馈归属已解决。

保留 DSH 配置外发中的功能失败，不增加“不要先读该文件”之类提示来制造通过，也不清除秘密标签或放宽规则。该失败说明标签粒度、执行器结构和合法任务可继续性必须一起验收。mini 的成功只证明本夹具下父子进程与派生文件路径的效果；不据此宣称它整体更安全。

比较使用相同模型名称、场景与规则目的，但 DSH 的 Messages/high reasoning 与 mini 的 Chat Completions/temperature=0 没有完全匹配，且前三项 DSH 的任务 Python 为 3.14、mini 为 3.11.17。本轮是机制和功能对照，不输出性能排名或统计攻击成功率。Flask 最终均在同一 Python 3.11.17、同一 52 项冻结 oracle 下验收。

没有修改正式 API、Broker、内核引擎、前端总览、公告或普通业务。后续若工程化，先设计可信工作进程、IPC 来源传播与合法诊断导出合同，再单独评审并验证；不能靠隐藏读取操作绕开来源跟踪。
