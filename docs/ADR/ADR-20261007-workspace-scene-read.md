# ADR：先识别工作区任务，再采用与生成策略

状态：采纳，已实现并验收。

问题：当前入口把任务名称和目标都设为必填，阻止 Agent 读取已经包含明确任务说明的场景；名称只是标签，不应成为冷启动的前置语义要求。

决定：新增独立异步只读 Pi 作业。使用固定版本 Pi、隔离运行目录、无内置工具和三个作业绑定工具，让模型读取来源后提交精确引用的任务草稿。没有目标时如实澄清；补充目标作为明确用户来源创建新作业。保留既有显式目标接口作为既有调用方合同，前端主流程采用已读草稿。

确认采用与策略确认分开。采用操作原子建立 task/context/source/read 关联，生成策略仍使用现有启动前 Pi 与人工确认。读取失败不创建任务、不启动 DSH、不编译或加载权限策略。过期源、代次与 hash 阻止采用。

取舍：比文件名启发式多一次模型调用，换取实际语义判断和来源证据；读取快照占用有界服务存储，换取后续可复核性。已读片段引用校验保证来源真实性，不替代模型语义评审或用户确认。权限范围仍由现有可信控制面和 Broker/ActPlane 决定。
