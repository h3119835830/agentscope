# ADR：将生成历史与配置、审批解耦

日期：2026-10-11。状态：已采纳并完成源码/隔离预览验收；共享环境未发布。

旧系统“生成记录”把 `HistoryLibrary` 整体嵌入产品页，重复提供生成、历史策略审核和诊断详情；同时 DSL 配置按原始 pending 状态展示，审批中心按动态基线判断失效，容易造成权限流程误解。

采用独立产品历史读取投影和只读组件。生成历史只描述保存结果；候选产生和参数补充留在 Agent 策略助手/DSL 配置，授权决策留在统一审批对象。详情直接读取保存记录，不复用包含实时资格验证的 `generations.results`，避免历史展示依赖在线 Agent、Broker 或当前工作区。客户只看到需求、匹配、处置和历史目标，技术诊断继续保存在独立研究/运维接口及验收资料中。

DSL 草案复用审批投影，应用判断保持服务端权威。编辑器不再调用旧 confirm 接口；显式“前往审批”只导航。重新校验产生新候选后切换追踪对象，防止旧失效状态遮住新结果；批准或拒绝后继续读取该对象的最新状态。系统配置库复用现有审批详情组件与统一决策接口，保留新增配置版本功能。

没有删除旧研究组件/API，也没有只用 CSS 隐藏诊断。前者会破坏既有研究与取证能力；后者会保留旧操作入口和原始数据依赖。取舍是增加一个小型白名单读取层，并让产品导航彻底脱离旧组件。产品历史 GET 的返回字段已收敛，外部研究调用者应继续使用原始 `/api/history/...` 接口。

旧链接统一进入只读历史；界面收敛不能作为权限迁移、共享环境发布或新增内核效果的证明。正式发布必须使用包含第一步审批和本次产品投影的同一版本，不能只替换前端。
