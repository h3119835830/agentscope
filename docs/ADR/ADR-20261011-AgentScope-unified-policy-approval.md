# ADR：统一审批投影与人工授权，复用权威加载器

> 2026-10-26 部分取代：本 ADR 对系统/Agent/扩权治理仍有效；受管 DSH 运行时收紧已改为“认证用户请求 + 只追加候选 + 控制面自动加载和效果验证”，不再 pending 人工审批。

日期：2026-10-11。状态：本地采纳并验收，未发布。

## 背景

实例策略把 restrict 分类直接作为自动应用依据，Agent 工具提交还会异步替换自己的执行器。审批中心原先只有 DSL 提案，受管任务的 restrict/expand 候选虽需人工 review，却不在同一目录。使用者难以从一个入口核对完整待审范围。

## 决策

1. 类型化实例策略一律先 pending，删除 user/agent 的自动收紧应用分支。restrict/expand 不携带批准权限。
2. 统一 `PolicyApproval/1` 与管理员决策路由；保留既有候选 id、权威存储与加载器。来源和作用范围独立表达。
3. 人工确认绑定候选哈希与冻结目标/基线。缺失历史快照或环境漂移时关闭批准能力，要求重新生成。
4. 提交时保存类型化策略的修改前快照，历史审批对照不依赖应用后的当前配置。
5. 运行时成功状态来自精确匹配的应用回执，不改写 completed 作业状态来制造另一套审批状态机。
6. 本次验收隔离于共享 18003；特权 IO 使用测试替身，内核效果单独验收。

## 取舍

统一合同可以逐步替换客户入口，并保持各加载器的锁、编译、目标绑定和恢复机制。代价是审批投影需要适配不同来源，暂未迁移为单一候选数据库。

未采用“一次性重写所有加载器”方案：第一步应先消除自动变更权限和审批遗漏，重写会扩大运行时风险。未采用“旧候选缺字段时读取当前环境补齐”方案：它会把已变化的执行对象误当成原审批依据。

人工收紧会增加一次确认，但用户明确要求控制所有权限应用。控制门暂停与权限包变更继续分别记录；拒绝提案不能静默撤回用户原有安全要求。

## 后果与验证

旧无快照候选需重新提交；旧确认接口保留兼容但不赋予 Agent 审批能力。已确认权限、停止状态与未运行实例不会被查看或拒绝动作改变。
