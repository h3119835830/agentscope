# ADR：统一配置目录，目标由子配置决定

日期：2026-10-15。状态：采纳为设计，应用代码及迁移未实施。

采用同一个策略库管理静态模板及版本化子配置；系统 / Agent 不再对应两套可独立写入的配置库。适用范围作为子配置参数，所有受控 Agent 对应系统基线，指定 Agent 对应精确实例；期限与来源另存。模板允许范围仍受权限及执行能力限制，不通过界面单选扩大权限。

放弃仅改页签名或按模板名合并的做法：不同匹配方式、效果及访问组可能不等价。迁移必须保留旧 ID / 审批 / 生效记录并确定单一权威写入口，兼容 API 委托该入口。

采用 Jev 作为可替换的有界模板推荐器，配置 Agent 负责按 Schema 填参和草案工具调用。None / 低置信度 / 超时走澄清或手工；多需求按原子判断组合。Jev 不替代确定性权限检查、人工批准、Broker 加载或内核执行。模型版本和阈值需校准后固定，中文场景独立评测。

保留系统 / Agent 两种真实目标与同域共享执行约束；界面合并不等于把各 Agent 的进程域合并。当前生效快照与草案分离，停用也经独立审批与回执。

理由、接口及实施验收见 [RFC](../RFC/RFC-20261015-AgentScope-unified-policy-catalog.md)。历史[工作台决策](ADR-20261014-AgentScope-template-agent-security-workbench.md)保持，本文更新“系统策略 / 策略与模板”的导航组织，不恢复四个固定策略层。

界面细化：子配置行采用“实际策略名称 / 范围 / 详情”。名称来自具体场景约束，来源与模板名分开保存；范围只呈现所有或具体 Agent。详情与模板新增配置共用参数表单并回填实际值，不维护第二套详情字段。应用元数据在详情渐进展示，原有审批与版本边界保持。

最新用户取舍：撤回系统中的助手快捷入口和前轮原型作为正式视觉基准；采用现有系统策略页作最小改造，Agent 页负责助手配置。合并目录、子配置范围及统一审批合同保留。主路径继续批准与显式应用分离，旧组合确认入口需收口，不能把保存或生成视为加载授权。
