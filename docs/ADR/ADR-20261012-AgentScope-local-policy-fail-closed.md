# ADR：局部目标必须精确绑定，能力不足禁止应用

日期：2026-10-12。决策状态：本轮已实现目标与禁止应用；局部原生加载器待实现。

## 决策

采用四层产品目标：系统、Agent、工作区、会话。服务端根据生成流程固定默认目标，仓库场景为工作区，运行时为来源会话。材料路径限制与执行主体绑定独立表达，不以 PID、cwd、可执行文件或对象目录推断会话隔离。

原生局部绑定不支持时，保存独立 `local_policy_proposals` 审批记录，展示阻塞原因，禁止确认和实例级加载回退。收紧、扩权均没有免审批或自动生效例外。人工系统／Agent 配置继续使用已有独立合同。

审批归档展示与完整执行核验分离。没有可执行转换的 blocked 记录只展示冻结目标与内容；生成提交保留完整上下文核验，所有确认路径仍拒绝。本轮实际发现逐记录重验使审批列表超过页面读取上限，故采用此分离，不通过延长超时掩盖问题。

## 取舍

代价是工作区／会话候选暂时只能审查和拒绝；生成成功不代表可加载。收益是无法将共享原生执行器错误表述成独立会话，也不能把局部申请静默扩大到整个 Agent。未来启用局部加载必须新增可信 binding、父域与生命周期核验、明确加载回执及内核隔离验收；不能只把 capability 标记改为 true。

废弃生成候选默认导入 Agent DSL 的行为；阻止旧实例级运行时工具在缺少会话目标时提交全实例提案。历史已应用 Agent 策略保留真实范围，不能事后改名为会话策略。
