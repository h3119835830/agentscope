# 复用 DSL 提案建立客户审批入口

日期：2026-10-11；状态：采纳。

问题：助手候选重复整段需求、策略选择是小型原生菜单、校验草案需回到 DSL 编辑器才能处理；侧栏没有独立审批入口，客户难以查看或确认应用。

决策：用紧凑候选卡片、可搜索策略记录表与分组详情承载阅读；审批页作为现有 DSL proposal/confirm 状态机的产品投影。应用继续由用户明确操作；拒绝只关闭提案并审计，不修改当前生效策略。现有 DSL 编辑器打开已校验草案时恢复校验预览，仍要求显式确认。

取舍：新增产品读取投影和无运行副作用的拒绝接口，不创建并行审批状态机，不把生成完成当成批准。提交可能进行编译校验，但不启停受控 Agent；批准应用仍可能重新加载受影响 Agent，界面明确提示。只对当前真实提案量验收，未声称大规模历史分页或性能验收。

替代方案：继续要求客户跳转 DSL 编辑器，无法解决审批发现性；自动批准生成策略会越过用户确认边界，未采纳。

## 审批对象定位补充（采纳）

沿用已确认的产品名称与实时进程展示约定，将审批定位作为既有提案的只读投影，不修改登记名称或冻结确认快照。生成来源由不可变生成证据和精确 Agent/session 主键关联；旧模板未记录会话时明确缺失。拒绝按当前选中会话、相似名称或 PID 自动补关联，因为重启后 PID 会改变，同名 Agent 与共享解释器并不证明会话归属。

列表并列显示当前 Agent/PID 与生成会话，详情分别标注提交/生成时 PID。来源定位不改变 Agent 级策略的应用范围。复用系统策略库的新校验、完整影响目标与应用回执投影，不以本轮 UI 修改回退最新已发布系统功能。
