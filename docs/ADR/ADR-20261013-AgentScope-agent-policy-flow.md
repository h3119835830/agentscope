# 采用版本化草案和批准/应用分离（2026-10-13）

状态：采纳，仅本地实现与独立实验环境。取代当前控制台“批准并应用”的单一步骤；旧管理员接口继续兼容，不改写历史事实。

长期基线以实例为所有者，生成环境以可信登记资源和受控执行来源为依据；会话只用于局部证据，不能暗中决定实例策略范围。工作区和会话执行能力不足时保持审查可用、应用禁用。

草案输入追加版本，引用的材料/场景/产物与输入摘要共同冻结。批准形成不可变依据和前配置证据；应用消费准确回执。配置范围的一份待应用版本由数据库唯一约束强制保证，不能依赖页面按钮或模型自觉。

继续复用原控制器和加载器，以避免重写安全域、门控和失败处理。两阶段持久化无法与内核操作组成数据库事务，因此中断记录保持不可自动重试；API 启动先恢复暂停，暂停未核验时拒绝声称完成。既有配置直到显式应用才改变；历史已应用但无批准回执的记录保留证据缺失状态。

代价是增加草案版本和决定/应用请求表，以及一次用户应用确认。它换取清晰的授权时点、并发冲突、可追溯材料、准确范围和运行回执。当前仍不提供原生会话独立内核域，不能因为页面区分四种范围就宣称四层执行隔离已实现。

独立来源观察采用可配置缓存路径，保留 root 所有权、时效及六项身份核验。源动作 schema 补齐 truncate，仍由已有 mutation 组执行；不以提示词修补代替合同修复。会话命中必须有可信关联，Agent 运行域的未归因内核事件只作为独立证据。
