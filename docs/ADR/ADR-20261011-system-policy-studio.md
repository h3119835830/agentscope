# ADR：系统与 Agent 策略层级、配置表达与预览边界

日期：2026-10-11。状态：采纳，系统应用流程尚待生产集成。

1. **系统目标固定全体受控 Agent。** 用户明确确认，系统勾选后人工统一载入根层。弃用系统策略选择单个 Agent 的设计；具体 Agent 的追加配置放在下一层。
2. **库内保存与运行应用分离。** 保存草案不触发执行器变更。取消勾选不删除生效规则。代价是需要独立预览、确认与逐目标回执，但避免误把编辑当成授权。
3. **选择匹配语义，不要求手写 glob。** 后缀 `.env`、同名文件 `.env` 与实际路径分开。DSL 可读且保留条件，避免路径通配符被误解。
4. **动作是 block / notify / kill 的明确选择。** 反馈消息独立；不将 notify 显示为阻断，也不将 kill 描述成无副作用的更强 block。
5. **候选数量由适用安全约束扩展。** RQ1 仅提供候选依据；平台边界与 ActPlane 信息流扩展单独注明。项目测试、提交与生成器流程不强行变为全局策略。
6. **只读编译不替代运行能力验证。** 文件后缀在当前编译器可表达，在当前受控 profile 暂不可加载。展示限制，保留配置；不扩大到所有文件或改用不等价 contains 规避限制。
7. **先交付可操作 UI 预览。** 独立工作树、18141 端口，不覆盖其他并行编辑，不部署或改变实际安全策略。代价是尚不能直接投入生产；集成合同在 RFC 中明确。
