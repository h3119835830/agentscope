# ADR：先核查原生启动拓扑，再设计多 Agent 适配

- 日期：2026-10-14
- 状态：采纳设计约束；实现方式待后续评审，未部署。
- 关联：[RFC](../RFC/RFC-20261014-AgentScope-agent-launch-adapter-research.md)、[REVIEW](../REVIEW/REVIEW-20261014-AgentScope-agent-launch-adapter-research.md)、[BUG](../BUG/BUG-20261014-AgentScope-agent-launch-adapter-research.md)。

## 背景

用户明确要求不改 DSH，先研究各 Agent 的启动方式，主要改造 AgentScope 并适配多个 Agent。此前提出每会话独立工具进程，只验证了最小工具组合能启动；没有证明原生上下文、工具输出、子 Agent、MCP、后台任务和会话历史全部保持原义。该方案不应在原生执行拓扑尚未核查时直接成为默认架构。

## 决定

1. 撤回本轮未发布的独立工具进程草稿，隔离服务停止，保留私有草稿供追溯；不提交/发布这些应用代码。
2. 保留四层策略归属，但独立建模实际执行单元和共享性。会话 ID、cwd、产品名、启动器 PID 均不能独立授予局部执行权限。
3. AgentScope 将启动/打开、原生身份/协议、能力探测、执行绑定、审批/执行分为清晰合同。适配器按真实能力暴露功能，不把 DSH 逻辑写成通用 Agent 假设。
4. 不修改原生安装源码、提示词、工作区/会话交互、工具实现；本研究阶段不新增 profile 插件或覆盖原生 sandboxPolicy。现有 AgentScope 的 profile 注入和 sandboxPolicy 覆盖是已存在的耦合，另列整改，不能静默删除导致现有保护失效。
5. 优先复用已有原生入口与公开扩展/协议能力。原生扩展存在不表示已经获准修改运行配置；新的配置行为必须作为后续具体设计明确展示。
6. 共享进程可保留。没有可信局部边界的入口不得显示工作区/会话已强制执行，也不得把局部规则自动变为整个 Agent 的规则。

## 评估过的选项

| 选项 | 结论 | 取舍 |
|---|---|---|
| 固定每会话新建工具执行器 | 不作为默认方案，草稿撤回 | 需复制/代理工具语义和上下文，易与 Agent 原生行为漂移；多产品通用性不足 |
| 根据 sessionId/cwd 切换共享 PID 策略域 | 不采纳为隔离证明 | 并发异步任务、线程池、后台子进程与旧句柄无法由这些参数自动区分 |
| 仅接一个启动命令和网页地址 | 可以做启动功能，但不足以完成局部安全管控 | 缺原生身份、取消、策略能力和可信执行归属 |
| SDK/ACP 替代原生 Web 并声称透明 | 不采纳此推断 | 协议会话仍可共享进程；既有 Web 会话/历史兼容未验证 |
| 通用启动监督 + 产品适配器 + 能力和绑定校验 | 采纳为设计方向 | 先形成各入口的真实拓扑，再决定是否使用其原生 worker、沙箱或独立实例 |

## 验证与后果

本轮是研究验收：安装包/源码锚点和 launcher help 已检查，应用代码已恢复基线，隔离服务停止。没有四层运行验收或协议互通结论。后续实现需满足 RFC 中 A1/A2/B1/另一个 Agent 的负向控制和原生流程保持要求；不能以界面和编译测试代替 OS 拦截事实。


## 补充决策：执行单元是多 Agent 接入的共同抽象

采纳 Connection、NativeSubject、PolicyDocument、ExecutionUnit、PolicyBinding 的结构化分工。四层是规则归属/继承，ActPlane domain 是实际执行边界，二者不强制一一对应。

对当前 ActPlane 接入，同一个执行域中的多个逻辑会话共享已加载的内核策略包。若所需权限不同而边界相同，默认拒绝局部应用；不得以最严格规则合并代替范围正确性，不得以宽松合并损失保护，也不得强制修改原生 Agent。是否复用原生独立边界或会话授权接口，按适配器能力另行验证。

此为研究设计约束，未改变应用代码或现有运行策略。
