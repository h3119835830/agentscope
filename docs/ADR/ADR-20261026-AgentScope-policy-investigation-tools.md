# ADR：调查、填参与验证分离，复用原生 Pi 工具循环

日期：2026-10-26。状态：采纳，隔离验收通过，未正式部署。

## 决策
1. 同一模板库同时服务人工和 Agent；根据现有参数类型生成工具 JSON Schema，保留数组、整数、枚举和参数帮助，不复制另一套模板语义。
2. 调查沿用固定 UID 的 fd-anchored reader 与现有策略守卫。不为搜索引入 shell、任意路径读取、正则执行或生产业务接口。
3. 使用真实 ActPlane 编译产物与共享 C 匹配谓词，不另写 Python glob 模拟器，不修改 ActPlane 核心。新增纯匹配二进制为控制面验证组件，不含 BPF 加载能力。
4. 参数校验与覆盖验证分别返回。保留既有 validated 字段的格式兼容性，但明确其仅为 template_parameters_only；Native Pi 完成提交还必须核验对应候选的预览结果。
5. 不加入场景名、特殊路径或按失败案例定制的系统提示词；不自动拼接递归后缀。模型依据通用工具语义和实际反馈自行改参。
6. 保持已有人工审批和显式应用流程；现有策略、模板版本和历史候选不静默改写。
7. 调查资料负责提供线索，不直接建立外部逻辑 ID 到本地路径的权威映射。不存在的目标需明确操作者路径，不能靠预览假设样本“证实存在”。
8. 将已验证正向样本保留为本轮工作状态，最终集合遗漏时反馈真实差异，供 Agent 自行恢复完整候选；不手工补齐模型结果。

## 取舍
真实编译/匹配需要部署编译器及与其 ABI 相配的预览组件；缺失或 ABI 漂移时不能声称验证通过。样本测试不是形式化自然语言证明，条件化规则仍须运行层独立验收。调查预算扩大但受控、截断可见；不以穷尽扫描服务器作为智能程度的判据。
