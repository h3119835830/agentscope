# 会话安全配置入口方案决策记录

日期：2026-10-14。状态：第一阶段统一界面、只读安全视图及所属层配置候选方案已实施，真实隔离与 18003 发布验收通过。独立原生会话执行仍为后续能力。

提议将现有会话入口升级为统一安全工作台，聚合当前约束、配置候选与检查结果，保留系统和 Agent 的权威配置所有者及既有审批/加载链。DSL 作为其中一种执行表达，通用约束使用机制适配和明确状态展示。

这样可复用现有会话目录和精确实例/会话身份，降低用户在系统、Agent、审批和会话之间反复跳转的负担。代价是需要统一只读视图和语义可无损映射的结构化编辑器；复杂 DSL 继续使用高级编辑。另建独立 DSL 管理模块会保留现有会话视角的断点，因此当前方案优先升级会话模块。

会话视图不能新增第二套授权事实，不能凭 UI 开关绕过批准或加载核验。工作区和会话独立应用继续以可信执行绑定为前提；初始可交互演示不修改真实配置。本次实际实现仅通过已有权威控制器提交所属层候选，经独立批准和应用后才变更配置。

完整合同和验收见 [RFC](../RFC/RFC-20261014-AgentScope-session-security-workbench.md)。

第一阶段复用结构化策略、DSL、系统和实例控制器，不重写 Broker 或普通业务接口。增加的请求元数据仅关联会话来源、审批和幂等返回，不建立第二套授权库。结构化规则在面板内编辑和停用，复杂 DSL 保留高级编辑并按完整文档停用。原生会话暂不支持的局部能力显式禁用，不以共享执行器模拟隔离。

目录折叠采用浏览器本地布局偏好，复用原目录组件并保留所选会话与已有数据，不新增服务端状态或接口。展开/收起按钮提供 aria-expanded、aria-controls 和键盘操作；收起后主面板释放空间，窄屏不保留竖向轨道。
