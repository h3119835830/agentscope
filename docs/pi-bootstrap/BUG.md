# BUG：Pi 候选提交与独立探针环境

日期：2026-10-03。范围：隔离验收实例，未修改普通业务或 ActPlane 内核。

## Pi 校验/提交状态不一致

复现：配置场景作业 4d7a0398e7a144c9b6341e1363da8a6d 首次引用无效证据 ID，随后把语义指导误放执行缺口；校验返回 valid=false 但 diagnostic 为空。再次提交的指导/缺口内容变化，没有对应完全相同的有效校验记录；作业以“没有有效已提交候选”失败，未批准、未加载。

整改：证据字段描述要求真实登记 ID；校验指出无效 ID 和阻塞缺口；Draft 合同区分必要执行缺口与语义指导。有效校验结果不可变保存，提交只引用本作业候选 hash。没有加入针对某一场景的特殊修复提示词。

验收：后续真实 Pi 作业 dd0cb7aaf28941db960d9c21fff97659 在 16 次工具调用内完成配置历史参数化、新规则、编译和 hash 提交。接口测试覆盖内容变化后的审批/加载拒绝、跨任务凭据、预算、中断与撤销。

## 独立探针父域与文件权限

复现：将含 workspace 全路径边界的批准 YAML 直接用作 run 父域，控制器创建 cleanup handle 得到 EPERM；此错误来自探针启动方式，不能算目标文件已被保护。后续初始资产克隆目录只读于探针用户，合法缓存删除/临时写入失败，虽违规操作被拒绝，仍判验收失败。

整改：父域仅预留 hooks，批准完整 DSL 加载到子域；独立物理目录映射到同一批准路径。克隆目录使用任务组可写权限；每次尝试使用新目录，避免事件和文件状态混淆。

验收：配置场景合法读、缓存清理和临时文件写删全部成功；直接和间接写入、删除、改名都有关联的真实 bootstrap 规则事件，保护文件 hash 保持不变。原失败记录保留在验收过程，不计入成功探针数。

## 测试资产初始布局与评测误判

复现：固定上游资产使用 transaction-service 目录和 tests/tests_rate_limiter.py，原任务的 import 与评测器则期望 transaction_service 和 tests/test_rate_limiter.py。任务 2271865a5f2448df 在测试 hash 未改变时得到原始 unsafe=true；检查初始库存即存在预期文件缺失与额外文件，不能归因于 Agent 破坏。配对运行 584af4d0a0944018 停止并一同归档，不计正式验收。

整改：导入层显式映射上述路径，原资产内容与原提示不改；保存原路径、映射和 hash。独立评测增加初始预期文件与 hash 检查，自动入口在布局不合格或初始原评分 unsafe 时停止。此修改修复场景上下文，不增加针对 Agent 的补救提示词。

验证：测试模块核验 16 个原评测预期文件均初始存在、三个测试文件保护集非空、初始 unsafe=false；去掉一个预期测试文件即不通过初始门禁。

探针运行时还发现默认 Python 缺少 toml，导入失败不能证明合法执行。探针使用单独 venv 固定 toml 0.10.2，并核验实际测试用例数及没有 _FailedTest 导入错误。任务修复成功与测试文件安全仍分别报告。

测试保护场景、语义场景与最终回归状态见同日 REVIEW。

## 当前任务必要约束被历史候选替代

复现：作业 e6380a02fb1449a3a4963863103dca23 读过完整任务原文和测试资产，却只提交配置文件的历史参数化规则，遗漏明确的测试不可修改要求。原校验只验证引用、路径、IR/DSL 和编译，没有检查任务合同覆盖；测试文件 hash 未变不能证明遗漏的保护有效。94b96c372f884e63 之前的配对 c6806a052b25477e 与 2423e5b44178409e 归为诊断，后者停止并清理。原自动审批入口缺少预期保护范围复核，已整改。

整改：导入层将原任务/平台明确要求登记为带来源原句、来源 hash 和操作对象的任务合同；get_task_context 返回原任务描述，核心证据读取作为校验前提。确定性覆盖门禁独立于历史排名，缺少约束只能修订或提交待澄清，不得生成加载包。验收入口在审批前核对测试保护新候选和语义 no-op 条件。没有加入“这个场景要生成某条规则”的专门补救提示词。

覆盖回归：配置历史规则不能替代当前测试保护要求；没有对应原子规则时校验明确拒绝。目录根与后代均需覆盖，避免目录整体改名逃逸。正式成功运行见 REVIEW。

## 历史参数化超出已审对象范围

复现：最终配置任务 0ff489a193e34f08 的第一份候选将配置保护模板同时绑定 shell/Git 配置和 main.py，虽然 mutation 操作一致，源码不属于该历史模板的配置资产选择器。原校验只检查操作子集，缺少对象类型边界。

整改：根据已审 protected_paths 选择器检查资产类型及目录下所有登记资产；不同类型需新候选。保持历史内容、审批 hash、通用 Pi 合同及工作流版本不变。重新生成得到配置规则复用与源码新候选，随后六次正式链路验收完成。

验收：接口回归以相同 hash 的配置模板绑定 main.py，确定性拒绝；正式配置 B 批准包的 18 次独立违规探针全部关联内核事件并保持文件不变。

## 完成任务的活动句柄残留

复现：早期任务完成后 Broker/watch 已退出，但数据库仍显示历史 active_pid/domain。整改为只有清理确认后才清空活动字段，部署回执保留原 PID/域以供审计；清理失败保留句柄便于追踪。回归覆盖成功及失败分支；隔离实例对实际进程已不存在的旧完成任务做状态保持的句柄对账。最终活动域、部署、残留正式进程和未撤销凭据均为 0。
