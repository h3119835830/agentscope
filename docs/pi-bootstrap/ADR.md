# ADR：Pi 结构化候选、受限工具与独立 RQ5 验收

日期：2026-10-03。状态：采纳。

1. Pi 采用一次性进程和受控 API 扩展。提供七个工具，不提供通用 shell/文件工具，不自动加载项目资源；bubblewrap 移除数据库和隐藏评测材料的文件可见性。代价是需要证据注册及专用工具合同，收益是权限和模型证据可审计。
2. 采用结构化 PolicyIR 确定性生成 DSL。首版只覆盖路径 mutation 拒绝；语义项保留指导，不为了展示“可执行”而伪造网络/文件规则。扩展其他操作需补能力合同和真实 hook 验收。
3. 全库 FTS5 召回后由 Pi 判断适用性。只使用 hash 审批的不可变历史版本，不将历史自然语言直接变成已执行规则。暂不引入向量库与自动策略晋升。
4. 校验阶段保存不可变候选，提交引用其 hash。废弃模型在提交时再次复制整份 Draft 的方式；保持校验结果与提交内容一致，减少上下文同步错误。
5. A/B 使用一份 Pi 判断，经确定性路径/证据重绑形成独立任务实例。保持基础配置、规范化提示及指导项一致；分支差异只为批准的任务执行规则。代价是每个实例仍需自己的上下文 hash、编译和审批。
6. 探针在新域和新初始资产上执行，映射到相同批准路径，复用同一完整 DSL 和 YAML hash。父域只预留 hooks，不把任务的全路径边界施加给控制器；此方式与 Broker 受管启动一致。
7. 使用独立测试库、数据库、Broker/profile/UI 快照和工作目录；单域串行。生产待审 RQ1 状态不被测试数据或测试审批修改。静态 UI 部署目录也隔离，原 API 未部署新模块时不出现对应控制入口。
8. 原始 evaluator 与完整性 oracle 分开保存，任务是否修复、退出状态、安全评分、内核效果和误阻断分开报告。测试任务不必成功修复才能验证保护约束，但未完成/超时不能被隐藏为成功执行。
9. 导入首版固定场景时，将任务/平台明确声明的操作对象登记为带来源原句及 hash 的任务合同。确定性校验保证登记约束的覆盖，补足仅验证语法与编译的缺口。代价是新场景需登记和评审；该输入规范化区别于论文中只读取原始描述的生成方式，不代表完成任意自然语言约束抽取。
10. 对必要但未解决的执行要求保存 needs_clarification 候选，允许正常结束生成作业，但禁止构建、审批和加载执行包。生成失败和待澄清分开；原有效批准版本不会被隐式修改。
11. 复用校验同时约束操作与参数选择器的对象类型。配置规则不能扩张保护源码或测试；不同对象形成当前任务新候选。该边界由已审模板合同与登记资产决定，不添加场景专用模型提示词。
12. 第三层交接只提供冻结输入、批准 hash、回执及基线。语义不安全评分保留为实际结果，不通过伪造执行规则或更改 evaluator 把第二层链路通过包装成语义安全通过。

实现与接口事实见 RFC-20261003-AgentScope-Pi启动前策略与RQ5扩展验收.md；验收见同日 REVIEW。
