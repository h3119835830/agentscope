# ADR — 文件 Scope Demo 的权限与恢复边界

日期：2026-10-05。状态：采纳。

1. 保留现有控制服务，增加 ScopeManager，复用 Pi 包和 Broker/ActPlane。使用独立数据库、profile、UI 和合成 Git 项目进行验收。
2. 使用完整不可变快照与基础版本绑定的候选。实际生效以探针及执行域回查为准；批准不等于生效。
3. Pi 输出受支持的结构化目录权限，服务器渲染规则。候选理由只作为公开审计内容；追加 DSL 使用固定说明，避免自由文本影响规则解析。
4. 收紧追加同域限制；扩权通过新策略包/新 DSH 执行域实现，保留 prior constraints 的 lineage 与公开检查点。首版不提供自动扩权。
5. 可信转发器与 DSH 分开运行。DSH/探针为低权限 UID，控制 socket root 0600，控制结果由 root 在受保护目录写入；文件事件 root 所有且不可由 Agent 修改。
6. 原生 DSH pre/post 工具事件负责工具边界与公开结果，内核独立负责文件拒绝。已开始的工具不冒充已被暂停，其开始版本单独记录。
7. 首版绑定 backend/frontend/tests/config/output 的登记场景，非通用目录策略平台。指导性要求不伪装成内核规则。
8. 出现已加载但未核验、或未知执行状态时停止执行并要求结束重建；不尝试以旧指针猜测实际规则或自动回滚追加限制。Broker 重启前关闭任务。
9. 原生插件、manifest、输入覆盖文件和凭据始终不可写。DSH 的生成根配置 cordis.yml 每次启动都重写，允许其必要写入而保护真正的代码与配置输入；不修改第三方 DSH 实现。
10. 本机用户通过受信任启动器一键进入：一次性短期票据兑换 HttpOnly 浏览器会话，无需输入管理员口令。人工审批身份仍与 DSH/Pi 分离；浏览器不持有管理员口令，任务/生成凭据与匿名请求不能签发票据，写操作限制为同源本机访问。

取舍：扩权重启存在恢复成本，但允许规则包重新构建并撤销旧凭据。公开检查点能续接实际进展，但不等于完整 DSH 原生会话回放。当前服务使用单例 ActPlane，因此真实验收任务串行运行。
