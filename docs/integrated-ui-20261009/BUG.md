# BUG：独立安全页缺少整体定位

日期：2026-10-09。

## UX-002：两页原型不能展示完整平台路径

复现：上一版独立原型只有“会话安全”和“平台安全底线”入口；与完整原型的总览、审批、策略库等模块分开，无法在同一壳层演示从全局连接到会话进程，再到对应约束的路径。

本次在新合并 HTML 中提供五项导航，将底线归入系统、约束归入会话，补齐全局连接图及节点跳转。审批复用提案记录，模板复用底线编辑器，避免重复配置。35/35 项交互与响应式验收通过；上一版原型仍保留用于对照。

未发现新增运行时问题，因为本轮未运行生产服务或实施安全规则。现有编译支持限制与已记录的内核保护缺口没有被本轮关闭。

## UX-003：Agent 节点虚构独立 PID，连接图使用范围过大

复现：首版进程树把主 Agent 标为 PID 210、测试子 Agent 标为 PID 220；总览也使用连接/服务图。此表达误导用户认为每个聊天会话或子 Agent 都独占 OS 进程。

代码核对：原生 SessionController 管理进程内 Agent；当前 DSH 有进程内子 Agent driver；Web 回复完成进入 idle，一次性 headless 才在保存后 exit。当前平台的 managed admission 使用 native SessionController。

修复：连接/服务改记录表。会话关系分为逻辑 Agent、真实进程形态样例、域继承意图；不再给进程内测试 Agent 分配 PID，宿主标明可共享。节点详情说明绑定未验证，生命周期说明区分 Web 与 headless。

验收证据：evidence/session-lifecycle/，旧 35 项结果保留为首版历史。此修复不证明真实会话隔离或进程退出行为；既有内核保护缺口未关闭。

## UX-004：节点缺少策略和会话身份，打开语义错误

复现：原节点详情主要显示对象类型及域，需再次跳转才能看到策略；主、子会话身份不足。草拟的“打开”在平台内增加聊天页，不能满足打开真实 Agent 原生会话的要求。

修复：三类关系增加共用数据的图/表切换；节点默认直接展示策略，元数据独立页签；共享宿主可选择关联会话。规则编辑只有一个入口。移除内嵌聊天与模拟恢复，将打开解耦为外部原生入口控制器，样例未绑定时禁用。

UI 验收：28/28 浏览器检查和 10/10 控制器模拟测试通过，见 REVIEW 及 `evidence/records-and-open/`。UI 语义修复已验收。

实际接入缺口仍开放：当前 DSH `open_url` 返回根路径，实例 API 无指定会话打开接口。需要原生客户端会话定位与恢复合同；不得用打开首页、新建 Session、虚构 URL 参数或样例状态更新代替真实验收。此缺口未因客户端模拟测试关闭。

## UX-005：首页打开被会话深链接条件阻止

用户确认打开对应 Agent 首页即可。旧客户端同时要求原生会话 ID、会话导航能力及 session 范围入口，错误拒绝现有的实例根入口。

修复：按钮改为“打开 Agent 首页”；控制器只要求实例 ID 和 instance 范围入口，移除会话导航前置条件；主、子会话按同一实例合并打开与启动。保留外部原生 UI、身份核验和启动许可。10/10 模拟控制器测试通过，界面证据见 `evidence/agent-home/`。

指定会话深链接作为可选后续能力，不再阻塞当前首页目标。当前样例未绑定真实实例、真实适配器尚未接入；带 Origin 的本机实例接口另有“管理员口令未配置”503，未绕过认证，未把上述模拟测试当作真实首页验收。
