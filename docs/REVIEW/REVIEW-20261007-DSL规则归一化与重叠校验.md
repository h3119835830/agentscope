## 设计评审

| 风险 | 设计约束 | 后续验收证据 |
|---|---|---|
| 同路径不同语义被合并 | 比较操作、效果、条件、例外、标签、权限和生命周期；首版限制规则种类 | 差异矩阵与不合并结果 |
| 运行时规则替代启动底线 | 底线身份与哈希独立封存，只建立引用 | 替代、撤销及伪造权限请求均失败 |
| 原始非法候选被优化隐藏 | 原始解析、能力和授权检查先于归一化 | 非法路径、未知条件、同名规则仍拒绝 |
| 规范化改变编译器路径语义 | 使用真实解析及降级字段，复杂模式标记 unknown | 实际编译结果及相邻合法路径探针 |
| 规则减少导致反馈或来源丢失 | 多对多来源映射，内核事件不重复计数 | 单事件多来源、不同原因与跨版本追溯 |
| 去重摘要被当作加载证明 | 包、来源、版本、PID 和域分别核验 | 过期候选、失活域、重启和加载失败测试 |
| 范围消冗余改变未来行为 | 首版只报告包含，不删除窄规则 | 广规则撤销或条件变化后窄规则仍在 |

## 验收口径

设计文档检查覆盖：论文原则与工程扩展分开；代码接入位置匹配现状；四类技术记录互相链接；实施及验收状态明确。文档交付不等于归一化功能已经上线。

实现验收需分开提交分析器正确性、编译等价、加载及进程域、真实 OS 结果、DSH 反馈与界面证据。首版只能宣称“受支持的简单等价条款去重”，不能宣称任意 DSL 语义去重。

正确拦截、误拦截、漏拦截、正确放行分别按冻结预期和实际效果判定；Agent 未尝试与探针结果分开。全部必要用例通过后才可启用执行包复用。

v5 对初始清理范围不明确的情况保留控制面暂停，通过公开任务消息澄清为只读报告；没有放宽底线。所有额外入场澄清单独记录。

启动竞态补充：v6 一次受管 root relay 在 Broker 登记精确 PID 前读取 task_runner.py，被本任务读取边界阻止。新增 root-only、一次性且有超时的启动握手：内联 bootstrap 不读取仓库代码，Broker 登记精确 PID 后才释放执行。例外不向 DSH 或后代继承。真实子进程测试覆盖释放前不执行、错误 nonce 和符号链接拒绝；完整 v7 内核隔离继续复测。
