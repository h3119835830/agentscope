# REVIEW：四层第一步的安全边界与验收范围

日期：2026-10-12。

## 评审结论

目标统一必须落到服务端生成记录和审批存储，而不只修改 UI 文案。新增局部提案入口只接受候选指纹和幂等键；实例、会话、材料来源和目标均由服务端恢复。系统／Agent 导入入口拒绝新的局部生成文档；统一确认入口和局部直接决定入口均拒绝加载。测试以权限表快照及“触达 Broker／适配器即失败”的断言验证边界。

局部审批的 blocked 状态不代表上下文持续有效。展示冻结归档避免逐行原生读取，保持读操作有界；提交仍做完整核验。任何后续启用加载的改动必须独立评审并增加加载时的来源、父策略和执行身份核验。

审批目录先过滤不可见运行时作业，并合并同时到达的读取；没有跨串行请求的过期缓存。最终真实目录读取为 4.607 秒，Chrome 列表、会话／工作区详情及助手范围均已核验并保存截图。

## 兼容性与缺口

人工 Agent 范围配置与系统配置合同保留；独立 managed task 会话审批保留其原执行链。共享原生 DSH 不具备局部加载能力，本轮不能宣称完成工作区／会话内核隔离。工作区身份为空时保留工作区目标并阻止应用。

旧运行时实例提案不再可批准为全 Agent 范围；缺少冻结目标的旧生成结果须重新生成。已加载且没有变化的历史 DSL 文档保留，避免改变既有批准范围。下一步需补充原生工具携带可信会话身份及对应执行域的协议。

## 发布事件

第一次 API 发布的优雅停止超过 Broker 既有 8 秒存活检查，触发其 fail-closed 行为，三个受控实例的进程被终止。回滚后通过既有 start 接口按原已批准配置恢复三实例，运行代次、PID 和执行域均更新；策略哈希及 DSL 配置未变化。不能把本轮整个发布过程描述为“进程从未重启”。

发布脚本增加空闲／任务／租约检查，并将 API 停止上限设为 3 秒；没有延长或伪造 Broker 存活检查，没有重启 Broker。随后发布使用权限、代次、PID、执行域、DSL 和系统策略快照逐项比较；详情见验收记录。发布失败的私有备份保留在服务目录，未向文档复制原始数据库或敏感配置。

## 测试限制

本轮额外真实只读生成任务返回不必要的澄清，没有生成“禁止读取”，但也不能算只读生成成功。另一个原生只读实例场景扫描因历史 root-owned 文件权限失败；未扩大读取权限以取得通过。两项保留为独立问题。本轮成功的真实范围验收使用“禁止修改 README.md”这一独立用例。

全后端回归曾发现共享 outbox 残留导致单个测试顺序污染；该测试单独通过，其余全套分开通过，不将其写成单次完整全绿。最终改动测试、界面核验及真实接口结果以[验收记录](../acceptance/AgentScope-policy-targets-step1-20261012.md)为准。
