## 当前候选的实际影响

候选 `27739bdbca0a43bfa20e42d62e2267e4` 是系统层“新增 环境凭据文件”，仍为 pending、approval_status=unrecorded、can_approve=true、can_apply=false。其规则是 `notify open file "**/*.env"`，处置为记录通知，不能称为阻止读取。候选规则 loaded=false、active=false，正式系统用户 DSL 仍为 revision 6、空文档；已有平台底线和实例权限不因用户 DSL 为空而消失。

**批准只保存决定；点击应用会关闭门禁并停止、重建受影响受控实例。当前不是原进程无重启热更新。** 此系统候选冻结四个登记实例，其中三个运行、一个已停止；在目标未漂移且应用成功的情况下，三个运行实例会生成新 PID、generation 和执行域，已停止实例只保存新策略，下一次人工启动时加载，不自动启动它。影响运行实例的全部原生会话与子进程，不能承诺正在执行的任务无中断或自动续跑。单 Agent 层候选仅影响该实例，不应扩大到全部 Agent。

## 增加、停用和删除

| 操作 | 当前实现 | 何时改变运行保护 |
| --- | --- | --- |
| 分批增加或修改系统策略 | 当前已应用文档按 ID 合并所选配置；未选中的已应用文档保留。新配置先保存版本，再生成独立候选 | 批准后另行应用，重建受影响运行实例 |
| 分批增加或修改 Agent 文档 | 在本层完整文档集合中增加/修改；系统文档与本 Agent 文档合并。系统、Agent 层可以分别配置，不要求每层一次填满 | 单独审批和应用，仅重建该受控实例 |
| 停用已生效文档 | 创建移除该文档的候选，保留其他文档；系统层移除不删除 Agent 文档，Agent 层移除不撤销继承的系统约束 | 待审批、已批准待应用时旧保护仍在；应用时停止旧域并按新集合重建 |
| 删除未生效系统配置 | revision CAS 后软归档，配置列表移除；版本、审批、执行历史保留 | 不加载策略、不重启 Agent；引用该配置的未应用旧候选会因版本变化失效 |
| 删除已生效系统配置 | 服务端拒绝直接归档，必须先停用并完成应用，再归档 | 停用应用阶段改变保护，后续归档仅改变配置库 |
| 拒绝或撤回未应用候选 | 处理候选与批准回执，不删除现行生效文档 | 不改变运行保护 |
| 停止 Agent | 独立的实例停止合同，终止整个受控执行域并保留配置和历史 | 这不是停用某条策略，不自动启动 |

停用入口针对完整策略文档；一份 DSL 含多条规则时会一起停用。若只调整其中一条，应编辑文档形成新版本并重新审批。底层 DSL proposals 的 `documents` 表示该层的完整下一版本，不能把只含新增项的数组当作自动追加接口；系统配置库与前端编辑/停用入口负责保留其他当前文档。

## 已核对的生效链路

1. 保存配置或草案：只保存版本；勾选不生效。
2. 校验候选：组合平台执行底线、系统文档和目标 Agent 文档，由 Broker 调 ActPlane 编译；冻结内容哈希、库版本、基线、资源、PID、generation、执行域及目标范围。编译成功不是加载成功。
3. 独立批准：校验当前候选，保存人工批准回执及影响快照，不启动、停止或加载。
4. 显式应用：匹配候选/批准哈希，校验当前基线与目标，重新编译并核对 bundle_hash 和执行能力。
5. 关闭实际 Broker 门禁，再将控制面标为 updating。等待已登记工具租约最多 8 秒，随后收集内核记录，停止受影响旧执行域；不保证所有在途任务都自然结束。旧句柄和映射通过进程终止回收。
6. 保存新本层文档集合、递增 revision、清除旧令牌/租约；仅重启应用前运行的实例。分配新 generation、令牌和域，Broker 启动 ActPlane watch、cgroup、网络边界、原生执行器，通过 `control launch-child --delta` 加载组合后的执行策略。
7. 核验 DSL 指纹、原生 PID/domain/cgroup、实际权限探针和匹配内核事件，持久化当前 generation 的加载回执。全部受影响运行实例完成加载核验、作用域 ready 后才开放门禁。
8. 运行期 Broker 校验 watch/anchor 身份、策略文件指纹、root-owned BPF pins、cgroup inode、Agent 进程开始身份和执行域；结果队列及内核事件按当前身份关联，不能用旧回执恢复权限。

失败合同：候选/批准基线的前置校验可以拒绝请求；进入应用执行后发生异常，统一应用服务会按 fail_closed 暂停/停止受影响实例，DSL 加载失败还会保留 blocked。不能推导为失败时旧进程一定继续运行，也不会自动回退旧权限或自动续跑。中断回收只修复暂停状态，不重试应用。

源码定位：`instances/approval_decisions.py:146-188,230-261`、`instances/dsl_policy.py:45-78,135-210`、`instances/controller.py:60-69,177-208`、`instances/policy_library.py:126-179`、`broker/instance_runtime.py:47-76,238-258,487-562,567-674`。核对的后端/API运行文件及 Broker 源码与当前工作树逐字节一致。
