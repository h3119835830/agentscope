## 修复、合同及故障验证

Broker 每秒核验实际进程身份、generation、执行域、cgroup、watch、策略与内核对象，再续写独立 runner 的心跳。控制台健康不再续命或杀死任务。实际保护核验失败即关闭准入并停止；Broker 失联或卡住仍由 runner 的 8 秒期限终止。root 信任边界及 map 内容核验限制见 RFC。

原生 `/lease`、`/result` 由 Broker 按冻结批准策略处理，回执先持久化再响应。队列预留未完成调用结果空间，容量不足停止新工具；generation/调用身份防执行重放，控制台接收事务提交后 ACK 防重复回补。修改控制策略先关闭 root 门禁。断控期间策略请求返回等待恢复，未实现自动排队审批。

最终隔离 18163 故障报告：

- API 离线 **45.13 秒**，Agent PID/generation/策略保持，实际原生合法工具可用，越权写入被拒绝，文件哈希不变。
- 14 条回执积压后正常回补，旧调用不能再次执行，审批失败关闭。
- watch 丢失后 **1.003 秒**终止；Broker SIGSTOP 后 **7.923 秒**由独立 runner 终止。数据来自实测轮询，不能把小数精度当作硬实时保证。
- root 队列权限、容量、磁盘失败关闭、严格类型、代次隔离、丢 ACK、变造序号和重复执行由后端反例测试覆盖；不是全部以端到端故障注入覆盖。

## 研究与实验结论

固定论文版本、公开源码提交、本地 vendor 提交及部署二进制分别索引；ActPlane、CaMeL、Progent、FIDES、BPFContain、Landlock 和攻击评测研究见研究附件。没有复现 CaMeL/Progent/FIDES 完整系统，没有测模型提示注入成功率。

确定性执行对照 **6 类 × 4 组 × 3 次 = 72 次**。ActPlane 组 18 次合法操作成功、攻击效果受阻且有内核拒绝；静态沙箱在凭证、验收完整性、路径变体、后代及资源对象五类中同样阻断。仅入口批准组表达“攻击已进入合法命令内部”的条件，不能代表所有工具权限实现。

来源实验保留相同地址和合法上报能力：普通来源连接允许，秘密经派生文件、重命名、另一进程后的新连接拒绝。本轮静态沙箱对两者均允许。这是对照中的增量，不能推广到已有 socket 的 send、所有 IPC 或完整信息流安全，也不是来源跟踪首创。

真实 DSH 六项均执行到结束并继续读取 README。凭证和后台读取出现 EPERM，测试改写 EROFS，跨挂载 rename EXDEV，另一资源未挂载 ENOENT；不能把挂载隔离的全部效果归因给 ActPlane。原生网络接收端无数据，但该策略没有普通连接允许对照，因此不作为来源比较证明。自然语言 because/next-step 是否准确送达仍未证实。

双原生实例补充完成平台撤权：A 旧进程有真实 FD、可写 mmap 及子进程；确认新策略后换代，旧持有者与子进程终止、保护文件不变；B 的 PID/generation/domain/策略不变。它验证平台销毁旧域的撤权路径，不验证引擎原地撤销 mmap，也不证明实例内部会话隔离。

保留首轮九项读取钩子未预留的载入失败、原生网络最初缺接收端的证据缺口、撤权脚本确认/探针身份失败和修正复验。没有修改模型提示词掩盖能力失败，没有保留模型私有推理或真实凭证。

## 正式部署及兼容性

第一版 `/opt/agentscope-value-20261012-223824` 包含 Broker/API/UI。以当时实际运行产物复制后覆盖本次文件，保留其他既有改动。发现 runner 的源码基线包含已测试 Hermes TUI 启动兼容修复，实际旧产物缺失；明确纳入基线差异清单。没有覆盖其他 worktree。

Broker 升级先冻结当时活动且无进行中任务的三个目标，受控停止后按正常启动流程重新核验；这是本轮明确执行的升级换代，不能宣传为 Broker 热升级无退出。原先关闭的实例保持关闭，策略、系统及 DSL 修订/文档保持一致。后续单独 API 重启耗时 4.48 秒，三个新实例的身份均保持。

第二版 API `/opt/agentscope-value-read-20261012-224541` 仅覆盖 managed schema/worker 与 approval_views。当时 Broker 仍为第一版，再次验证三个实例 PID/generation/domain/策略不变。

最终检查修正启动发布顺序：先记录 Agent 身份，再设置 ready，避免心跳线程观察到半就绪对象。补充脚本首次漏处理 API 对 Broker 的 systemd BindsTo/After 依赖，Broker 停止后 API 也被停止，后续启动请求失败；脚本回滚 Broker，随后从本次冻结目标恢复三个实例。这个可避免的部署脚本错误及恢复记录在 deployment-startup-first-failure.json 中保留。修正脚本为显式启动两个服务后复验成功，最终 Broker `/opt/agentscope-value-startup-20261012-225631`，API 代码仍为第二版。再次单独重启 API **1.862 秒**，最终三个实例 PID/generation/domain/策略保持。此次 Broker 补充升级及失败恢复均为受控换代，不能算作“整个发布期间实例一直不变”。

API/Broker 当前核验新鲜，队列无积压。其他 18000/18004 监听身份未变。普通业务未调用、未修改，未运行普通业务端到端验收；不能把监听不变说成业务功能全面通过。Hermes 本轮仅涉及独立原生 Agent 启动/保活，未触及 AI 大管家和 ERP 普通业务集成。
