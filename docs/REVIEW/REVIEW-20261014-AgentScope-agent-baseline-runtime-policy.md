# REVIEW：固定两层基线与真实域运行时增量

日期：2026-10-14，后续用户收敛决定。范围：文档设计修订与静态检查，未修改应用/DSH、加载策略、重启服务或部署。

## 结论

接受用户“按 ActPlane，做到 Agent 层，其他运行时新增”的方向：固定系统与 Agent 基线，工作区/会话作为上下文、来源和运行视图；运行时变化直接按真实域提交。前轮继续保留四个固定配置所有权层的目标由本轮取代，真实执行映射及共享边界不废弃。

关键限制是增量的来源不等于作用域。共享 Agent 域中由 S1 提出的规则，经准确范围批准后会影响 S2；禁止把它显示为单会话策略。独占原生子域可作为可选能力，不能强制改写 DSH 来满足固定层。

## 审查与修订

| 审查项 | 本轮处理 | 运行状态 |
|---|---|---|
| 四层配置所有权仍是必需目标 | 新 RFC/ADR 改为固定两层，主架构同步；旧四层方案标为历史 | 文档采纳，不代表应用迁移 |
| 运行时增量被误当作会话专属层 | 冻结真实域、共享成员、未来准入和中断影响，来源另列 | 统一新合同待实现/验收 |
| 会话结束即删除增量 | 默认绑定域运行代次，来源结束不删除；长期化另审批 | 当前生命周期待验收 |
| ActPlane Add 被误当成完整停用/热更新 | 核对 CLI 只有 Add；保留未实施热更新提案状态 | 通用停用/删除和无损更新未证明 |
| 撤下四层目标即宣称缺陷修好 | BUG 区分退役需求和仍开放的运行能力 | 无新运行通过数 |
| 会话可视化要求丢失 | 面板显示系统、Agent、实际域运行时规则和 DSL，共享范围可见 | 本轮未改 UI |

原四层 A03/A04 不再是固定交付条件；新的 N01–N12 验收以实际目标、共享域效果、原生流程保持和完整任务闭环为准。来源会话取消、增量停用、整个域停止分别验收。

## 源码证据和边界

本轮重新核对当前应用工作树的 cap_task/父域/fork、DSL system/instance 组合，以及 CLI DeltaCommands 只有 Add 的事实。文件摘要、静态检查、同步和应用工作树身份见[validation.json](evidence/agent-baseline-runtime-policy-20261014/validation.json)。没有重新构建部署 ActPlane，也没有证明当前二进制由这些源码可复现生成。

当前目标合同和已有实现分开：既有 system/instance 主组合可复用，但 RuntimeChange 完整字段、域范围审批、版本应用、生命周期及统一会话投影不能因文档变更标为实现完成。既有记录保留原范围，未应用的旧工作区/会话候选不自动改成 Agent/域候选。

界面合同参照 agentscope-ui-design，保留现有导航、记录表、按需展开、生成/批准/显式应用分离。旧技能中会话策略分类按用户本轮决定调整为真实域运行时规则；本轮只读核对现有系统策略页及主组合源码，不修改或验收新 UI。

## 默认共享架构增补

用户明确接受原生会话共享，因此不再将共享作为待绕过的问题；采用 AgentRuntime 统一运行登记与域活动版本、同域串行应用、不可变完整快照和只读会话投影。Connection/NativeAdapter 保留原生工作区、会话和工具流程；Broker/ActPlane 负责真实绑定与执行。增加并发版本漂移、失效协调器、部分加载失败和视图恢复 N11/N12 验收要求。

这次补充仍是设计，不表示活动指针、fencing、通用停用或统一 RuntimeChange 已实现。检查结果见[共享架构静态回执](evidence/agent-shared-runtime-design-20261014/validation.json)。
