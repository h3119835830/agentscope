## 3. 先做无新增策略的基线

在 A、B 两个 DSH 会话中，分别发送：

```text
请实际调用 Bash 原样执行下面的命令，返回 stdout、stderr 和退出码，不要仅口头判断，不要修改任何文件：
python3 /w/0/scope-policy-lab-20261016/probe.py --case all
```

两边都应返回 5 行 JSON：control、gm、am、ga、aa 全部 result=allowed；control 的 orders=3、total=340.00；退出码为 0。基线不通过就先记录问题，不进入策略测试。

probe.py 只读文件并输出结果。denied 仅代表操作系统返回 EACCES / EPERM（errno 13 / 1）；文件不存在等错误会标成 error，不能算策略拦截。全部执行时，即使一项被拒绝也继续测其他项。

## 5. 每轮都完整走：草案 → 提审 → 批准 → 应用

每轮只处理本轮一项，完成停用后再开始下一轮，避免多个待审批候选互相造成基线漂移。

1. **草案**：在系统页找到本轮实际名称，打开“详情 / 编辑”。核对范围、保护对象及“原始 DSL”。当前策略保持原样。
2. **提审**：详情中点“核对并提交审批”，或者勾选该子配置后点“校验并提交审批”。核对弹窗范围，再“提交审批”。此时是待审批，不应拦截本轮目标。
3. **批准**：审批页打开对应名称，核对变更内容和影响范围，勾选“已核对内容与影响范围”，点“批准变更”。此时已批准待应用，仍不应拦截本轮目标。A/B 再跑一次本轮单项命令检验。
4. **应用**：在同一审批详情重新核对，勾选确认，点“应用策略”。查看逐实例应用回执；正在运行的目标应显示加载核验结果，未运行目标应显示启动时加载。仅有“已批准”不算加载成功。
5. **重新打开 DSH**：应用会暂停并重建受影响实例。从 Agent连接重新“打开网页”，选择原工作区和自己创建的会话，等保护核验通过后再执行命令。不要在加载过程中继续发送任务。
6. **运行拦截**：A/B 分别跑本轮单项命令及 control，按表核对范围。最后再跑 all，确认只有本轮目标符合拒绝预期、其他三份文件仍允许、日报仍是 340.00。

单项命令（每轮替换 gm / am / ga / aa）：

```text
请实际调用 Bash 执行下面两条命令，分别返回 stdout、stderr、退出码，不修改文件：
python3 /w/0/scope-policy-lab-20261016/probe.py --case gm
python3 /w/0/scope-policy-lab-20261016/probe.py --case control
```

被拒绝的单项应为 result=denied、errno=13 或 1，退出码 13。允许的单项退出码 0。control 始终应允许并输出 340.00。B 在 AM/AA 轮被拒绝，就是范围隔离失败，不能算成功。

可选冷启动检查：在 GM 已加载后，通过连接页停止 B 再“打开网页”，重新执行 gm，仍应被拒绝。应用时若 B 已停止，先显示“启动时加载”，必须启动核验后才算真实执行生效。

## 6. 反馈与审计检查

回到 AgentScope → 会话 → 刷新列表，按自己创建的会话名称打开“查看策略详情”。核对所属实例，避免两个同名 DSH 会话混淆。

1. **安全配置 / 策略域**：能看到本轮已加载配置、所属范围以及继承关系。保存的草案和已批准待应用都不能显示为已加载。
2. **系统调用匹配记录**：按执行时间和本轮完整目标路径核对，查看实际 block 结果、策略名称、PID / 域及详情。仅显示声明的 block 动作，不足以证明已阻断。
3. **工具拦截 Trace**：区分工具准入拒绝、工具执行失败、关联的内核事件。查看“反馈状态”；只有显示送达回执才记为反馈已送达。
4. **DSH 对话**：记录是否收到可操作的反馈原因，以及 control 是否仍能继续运行。只有 Permission denied 而没有结构化反馈时，记为“运行拒绝通过，反馈送达未通过/待核验”。

如果内核事件没有可信会话关联，不能凭同一进程或时间强行归到某一个会话。会话页为空不能单独断言未拦截；可在 Agent连接 → 对应连接“配置” →“运行记录”核对工具执行及应用过程，并记录“缺少会话关联证据”。仍没有对应内核处置证据时，该项验收标待核验，不写通过。

## 7. 每轮最后：停用 → 再审批 → 再应用 → 恢复

1. 系统页搜索本轮策略名称，打开“详情 / 编辑”，点“停用策略…”。
2. 提交停用审批。**停用候选尚未批准、停用只批准未应用时，旧限制都应继续执行。**
3. 审批页核对这次移除的只有本轮配置，依次“批准变更”“应用策略”。
4. 从连接页重新打开受影响的 DSH，A/B 都再跑 all：5 项全部 allowed，control=340.00，退出码 0。
5. 检查停用审批与应用记录仍可查看；此前拦截事件保留。不用“删除配置 / 归档”代替停用，也不用停止整个 Agent 来冒充策略撤销。

完成恢复后再进入下一轮。这样四轮分别验证“所有 Agent / 指定 Agent × 手工 / 助手”的完整生命周期。
