## 2. 上一轮验收的准确结论

上一轮真实 DSH 23 项操作和 7 条 root 内核阻断证据继续有效，证明了 Agent 范围只读规则、未审批权限保持及批准后真实 OS 处置。候选目标固定 scopeType=agent，实例级确认后重建实例执行器；没有第二个原生会话/工作区对照，也没有可信工具 tag。

因此不计入 workspace/session 隔离通过，更不能把原生 sessionId 解释为独立内核域。显示“全部工作区与会话”是现有接口的真实范围；问题在于新局部目标尚无实现及此前回答未充分说明边界，不是已发现后端未批准自动扩权。历史审批目标不追溯改写。[原记录](../acceptance/20261011-policy-source-semantics-dsh/README.md)

## 3. 分级风险与处置

| 风险 | 处置/状态 |
|---|---|
| P1 局部需求进入实例范围 | 新合同默认 scene→workspace、runtime→session；能力不足禁止扩大；实现仍开放 |
| P1 共享执行器假隔离 | 首版每原生会话独立 worker/cgroup/domain；标签/路径不能替代主体；实现仍开放 |
| P1 上层约束或人工确认被旁路 | 上层强制规则锁定；所有用户变更确认；不开放高权上游变更接口给 Pi；需后续攻击/故障验收 |
| P2 论文/公开生成器来源混用 | 311 首轮、50 最终策略和缺失逐运行链分别记录；不能证明同一 Codex 来源，待补齐 |
| P2 示例被直接宣称完整产品能力 | 13 例逐项列出断言与缺口；复用分类不等于验收通过，文档整改完成 |
| P2 作用域整数/无限层级误读 | scope_id 不证明路径包含；有界深度和容量需拒绝/完整展开，未承诺无限内核层级 |
| P2 Progent 模板直接作为安全保证 | 比较器/开关/unknown、多规则及全局状态限制列明；仅借鉴机制，未引入代码 |
