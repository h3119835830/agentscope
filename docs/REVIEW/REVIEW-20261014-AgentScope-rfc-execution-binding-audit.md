# REVIEW：四层 RFC 的执行映射与生命周期复核

2026-10-14 后续收敛决定：本文记录 ad39d60 时的设计与检查；之后固定四层目标已取代，未实现的工作区/会话固定层退出当前要求，不能把需求退出记为代码修复。 见 [当前合同](../RFC/RFC-20261014-AgentScope-agent-baseline-runtime-policy.md)。历史验收及既有批准范围不变，本轮仅文档修订。

日期：2026-10-14。范围：RFC/ADR 的源码对照、部分重推及静态文档验收。本次未修改应用/DSH、重启服务、应用策略或部署；不构成四层运行管控验收。

## 结论

需要重推执行映射和生命周期前提，不需要推倒四层配置、人工审批和已有拒绝门禁。主要设计问题是把“每个原生会话一个 DSH worker”提前定为首版方案，并让取消、恢复和故障处置依赖独占边界；执行共享和原生流程尚未验证时，这一前提不成立。

原四层 RFC 已明确“四层配置不等于四个内核域”“工具标签不证明隔离”“scope_id 数值不证明路径包含”，这些正确条款保留。热更新提案本来已经限制共享域应用；本次补强共享范围及可用性门禁，没有把它误判为已实现的会话隔离方案。

## 源码与发布证据边界

本次复核应用工作树 vendored ActPlane 的 cap_task、祖先匹配、fork、child binding 与 TGID 钩子，以及 AgentScope 的 executor_shared、本地能力拒绝和 system/instance DSL 组合。具体路径、行号和 SHA256 见证据 JSON。源代码证明所审模型；实际运行二进制有独立路径和摘要，本轮没有证明它可由这些源码重建，也未重新测试内核操作。

原生 DSH/Hermes 启动方式和既有集成侵入事实沿用[此前调研](REVIEW-20261014-AgentScope-agent-launch-adapter-research.md)，不追加启动 Agent 来验证。实现工作树只读，部署服务的进程开始身份和二进制摘要复核结果另存静态检查回执。
