# BUG：ECS 三阶段流程已复现问题与修复

日期：2026-10-25。验收证据：`acceptance/evidence/three-stage-20261025/`。

| 问题 | 原因 | 修复与验证 |
| --- | --- | --- |
| API 无法读取服务器场景 | API UID 不应具有项目读取身份，元数据核验却走 API DAC | 固定 reader 同时承担正文、目录和元数据核验；三身份测试覆盖拒绝、软链接和越界 |
| Pi 使用 `.` 或执行映射作为目录参数 | 根目录参数合同不清楚，格式错误被混为权限拒绝 | 声明规范相对路径、根目录空字符串；格式错误单独反馈，不放宽读取权限 |
| 显式 DSH 启动入口无法绑定真实 PID | `.bin/dsh` 的拼写假设与固定 canonical argv 不一致 | 按登记 argv、cgroup 与 NSpid 精确匹配；拒绝仅在参数中提及入口的伪装进程 |
| 工具与内核只有两份孤立记录 | 没有在准入时写入已有原生 audit_call 标记 | 准入前写 tag、fork 继承、结果清根 tag；缺少 map 直接拒绝启动，事件必须精确关联 |
| 新引擎被 ECS verifier 拒绝 | file_permission 拒绝布尔表达式被编译为范围不可证明的负值 | 独立 noinline 常量拒绝 helper；真实 ECS 加载与合成受保护写入成功验证 |
| 表面维护成功但无内核事件 | DSH 只见基础 grant，未收到已加载 DSL，自行 chmod 造成 DAC 拒绝 | 保留失败记录；补齐 Scope 和分析上下文的 DSL 加载事实，再用真实内核事件验收 |
| 文件删掉或 reader 失联时可能没有审计 | enqueue 的完整性读取异常向外抛出 | 保留作业并记录完整性未知，不降级到 API 读取、不误报文件已改变或安全 |
| 审计设置标签难定位、长说明铺满页面 | 表单标签包住 textarea 内容；长模型结果直接显示 | 显式 htmlFor/id、范围明确的设置布局、模型说明折叠；真实页面宽窄屏通过 |

补充：Pi 的新 proc 挂载与 ECS systemd 限制冲突，改用空 `/proc` 而非放宽宿主进程可见性。独立读取服务、API、模型均不获得内核策略写权限。

未删除或改写失败的模型结果、原生回执和失败分析作业。后续重试保留相同输入摘要；新运行形成新记录。不得把未运行的 Rust ignored 项或 Jev 接口接入标成通过。
