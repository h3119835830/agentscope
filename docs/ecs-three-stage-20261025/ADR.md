# ADR：可信关联、固定读取身份与最小 LSM 兼容

日期：2026-10-25。状态：采纳，保留人工策略审批边界。

1. 采用原生 Pi 工具循环，不把一次 JSON 生成伪装成 Agent。文件选择和模板选择由模型完成，确定性校验决定是否可保存草案。模型输出不赋予执行权限。
2. 参考文件通过固定、独立、无能力的读取进程访问。API 不能代替读取身份，也不能借元数据核验扩大目录可读权限。读取不可用时失败关闭；运行后文件无法核对时明确记录完整性未知，不丢掉审计任务。
3. 使用 ActPlane 已有的 fork 继承调用标记，不以时间窗口猜测工具与内核关系。共享原生进程顶层工具串行，避免根进程 tag 被并发调用覆盖。重放返回原绑定，不重复写 tag。
4. 运行时和运行后作业冻结输入。运行时只生成待审批候选；运行后只读审计。重试必须匹配原 input_hash，人工意见追加保存。
5. 同时把当前已加载 DSL 约束提供给原生 Scope 和策略分析上下文。修正上下文合同，不新增场景特定提示规则，不改原模型输出或既有失败证据。
6. 经用户“最小兼容修复、不放宽安全边界”单独授权，修改 `actplane/bpf/process.bpf.c`：在原拒绝分支调用 noinline、带 compiler barrier 的常量 `-EPERM` helper，避免旧 verifier 丢失否定布尔表达式的返回值范围。原判定条件、hook、策略含义、Rust/C ABI 均不改。

兼容构建使用 clang BPF v3 和现有头文件，更新对应 prebuilt object。保留旧 ECS 引擎供故障恢复。仅改构建参数的 v2 尝试未解决问题，不作为合格版本。

通过验证的 ELF SHA-256：`87ffa35e50960acc9decba6b4163a71d809c8a7c8400a47d7698385acf6fbcf2`。

拒绝方案：关闭 LSM hook、降为仅观测、修改规则语义、扩大 Agent 权限、让 Pi 自动应用策略、用健康检查替代真实阻断验收。
