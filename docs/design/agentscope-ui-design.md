# AgentScope 界面设计约定

针对 AgentScope 界面工作，先读本文件，再核对当前代码和真实页面。以下来自用户 2026-10-10 的明确要求；后续直接指令优先。

## 信息与导航
- 模块名只放左侧导航和面包屑。页面内部不重复放“Agent”“系统”等大标题，不展示“第二层 · Agent 专属策略”等实现层级标签。
- 保留 Agent连接；会话作为其下方子入口。会话按已连接的 Agent 产品筛选，不按编码/研究等任务类型分类。任务历史位于导航最后。
- 会话目录只展示会话记录；去掉工作区、连接信息页签和工作区详情入口。“查看安全”改为“查看策略详情”。
- 策略列表以结构化记录表展示名称、匹配对象、操作、处置、状态等字段；详情提供可读、可配置的表单。不要把列表改成卡片墙或把全部配置堆在首屏。
- 会话策略区分系统策略、Agent 专属策略、会话策略；会话策略可区分场景生成和运行时生成。提供类型筛选。移除“基于/来源”长说明。
- 关系页展示策略域关系，去掉 Agent 关系和 OS 进程图；系统调用匹配记录与工具拦截 trace 分开呈现。去掉工作区、策略版本和无明确用户用途的执行记录页签。

## Agent 与系统
- 审批有独立侧栏入口。助手候选提供可读详情和提交审批，审批详情展示变更、影响范围与校验状态；只有用户点击批准并应用后才调用应用接口。策略选择使用可搜索的记录表。
- Agent 页是简洁的策略助手对话框。支持在对话中选取模板/候选、补充参数并起草对应 Agent 的策略；目标采用 Agent连接的真实实例身份。
- 系统模块管理系统策略、策略与模板和生成记录。系统策略供全部受控 Agent 继承；策略与模板供指定 Agent 使用。不要“服务与能力”模块。
- 不向客户展示“查看生成说明”、IR 缺口、英文内部阻塞码、原始 JSON、内部生成 ID 等诊断。用简短可操作的提示表达缺少的信息，技术证据放独立验收文档。
- 详情需认真设计密度、对齐、分组、排版和反馈，避免几个大框、编号步骤和大片空白。改后展示真实页面截图或打开可检查页面，不能只口头描述。

## 策略与真实边界
- 策略来源必须核对 ActPlane 源码与已连接 Agent 的实际启动身份；不能把通用 `source AGENT = exec "**"` 当成已绑定具体 Agent。脚本启动器、解释器和受控进程域要分别核对，不能按产品名伪造可执行文件。
- 模板/助手只生成候选；绑定精确目标，带入对应 DSL 编辑器。生成、保存、校验、人工确认、加载、生效和内核拦截是不同事实。
- 策略应用由用户确认。切换 Agent 后不得串用对话、候选或执行范围。不可为得到 DSL 而伪造已验证工作区或绕过服务端校验。
