# 会话安全界面未完整覆盖可视化配置需求

日期：2026-10-14。状态：第一阶段界面、约束汇总及所属层配置入口已在 18003 验收关闭；独立原生会话执行及完整模型安全任务闭环仍开放。优先级：P1 产品需求缺口，未据此认定已有保护失效。

用户提供的老师要求包括：每个 session 当前约束可视、像 App 权限一样通过勾选/复选/文字配置、支持通用约束及 Agent 动态提议、可见的安全检查和实际安全案例。

真实 18003 会话入口已能聚合会话记录，本次页面读取为 18 条；详情展示本会话新增约束、折叠的继承约束、策略域、系统调用匹配和工具 Trace。源码 `AgentSessions.jsx` 与 `SessionPolicyGroups.jsx` 将继承配置跳转至系统或 Agent，当前缺少围绕会话统一组织的可视化配置与检查面板。后端 `sessions.py` 仍声明 executor_shared=True，局部应用能力缺失另见既有四层合同。

初次交付时已有组件分散且用户操作围绕配置归属展开，未完整形成老师要求的会话安全体验；方案演示未用于关闭本项。

关闭条件按 [会话安全工作台 RFC](../RFC/RFC-20261014-AgentScope-session-security-workbench.md) 的八项验收逐项记录。独立会话真实生效和实际任务闭环必须单列验收，不能由原型或回归数量替代。

实现更新：原页面 records 仅汇总 DSL/编译映射及受管任务，没有接入已存在的结构化平台、资源、网络、工具与行为约定，导致绑定已核验而列表为零。新增独立 security 投影保留原 records，并显示已接入约束、缺失映射和执行方式。新 POST 在原控制器上创建候选，支持所属层配置与停用，复用两阶段审批。工作区/会话局部应用继续明确拒绝。

浏览器复现并修复：控制台原先过滤 legacy_generated，新增安全列表的启动规则虽可见，详情和证据计数却缺失。现在通过 security.evidence_records 提供仅当前会话命中的旧规则详情，保留原 records 合同；实际浏览器已验证 2 条记录和可打开详情。不存在的约束文件原被通用 OSError 映射为 503 控制连接异常；新入口现返回 409 路径错误，不创建候选或幂等关联，并可修改路径后继续提交。对应测试及真实页面均通过。

第二批隔离环境的新增限制、真实内核拒绝、所属层停用恢复、另一 Agent 不受影响以及真实会话候选切换均通过，详见 [交付评审](../REVIEW/REVIEW-20261014-AgentScope-session-security-delivery.md)。第一批因并发正式 API 发布导致生产身份比较失败的记录仍保留，未改写为通过。
