# AgentScope 失效审批缺少重新校验入口

日期：2026-10-14。状态：已修复并完成本次范围验收。优先级：P2，交互流程缺口。关联 [全流程评审](../REVIEW/REVIEW-20261014-AgentScope-policy-lifecycle.md)。

## 复现

在本机 `http://localhost:18003/` 打开审批 → 需要处理 → 系统候选“环境凭据文件”。候选 ID 为 4902875341f142e0b7f3d43b49ac29a3，页面提示“Agent 环境或策略配置已经变化，需要重新校验”。详情显示前述原因、变更内容和影响范围，操作区只有“拒绝”，没有重新校验或返回原配置起草新版本的动作。

复现只查看记录，未拒绝、批准、应用或更改运行策略。

## 影响与源码依据

失效候选被服务端禁止应用，保护边界符合预期；用户得到原因但缺少可直接完成后续处理的入口，需自行离开审批寻找原始配置。不能将该缺口描述为策略可以绕过审批。

源码 `/home/happy/projects/agentscope-policy-flow-20261013/frontend/src/PolicyApprovals.jsx` 的审批详情操作区仅按 can_reject、can_approve、can_apply 展示拒绝、批准和应用，未提供失效状态对应的恢复动作。后端 `backend/agentscope_app/instances/approval_views.py` 已能投影 stale 与原因。两个路径均属于同一源码工作树，实际运行目录为 `/opt/agentscope-policy-flow-20261013-200758`。

## 修复建议和关闭条件

提供“返回原配置重新校验”或“从此记录起草新版本”，保持旧候选及批准证据不可改写。按原 scope 和精确 target 载入可复用输入，重新读取身份、基线、能力和材料；新候选需重新批准，再显式应用。没有可恢复输入的旧记录明确说明，并提供所属配置入口。

验收必须覆盖系统、Agent 和能力不足的局部候选；返回时不扩大范围、不沿用旧批准、不自动生成或应用，不丢失旧记录。失败应用的恢复还需展示暂停是否核验。真实桌面和窄屏走通新版本至审批路径后方可关闭。

本次相关后端 145 项、前端 71 项回归通过，但不证明本缺口修复；本次未更改前端或后端实现。
