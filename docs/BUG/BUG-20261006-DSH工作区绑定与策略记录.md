# BUG：任务工作台记录混杂与重复导航

> 逐句合同修订：前版作业级完整 DSL 展示与评估复选框已废弃。现行逐句子句、证据及加载隔离见 [RFC](../RFC/RFC-20261006-逐句DSL与控制台锁定.md)；整包 DSL 仅后台用于验真和加载。

日期：2026-10-06。状态：已复现、修正并专项复验。

| 问题 | 原因 | 修正 | 验收 |
|---|---|---|---|
| 看不出运行事件是工具还是 OS | 混合源数组直接展示 | 服务端按 OS/tool/control 分类分页，来源标签独立 | 真实内核记录及 DSH 开始/返回、控制面送达分离 |
| 当前权限堆段落，运行前/运行时不分 | 仅有效快照，没有策略语句投影 | 三分页及结构化记录/详情抽屉 | 启动三规则、运行时保护及新真实 Pi 两语句可读 |
| 工作区下拉含义不清 | 历史保存 task 优先，缺注册核验 | 唯一活动受管工作区自动绑定，歧义显式选择 | 无 task 自动匹配；exact/ambiguous/ended 单测 |
| 任务工作台和运行时 Scope 重复 | 同组件双入口 | 删除重复入口、旧 URL 兼容 | 六导航与旧链接实际浏览器通过 |
| 扩权后仍生效保护显示失效 | 对整个权限快照做等值比较 | 比较该候选实际 delta 是否保留 | acceptance.txt 在输出扩权后仍生效，回归通过 |
| 审计层切换瞬间留下旧列表 | 新请求完成前旧数组未清空 | 清空旧类别、读取状态、过期响应防护 | 实际浏览器 tools/control 切换复验 |
| 探针工具结果误标 DSH 来源 | 结果记录缺独立标志，未关联开始来源 | 继承同 call ID 的开始记录探针标志 | 单测和现场 API / UI 通过 |
| 新 Pi 识别被标历史条款 | 顶层兼容 provenance 通用文字 | 以真实 identified_statements 标注 Pi 结构化识别 | 新现场记录标签正确 |
| no_change 显示加载版本易误读 | 回执现行版本复用加载字段标签 | 未应用时显示评估回执版本，已加载变更否 | 新真实 no_change 未加载且 v7 保持 |

没有用专门场景提示词修复这些问题。修正位于数据合同、来源关联、状态逻辑和页面切换；Pi 的新增要求为通用公开结构化注释。候选注释不授予权限、不实现不支持的引擎能力。

残余边界：历史完整 DSL 未登记，明确展示原编译器规则片段；旧启动上下文需求由证据角色推导；自动识别不扩展到未登记个人 DSH。完整支付业务任务失败仍单独记录，不以此次 UI 通过覆盖。
