# 安全总览难懂与公告入口缺失

状态：首次修复的发布/技术验收记录。用户随后明确要求先恢复原版，当前处理见 BUG-20261013-restore-original-security-overview.md；首次技术验收不代表用户接受了该布局。

## 复现与原因

打开总览的安全亮点，默认先看到十二行研究目录；进入场景后是任务、攻击者、已有方案、增量、结果和边界等多段文字。旧版工具/系统对照结构被替换，读者难以一眼理解攻击怎样发生、哪里被阻断。公告已经写成 announcement.md，但首页没有阅读入口，因此成稿难以发现。

## 修复

入口改为“安全总览 / 阅读公告”。安全总览恢复场景切换及工具/系统行为对照，默认测试插件场景；研究详情折叠，完整目录保留。公告生成独立可读全文页并接入两个入口。证据缺失时同步降级图解结果，避免残留允许/拒绝的实测色彩及结论。

## 验收

259 项前端测试通过、构建通过；十二类场景逐项切换，实测和待验证分级正确；完整目录十二行，来源场景保留已有连接/IPC 的边界。390×844 下图解和目录均无内容横向溢出；Escape 关闭、焦点返回触发按钮。正式总览三个实例当前保护核验正常，公告链接可打开完整正文。截图和发布证据见同日 REVIEW。

首次发布预检查误假定静态 UI 必须 root 持有，在任何发布前拒绝。读取实际目录确认现有可信部署用户为 happy 后，按既有静态安装约定接受该属主；没有修改目录权限或进程。记录保留于 ownership-preflight-first.txt。

本轮无服务重启，无策略变更，无数据库回滚。稳定性观察、数字地址读取挂起及既有安全能力边界仍由原 BUG/REVIEW 跟进，不因本次 UI 修复关闭。
