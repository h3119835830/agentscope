# BUG：WSL 无前台会话退出导致 18003 间歇不可达

日期：2026-10-09。关联：[ui-redesign 接入验收](../REVIEW/REVIEW-ui-redesign样式接入-20261009.md)。

## 复现与诊断

用户报告 Windows / Codex 浏览器无法打开 http://127.0.0.1:18003/。Windows GET 实测连接被拒绝且无对应监听；执行 WSL 命令期间 API、Broker 均 active，Linux ss 可见 127.0.0.1:18003。systemd 日志出现短周期停止及新的 boot 分段，说明仅检查服务 active 或短时 HTTP 200 不能证明 Windows 后续持续可达。

在受工具管理的前台执行会话运行 `wsl -d Ubuntu -u happy -- sleep 120` 后，Windows 首页立即返回 200。随后使用受工具管理的长期前台会话 `wsl -d Ubuntu -u happy -- sleep infinity` 保持 WSL 运行，不修改 .wslconfig、网络绑定、防火墙、普通业务代码或 Agent 策略。

## 修复及验收

采用现有 systemd 托管 API/Broker，并保持一个 Windows 侧 WSL 前台驻留会话。该会话是本次工具执行管理的运行会话，没有安装登录启动项或计划任务，也不是永久开机启动保证；关闭驻留会话、退出管理进程或显式 shutdown WSL 后需重新启动。

Windows 实测：首页、index-_VyB5nR7.js、index-DSLHCQMK.css、/api/status 全部 HTTP 200。这些资源仍为 ui-redesign 样式构建产物。最终复查在前述 120 秒诊断会话退出后进行，以确认恢复不依赖短时诊断。

最初尝试创建隐藏的 Windows 常驻辅助进程被自动审批拒绝，工具仅返回 blocked by policy，没有详细原因；没有继续采用该后台方案，改用受工具管理、可停止的前台执行会话。

## 验收边界

此次证明 Windows 到 WSL 的页面、静态资源和状态接口可达。没有重跑 DSH/Hermes 或内核执行安全案例；API active、HTTP 200 均不能代替当前策略加载、进程绑定或内核拦截证据。浏览器工具此前的 URL 策略限制尚未解除，本轮不宣称实际浏览器截图验收。此前样式接入检查遗漏了 WSL 无前台驻留后持续可达这一项，现补充记录。
