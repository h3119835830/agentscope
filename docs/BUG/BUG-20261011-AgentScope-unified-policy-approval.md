# BUG：第一步审批整改与验收闭环

日期：2026-10-11。状态：以下问题在本地源码与隔离测试中关闭；18003 运行环境未发布本次修复。

| 问题 | 复现与影响 | 修复 | 验收 |
|---|---|---|---|
| AP-01 实例收紧自动应用 | user/agent 提交 restrict 会直接或异步调用 apply，未人工批准就替换执行权限 | 删除自动分支，统一 pending；只由控制接口确认；同步移除旧编辑器的自动应用说明 | 未运行/运行中 × user/agent 均不触发 stop/start；权限哈希与状态不变 |
| AP-02 审批目录遗漏提案 | DSL 目录不包含 instance_proposals、system_security_proposals、managed_jobs 的待审候选 | 公共投影与统一决策分派 | 系统/实例/DSL/运行时可见，列表与计数一致；只操作目标实例或任务 |
| AP-03 旧候选执行身份不充分 | 同基线下资源、进程或 DSL 改变后，旧类型化候选未冻结全部相关上下文 | 附加快照并持锁重验；运行时增加会话/绑定核对 | 资源、generation/基线、DSL、域与 session 漂移拒绝应用；相同工作区不同实例确认指纹不同 |
| AP-04 旧运行时记录破坏目录 | 全量回归发现旧提案缺 hash 导致 KeyError；孤立作业加载不存在的 managed_tasks 导致目录冲突 | 缺合同记录显示 invalid，孤立作业不进入当前目录 | 目录与详情继续可读，无批准按钮，伪造指纹返回冲突 |
| AP-05 应用后历史差异消失 | 浏览器批准类型化实例候选后，详情按当前策略重算，显示 0 项变更 | 提交时保存修改前快照，详情使用冻结基线 | 系统/实例批准后仍有原始 before/after；最终浏览器截图保留网络变更对照 |

新增回归见 `backend/tests/test_unified_approvals.py`；原自动收紧测试已改为先断言 pending 与零加载调用，再显式确认。既有并发、失败关闭、项目证据、继承底线和归档回执测试仍保留。

未关闭原架构评审中的场景文件读取、独立会话执行域和无关 UI 诊断问题。完整范围见[RFC](../RFC/RFC-20261011-AgentScope-unified-policy-approval.md)。
