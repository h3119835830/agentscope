# 第三步问题与修复闭环

日期：2026-10-11。

## SCENE-001：策略助手没有项目文件场景输入（本轮修复）

原实现仅核验 Agent/会话环境和用户文字对象。现增加受限文本冻结、模型建议与文件引用、人工采用和 scene_binding。后端覆盖真实文件过滤、凭据清理、容量限制、符号链接、目标隔离、文件/运行身份漂移、未完成读取、引用伪造与存储完整性；浏览器完成实际读取到待审批链路。

## SCENE-002：产品读取路由漏接导致轮询空响应（本轮修复）

初版仅有管理员 GET，产品地址转换后未命中 API，轮询结果缺少 recommendations 导致页面异常。已补产品 GET 与可见性校验，并增加接口等价回归和前端空值防护；最终页面正常。

## SCENE-003：摘要算法混用（本轮修复）

共用扫描器使用 bootstrap.digest，新模块初版用 pipeline.digest 核对其文件清单，序列化不同导致全部清单拒绝。现以同一扫描器摘要核对，存储/结果摘要各自使用明确合同，全量后端通过。

## SCENE-004：旧场景需求和旧异步响应污染上下文（本轮修复）

对话恢复保存 sceneId；生成只携带相同场景的此前需求。新读取使旧恢复响应失效，轮询串行，目标卸载后忽略响应。测试覆盖场景隔离、显式读取、采用只填输入框、失效和加载状态；浏览器重读后 .env 新请求未混入此前 sales.csv 需求。

## SCENE-005：审批失效提示缺少下一步（本轮修复）

场景校验失败时，审批中心显示回到助手重新读取并生成候选，移除批准入口。已用真实文件变更及审批投影测试验证。

## GEN-SEMANTICS-001：既有生成器可能扩大只读限制（开放，禁止当作已验收语义）

实测需求：只读取 sales.csv 以获取报告数据，不写入、追加或覆盖该文件。场景推荐和环境对象均正确定位到 /w/0/sales.csv；生成器输出 block write、block open、block unlink，其中无条件 block open 会阻止正常读取。该候选编译通过，但未提交审批或应用。

问题位于既有自然语言→IR 的语义保持链路，不能归因于 Agent 不智能或用针对 sales.csv 的提示词修补。后续应核对 source/完整性复核/目标适配/IR 之间的上下文、允许操作和限制操作合同，并增加通用语义一致性校验。验收门槛：只读意图应允许正常读取并拒绝修改；禁止访问意图才拒绝打开/读取；跨多文件和不同表达验证，不以单样例通过替代。现有人工审批和未批准不改权限保证此错误候选未成为有效权限。
