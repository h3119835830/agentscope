# 原生接入问题与闭环

## 长路径规则过度拒绝

复现：原始 RQ5 路径超过 ActPlane 当前 64 字节规则 ABI，源码写入授权存在，但内核把授权源码内的固定 held-handle canary 匹配到配置保护规则并拒绝。最初只验证保护文件拒绝，因此漏掉此问题；原失败保留在私有验收事件中。

修复：受控挂载统一短别名，编译规则及 unless 使用短路径；超限规则拒绝。原生会话和候选都通过显式资源映射。新增每个写入授权的真实正向 canary，与保护文件拒绝及 root 内核事件一起作为 gate 开放条件。

验收：DSH/Hermes 授权 canary 成功，测试/配置拒绝与完整性通过。固定 FD+可写 mmap+忽略 TERM 的后台后代建立成功；实例收紧后旧进程全部终止、内容未变，新域重新核验。单元回归覆盖长原始目录的精确编译与反向映射。

## 原生启动与映射

- bwrap 资源目录 DAC 失败：进入 bwrap 前降权到 happy 与任务组；保留独立 mount/user/pid namespace。
- namespace PID 误认主机 PID：只能在登记 cgroup 内按 NSpid 和原生安装身份唯一匹配。
- Hermes 继承 host 日志 FD，namespace 内路径不可解析导致 CLI 输出 EPERM：根 relay 用管道转存，Agent 不持有 host 日志 FD。
- DSH 配置封存后无法创建 sessions：提前建立 sessions/storages/logs 可写目录，只封存启动配置与插件。
- Broker/API 断连遗留执行器：增加独立 relay 的 8 秒心跳期限与恢复清理；不得用历史回执恢复生效声明。
- Agent 提案同步等待自身重建：Agent 收紧先返回回执，可信控制线程排空再切换，避免停止服务等待原 HTTP 调用循环。

## 验收边界

RQ5 原始未改测试的功能失败单独记录，不修改测试使其通过。既有前端 managed_records 的默认视图断言与现有 workbench 行为不一致，须在 REVIEW 中记录现状；不是本模块安全核验的替代证据。完整验收表见 [REVIEW](../REVIEW/REVIEW-Agent实例接入验收-20261008.md)。

## 2026-10-09：同一 Agent 被平铺为重复入口

复现：同屏四行，分别为受控 DSH、受控 Hermes、本机 DSH 观测、Hermes 安装入口。原因是把不同来源记录直接作为首页行，未区分 Agent 产品与具体连接实例。

修复：首页按已识别 Agent 类型聚合，当前四记录归为 DeepSeek Harness、Hermes 两行。未删除记录，“实例与进程”保留来源和独立身份；可打开的已有入口优先于未运行受控连接。过期/未知 PID 不展示，未连接详情不请求不可用的运行时会话/进程映射。135 项前端测试与构建通过，实际接口数据验证为 4 条记录、2 个产品分组。当前浏览器工具限制仍在，不把代码和接口验证描述成实际浏览器视觉验收。

## 2026-10-09：旧表仍显示四行，且无法区分 Web 与 CLI

复现：用户截图仍是“实例名称”表头，没有“实例与进程”；交付端 HTML 当时已引用包含分组的新 JS，截图呈现旧客户端布局。四条原始记录分别为两个受控 Web 连接、原生 DSH Web 观测、Hermes CLI 安装入口，并非四个正在运行的 Agent。HTML 原来没有 Cache-Control，且已打开的标签页不会因静态部署自动替换运行中的 JS；未从浏览器取到缓存证据，因此不把具体缓存命中认定为已证实根因。

修复：HTML 导航增加强制重新校验；入口方式由适配器元数据说明，按钮改成“打开网页／启动网页／查看入口／CLI 启动方式”。CLI 安装入口显示固定终端命令，既不宣称正在运行，也不执行任意命令。首页按 Agent 聚合为两行，实例明细展示来源、入口方式和 PID。仅 OS 观测的当前进程可查看，但不宣称已核验策略域；过期 PID 隐去。

验收：前端 138 passed、后端相关 33 passed、Vite 构建通过；独立 18003 实际响应为四记录、两产品分组，Hermes 安装记录为 cli_install，Windows HTTP 200 且返回新的缓存合同。没有启动 Agent、没有应用策略变更。交付端与逻辑验收通过；浏览器策略拒绝 localhost 自动化访问，真实截图和窄屏视觉复验仍待完成，不能记为完整视觉闭环。[脱敏接口证据](../acceptance/agent-instances-20261008/entry-modes-20261009.json)。
