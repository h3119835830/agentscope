# BUG：真实策略展示与会话证据验收闭环

## 已修复

- 旧安全配置以“允许修改与删除”等通用权限替代 ActPlane 规则，详情未呈现原始 DSL。改为真实动作／事件类型／上下文／来源／状态记录；旧挂载与工具准入保持兼容，用户原文缺失如实标注。
- 原生会话目录与连接抽屉重复。改为独立导航，连接中提供跳转，保留原生 ID、名称、实际工作区和 PID。
- 候选保存的 SQL 占位符数量与新表不一致。真实候选 API 回归覆盖保存、编译、确认和重试。
- 原始 AST 适配错误使用 via、lineageIncludes、带括号条件，以及遗漏 source marker 的 ref=，导致真实 DSL 变换／规则映射失败。按实际 ActPlane 语法修正为 by exec、lineage-includes exec、左结合条件与受信任 source_ref；增加真实 AST round-trip 及编译映射回归。
- 旧回执与新修订共用稳定 source_ref 时可能被误认为新版本已加载。补核当前 DSL 指纹、原文与编译子句，只有版本一致的绑定能显示当前核验。
- 浏览器由策略页切换到内核页时，新页签先渲染旧策略 rows，访问 source_refs.length 导致白屏。以连接／会话／代次／页签键隔离数据，在新请求完成前显示加载态；浏览器四页来回切换回归。
- 编辑器轮询更新基准可能覆盖并发编辑。打开时冻结完整基准，确认再次核对版本和运行范围。
- 特定 exec 来源的标签可传播到后代，不能全部视为单事件。分类补充 exec 来源的谱系依赖，并增加真实 AST 回归。
- 页签切换或刷新前先清空运行概要，会短暂显示“未核验”及零策略。按会话／代次保留已核验概要，首次读取显示核验中，策略域和统计显示读取态。
- Agent DSL 失败被全局 ensure_ready/lease 检查放大为其他连接不可执行。检查收窄为 system + 当前 connection；新增其他连接仍能取得 lease 的回归，原 DSH 在测试连接 blocked 时实际恢复成功。
- 重复启动复用 control 目录，而 ActPlane 会重置反馈文件；旧文件大小作为新代次起始偏移导致开头事件丢失。真实复测中 block/notify 操作结果正确但目录只有后面的 kill 匹配。改为 control/{generation} 独立可信目录，从 0 增量采集，保留各代次原始文件。增加文件身份／代次游标回归，并在真实连接重启前后分别验证三种动作、全部命中映射和同一包 hash，均通过。

## 验收中记录的真实差异

固定 kill 测试进程的 bwrap 外层返回 137，而非 Python subprocess 的 -9。不能仅依据外层返回码判断处置；同时核对真实子 PID 已退出、内核 killed=true、域／包 hash／命中子句。第一次严格断言失败保留在原运行代次的数据库与内核日志中；修正断言后使用同一连接再次验证，不改内核行为。

notify 的真实 action 为 report。界面按实际 report 展示“匹配已上报 · 操作继续”，反馈回执仍为未取得；不显示为阻断或已送达。

浏览器导入含 `source F = file "**/.agentscope-context-canary"` 的文档，静态编译通过，但实际运行 delta 报缺少 path suffix 特性，测试连接按失败策略暂停。向 watch 添加 matcher 预留规则的尝试也被真实引擎拒绝；已移除，原 DSH 恢复。根因为 pinned singleton 的 full_profile 不含 path contains/suffix，且从空配置初始化，不读取 watch 规则来扩展能力。修复为检查真实 lowered ABI，候选保存为 invalid，UI 禁止应用；改用 `/w/0/.agentscope-context-canary` 后同一文档重新确认并实际加载。失败候选、应用记录和原代次事件保留。

系统继承验收最初附加“启动一定产生 exec notify 命中”的断言没有成立；两次试验均在 finally 中恢复原系统文档。保留失败运行／候选，后续验收改为分别核对多连接加载回执，以及明确驱动的固定文件读取匹配，不把加载成功作为命中证据。

## 边界

本次独立测试连接和固定探针没有替代原生工具 Trace。原生 DSH 的一次读取单独验证了 tool_start/tool_result，未提供可信工具内核标签，因此不强行关联其相近内核事件。旧原生会话与任务绑定缺失时不生成假关系。

## 生产会话界面混入测试别名和后台概念

复现：会话目录筛选显示“连接实例”和内部 ID，详情标题下展示旧的 RQ5 DSH 受控实例别名，且要求用户选择“运行代次”。根因：界面直接展示登记名称和运行隔离键，没有区分产品对象与后台证据主键。

修复：统一已知 Agent 产品名，以实时 PID 区分当前进程；隐藏测试别名、连接 ID 和运行代次选择；加入原生工作区筛选。停止的 Agent 不使用历史 PID，原生会话名称与真实路径不改写。未连接的安装占位项不作为会话 Agent 选项。保留后台隔离键与匹配校验，不按 PID 强行合并会话或历史事件。

验收：渲染回归包含带测试别名的登记数据、真实原生标题、多工作区、停止后的缓存；API 回归核对精确工作区筛选在分页前执行且停止后 agent_pid=null。浏览器核对四页、工作区筛选、返回保留、停止 PID 和旧链接均通过；当前 DSH PID 54870 与受控连接保持，详见 REVIEW 生产会话呈现修订验收。
