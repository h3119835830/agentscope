当时任务 `d5e21e674b464d16` 的 v7 编译加载回执中，`acceptance.txt` 只有一条 write 和一条 unlink 阻断。页面多条语句引用同一保护，因此不能据页面记录数量判定这个任务重复加载了规则。该观测仅描述 2026-10-06，不证明今日进程域状态。

问题影响是通用候选缺少等价与重叠关系分析，以及列表顺序或重复项可能被当作权限变化；不是已经证实发生越权、漏拦截或该任务重复加载。后者必须另有实际效果证据。

## 原因与整改

现有编译器负责解析、能力与结构检查，重名规则拒绝不等于语义去重。控制面 `render` 逐项生成保护条款，`validate_candidate` 部分比较仍依赖列表相等。详情层的规则片段整理不会改变实际策略包。

整改按 RFC 分阶段增加规则分析、简单等价复用、来源映射及审计关联。保持现有授权和启动底线校验，不能用分析器取代内核约束。

## 关闭条件

受支持的简单重复条款只生成一个执行身份；不同操作、权限、生命周期、条件和效果不误合并；顺序变化不触发虚假加载。范围重叠有准确关系或 unknown 标识。逐句来源、DSL、加载回执与审计均可追溯，真实 DSH 及独立内核探针回归通过。

当前已实现修复，自动化及真实验收进行中；完整关闭条件尚未满足，BUG 保持开放。

## B12 线程域表泄漏及旧可写能力清退缺口（已复现，修复复测中）

v7 支付会话29d038588efe41bc收紧后，探针PID647168仍持有acceptance-temp.txt的可写FD及共享映射；任务结束也未回收。文件哈希未变化，但清退不合格。已核验UID、启动时间和FD对象后用pidfd终止该遗留验收进程，证据保存orphan-holder-v7.json。

进一步独立复现：旧二进制执行20000个短线程后，cap_task占满16384项，其中16378项对应已消失线程；新进程没有域绑定并成功写入受保护验收文件。记录thread-check-old/result.json，旧引擎存在真实漏拦截，不得以旧会话的局部通过替代最终验收。

原因：fork为线程TID创建域条目，exit却只清理TGID。整改：只为新进程复制域状态，线程共享TGID状态，并清理遗留线程条目；不改DSL效果和规则匹配语义。另加入root-owned任务cgroup，清退独立冻结/终止整个任务组并核验空组；探针放行前核验真实cap_task绑定和cgroup身份。域表缺失时探针不得执行，不能将服务器声明的domain_id当作同域证明。

真实cgroup回归在故意返回空域成员列表时仍终止FD/mmap holder，内容不变；伪造cgroup路径拒绝。新引擎线程压力及全新六会话最终验收继续执行。
