# 会话策略域全零计数误导为策略停用

日期：2026-10-14。状态：修复、回归与 18003 发布验收通过，已关闭。

复现：正式实例 instance-1f4469579e8947f4 的原生会话 session-1e38fe17-5015-494b-92f4-a164b650bdf4 安全配置包含 17 项约束，但策略域页显示系统、Agent、会话均 0 条。运行侧 active=true、PID 1881572、执行门 open、protection_fresh=true，已批准策略保持执行；没有发生停用。

根因：会话安全面板改造时漏同步策略域计数。产品接口按过滤后的旧 DSL records 统计，丢失平台、结构化权限、网络和启动约束；原始域接口也沿用 DSL 口径。页面还将无局部执行能力显示为 0 条，缺少能力说明。

修复：两个域接口统一调用 security.domain_view，计数与安全面板一致，增加平台及工作区归属，区分无额外约束、无独立约束、独立应用暂不支持；不完整信息显示已取得数量或未知，不返回假零。前端使用服务端 count_label/status 展示，保留原目录折叠和精确会话身份。

验收要求：对比正式同一会话的平台 2 项、Agent 15 项和安全配置总数 17；独立能力不足不显示已停用。验证读操作和发布前后不改变策略、Agent 身份、Broker 和其他端口。定向后端 25 项、前端 279 项及构建已通过，全量及正式页面待补齐。

最终结果：后端 1210 passed、11 skipped，前端 279 passed。正式公开/原始策略域节点一致，平台 2 项、Agent 15 项，总数与安全配置 17 一致。空系统层显示继续继承；workspace/session 独立应用暂不支持。发布仅更换 API/UI 读模型，Broker、正式 Agent PID/代次/策略/域和系统/DSL 配置、18000/18004 监听均保持原样。
