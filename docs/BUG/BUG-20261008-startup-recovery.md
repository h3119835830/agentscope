# BUG：启动 Pi 失败任务缺少有效恢复入口

状态：已修复并完成真实恢复验收，2026-10-08。

## 复现与原因

原任务 0dae79b573f14bca 的启动 Pi 报错 `Pi settled without a server-validated submission`。具体失败涉及固定快照目标路径超过执行引擎 64 UTF-8 字节上限。前一轮新任务路径修复并不能自动恢复旧 context；旧页面继续调用 start 仍复用原固定路径，因此用户仍只能看见失败和空列表。

另有界面整页嵌套：ManagedWorkbench 在运行前嵌入完整 TaskRecord 后又渲染运行前列表，产生重复摘要和旧新版策略列表。task 与 archive 残留参数也未在任务切换时清理。

本轮真实恢复验收再发现：Pi 已提交成功，但 recovery 检查错误地要求 validation_json 重复包含 proposal 正文。生产 tools.submit 已将正文单独存储，因此待审核关联在生成完成后消失。最初测试用错误存储形状掩盖了该缺陷。

## 修复

新增严格的启动恢复 GET/POST 与持久关联；从旧可信上下文重建短路径快照，全部原约束和文件证据保持一致。候选复用校验正文 digest、摘要 proposal_hash、任务/上下文/作业、编译和待审核状态；兼容真实摘要形状，未放宽执行上限或审批边界。

前端移除重复旧列表，保留确认、来源、生成、版本和抽屉。旧页显示原因、恢复进度或查看恢复候选；串行轮询更新完成状态，错误撤销旧操作状态，切换任务清理 archive 选择。
