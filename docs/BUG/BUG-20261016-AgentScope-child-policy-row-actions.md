# 子配置必须进入详情才能操作及审批关联缺失（2026-10-16）

复现：六列子配置最后仅有详情，高频提交和停用必须进入详情；旧系统配置不投影审批 ID，即使提审后返回列表也无法准确打开该配置审批。已应用旧版另有新版草案时，操作核对还容易混淆参数版本。

修复：记录行新增提交审批、查看审批、停用，沿用独立详情；无审批 / 未应用 / 处理中状态提供明确禁用原因。服务端只读关联准确配置 ID、范围和版本，历史审批附版本信息，当前草案不沿用历史状态。停用预览实际已应用参数，冻结提交当前库版本，依旧先审批再显式应用。

验收：319 项前端及 1358 项后端完整回归、构建通过；三类作用对象 HTTP 流程覆盖批准不应用、无效收据拒绝、明确应用后仅移除目标和保留草案。浏览器真实只读页面核对及取消正常。正式运行策略未由本次测试修改。
