# BUG：探针登记文件受服务 umask 影响，API 无法读取

日期：2026-10-07。状态：源码修复、权限回归与真实任务恢复/结束闭环均已完成。

## 复现与影响

真实受管任务运行固定验证探针时，task_runner.handle_request 以 os.open(..., 0o640) 创建 .actplane/probes.jsonl。服务继承 umask 077，实际新建权限成为 0600。虽然之后设置 root:agentscope-task 所有者和组，但没有恢复组读位，API collect 无法读取探针登记并触发任务失败停止。

该问题属于可信探针登记传递边界，不是 Agent 能力问题。不能通过给 API 增加 root 权限、放宽整个任务目录或忽略证据读取错误绕过。

## 修复

task_runner.py 的 append_probe_record 使用受保护 .actplane 目录文件描述符和固定 probes.jsonl 文件名。目录与文件均使用 O_NOFOLLOW；文件打开增加 O_NONBLOCK 防止恶意 FIFO 阻塞，并验证普通文件、root 所有、单硬链接、无组或其他用户写权限。

通过文件描述符显式 fchown(root, agentscope-task) 和 fchmod(0640)，复核权限后追加并 fsync。该设置不依赖进程 umask，也能修复已有的合法 root-owned 0600 登记文件。既有内核绑定验证与探针 admission 次序不变。

## 验收证据与剩余闭环

以真实 root 身份运行 backend/tests/test_probe_registry_permissions.py，8 项通过。测试实际设置 umask 077，创建文件后以 stat 核实 root:agentscope-task 0640，并将读取子进程降为 agentscope-api UID 与任务组，确认其可以读取登记内容；不是源码字符串断言。

回归还覆盖已有 0600 文件修复，以及文件符号链接、FIFO、硬链接、非 root 文件、可被其他用户写入的文件和目录符号链接拒绝。
