日期：2026-10-04。状态：本次开发展示修复验收通过。

## 复现与定位

用户提供 18000 页面停在“连接 AgentScope”，显示 `Failed to fetch`，并明确要求开发阶段取消口令。该截图不能单独证明网络失败由口令错误引起。本次检查原 API/Broker 为 active；隔离 18001 的旧 PID 登记仍在，但对应服务未运行。旧页面不会自动发现开发模式，也会保留过期缓存身份。

## 处理

新增显式开发模式查询，前端自动清除旧口令并直接进入；不可达时显示重新连接。只修改受保护配置中的开发开关，不输出其他配置值。重启原 API，按已核对的进程状态恢复隔离 API/Broker，分别部署当前 UI。

隔离审计原先要求原页面没有 Pi 控件且两个 index hash 不同，在用户要求同时展示当前开发前端后不再适用；改为验证两个物理静态目录分离及各自实际响应与文件一致。历史 2026-10-03 报告不覆盖。
