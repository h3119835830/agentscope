# BUG：模板没有持久子配置，助手生成链路与手工参数配置脱节

日期：2026-10-14。状态：源码修复与隔离验收通过，正式发布结果见 REVIEW。

复现：旧“策略与模板”页面只有六个静态样例，参数候选通过客户端 DSL handoff；助手长期基线使用自然语言到意图/IR 转换。不能在同一静态模板下持久查看多个独立配置，也没有强制的模板 ID/版本填参入口。用户分别提出删除与修改限制时，界面未提供保留各自意图的子记录组织方式。

根因：静态展示目录、客户端模板物化、助手生成与系统配置库分别维护。模板 ID 主要用于展示/来源，未构成统一的不可变参数合同。把当前 write/unlink 的访问组别名隐藏在模板文案中，还容易将“只禁删除”误解为已实现精确内核区分。

修复：服务端发布合同和受限参数 API；每次配置创建独立子记录，编辑追加版本；手工与助手共用校验和实例化。新增模板在策略与模板页面显示，系统旧配置只读投影回原入口；保存和生成不加载。单操作意图保留，同时显示实际共享访问组并要求提交确认。模板/版本、资源映射、符号链接与重新校验绑定均重新核对。

验收：真实模型通过参数生成 API 保存同一模板下的删除、修改两条子配置；幂等重试无重复；手工对照一致；未知模板、自由 DSL、额外参数、越界目标拒绝；版本变化和重新校验后的再次变更均使旧审批失效。策略与 Agent 状态保持不变。

未解决：内核 write/unlink 仍共用访问组，当前不能声明精确分离；工作区/单会话独立应用仍不支持；提交前检查参数的事前 block 仍待运行时适配。本 BUG 的修复范围是模板实例与受限生成合同，不关闭这些底层能力边界。
