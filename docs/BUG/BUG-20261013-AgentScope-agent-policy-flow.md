# Agent 策略链路已复现问题与闭环（2026-10-13）

## 批准与应用混为同一操作

原页面和 confirm 直接触发加载，无法表达已批准待应用。新增决定回执、独立 approve/apply、服务端能力投影和待应用页签；旧 confirm 保留组合语义。真实批准前后两实例身份/配置一致；显式应用仅目标重建。单元覆盖并发批准冲突、增改删、重复请求、漂移及认证。

## 隔离环境误用生产来源缓存

不具备 /proc/exe 读取权限的 API 回退到写死的生产 cache，实验实例身份核验因此失败。修复为可信环境变量指定缓存路径，并启动独立 root 只读采样器。仍检查 root 所有权、8 秒时效、boot、generation、PID/start_ticks/domain/host；不绕过来源核验。独立 Agent 上下文在零原生会话时已通过。

## 源动作 schema 缺少 truncate

真实“只读且禁止截断”被正确拦在待补充，但原因是源动作枚举不能表示 truncate。补齐 schema，映射现有 file_mutate/write 组；独立校验继续保留 read，不新增模型特殊提示词或新钩子。修复后真实候选只有 block write，EPERM 与读取成功分别取证。

## 共享运行域事件误算会话命中

策略详情 hits 原先从同代 Agent 全部事件匹配，可能把未归因或其他会话事件标作本会话。新增 session_id 与 trusted_tool_tag 过滤，原 Agent 范围命中仍可保留。单元覆盖其他会话不得命中；真实事件 tag=0 时会话 hits 为空，内核证据独立保留。

## 应用中断与前置编译失败

仅保存 applying 记录不足以保证 API 重启后暂停。增加启动恢复，只调用已有门控/停止，不重新应用。前置加载失败也暂停精确目标；暂停未核验明确显示，不能自动放开或伪造加载回执。单元覆盖中断、前置失败、失败无自动重试，另一个 Agent 不受影响。

## 验收边界

草案生成/提交与引用写入之间也存在中断窗口。修复为持久化生成输入、固定提交选择并按版本恢复产物/提案引用；重试不能切换另一候选。补充恢复和模板未核验来源不能提交的回归，未宽松接受原文或改变执行权限。

最初原生探针两实例都返回 EROFS，来源是默认只读挂载。这一结果不构成 ActPlane 隔离证据；显式合成写授权后重新验收，A 为 EPERM/B 成功并取得内核匹配，才判定该项通过。最初模型证据定位失败保留为失败版本，不宽松接受非原文证据。
