# BUG：工作区切换与任务绑定混用，历史显示为长文档

日期：2026-10-07。状态：已修复并验收。

## 复现与原因

旧任务工作台点击“切换工作区”，实际打开受管历史任务选择；新建任务只能选择预设 RQ5 场景，无法先选择已连接 Agent 的真实文件目录。进入“任务与启动审核”又显示 BootstrapPanel 长篇英文候选、完整 DSL/JSON，与工作台的策略记录是两套界面。工作区、任务、Session 和策略版本混在同一选择动作中。

控制台把 task.workspace 当作来源选择和执行绑定的共同标识，没有独立的 Agent 工作区登记及任务来源关系。旧任务页复用研究验收文档面板，未按记录设计。

## 修复

- 新增执行端与工作区清单、真实文件扫描、来源 manifest 比较和任务快照。
- 工作区选择只用于新建任务的文件来源；任务列表只选择历史/执行对象，取消控制台自动选择和“切换工作区”语义。
- 普通工作区任务等待绑定哈希的显式策略确认，确认时及加载前复核文件与配置。
- 替换旧 TaskPage/BootstrapPanel 入口；历史使用任务字段、逐条策略、证据、生成及版本表。中文要求由类型化操作生成；原始描述与对应 DSL 在单条详情展开。
- 已建立 DSH 会话的执行目录可作为后续任务工作区，显示 Agent 更新后的文件；已结束任务不标记在线，目录缺失不删除历史。
- 修复返回列表被残留工作区选择带回创建表单的问题；初次读取期间显示加载状态，避免短暂误报未加载/无会话。

## 验收闭环

326 项后端回归、2 项前端检查及构建通过。浏览器真实完成连接、读取、生成、确认、运行和历史记录流程；DSH 修复验收项目，两个 unittest 通过，测试/配置及源目录保留。750 像素窗口、原支付任务历史和四个记录分页通过检查。证据与范围见同名 REVIEW。

旧支付任务的进程/文件权限核验失败属于原有运行故障，保留历史诊断；本次没有重新启动或宣布修复该故障。此次关闭的是工作区入口、任务来源和历史呈现混乱问题。
