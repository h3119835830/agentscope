# BUG / 设计缺口：策略管理分散及适用范围固定

日期：2026-10-15。

## 已复现的产品现状

在当前 18003 系统模块查看“系统策略”和“策略与模板”：两处仍有不同管理入口；已保存系统配置投影到模板子记录后提示跳回系统策略。源码模板固定 system 或 agent/workspace，无法用同一份通用参数合同选所有 / 指定 Agent。这是已实现阶段与本次新增设计的差距，未归因为 DSH 或 Linux 的工作区问题。

状态：开放，统一策略库及数据迁移尚未实施。整改需以 [RFC](../RFC/RFC-20261015-AgentScope-unified-policy-catalog.md) 的目标、单一写入口、迁移、授权和逐实例回执验收闭环；本轮没有把原型通过写成产品修复完成。

## 本轮原型修复

新增配置表单的保存按钮在预览宿主未触发草案动作，交互停留原表单；已改成显式局部保存事件，重测全局配置追加、审批及应用通过。草案编辑与等待停用曾共用当前记录状态，可能从有效视图丢掉旧规则；已分离独立活动快照，重测保持旧配置、批准不应用、停用成功再移除通过。

状态：原型范围已关闭，证据见[设计验收](../REVIEW/evidence/unified-policy-catalog-20261015/validation.json)。不能据此推断真实后端存在相同问题或已经修复。

## 明确未接入

Jev 实际模板推荐、通用模板跨范围迁移、统一全局助手入口、真实当前运行增量、原生工具审批及新增热更新能力均不在本轮交付内。不存在模型准确率、真实策略改变或 DSH 原生流程改造的验收结论。

## 子配置字段细化

原预览子行展示来源、版本、期限及完整参数，掩盖实际策略名与范围；现已将列表收敛为实际名称、所有 / 具体 Agent 和详情，模板新增与详情复用同一表单，13 项预览验收通过。正式应用尚未实施该调整；真实生成名称为空时的模板名回退仍需按新合同处理。本轮不将展示修订记为已接入真实场景提取。

## 用户否定原型与旧组合确认入口

前轮原型重复引入“让 Agent 配置”快捷入口且改动现有系统策略外观过多，用户已明确否定该视觉落地方案。设计已修订为沿用系统策略页、助手留在 Agent 页；正式应用改造仍开放。只读复核另确认旧 confirm 路径连续 approve / apply，主页面虽然已分开批准和应用，不能声称全部旧入口均完成收敛。后续整改需兼容调用分析、目标 / 版本冻结及显式审批应用验收；本轮不修改或调用该兼容接口。
