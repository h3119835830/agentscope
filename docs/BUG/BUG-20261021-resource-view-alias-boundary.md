# BUG：短路径适配的别名、fd 与上下文边界

日期：2026-10-21。状态：代码整改，隔离验收闭环；主服务未发布。

## 已复现问题

1. 初版通过 /proc/self/fd/N 作为 bwrap bind 来源。真实隔离 payload 枚举到额外继承的宿主来源 fd；路径策略可能无法约束持有的宿主句柄，不能上线。
2. 父目录拒绝若重新 ro-bind 宿主父目录，会抹掉规范链接并重新暴露子树路径。
3. 原会话对象绑定按 /w 字符串前缀判断；增加 /v 规范挂载后，同一工作区文件会被误认为越界或错误计算宿主 inode。
4. 跨独立挂载的父目录通配符若只做单次路径替换，会遗漏分流子树。

## 修复

- 逐组件固定来源，使用 bwrap bind-fd/ro-bind-fd 消费描述符；Popen 后父进程关闭全部描述符；真实 payload 的额外继承 fd 必须为空。
- 投影父目录拒绝使用 remount-ro，并将祖先 read/write deny 扩展到所有分流挂载。
- 旧路径/相对路径/规范路径统一回到登记宿主资源，核对会话宿主范围与 inode，再输出规范执行路径；工作区外目标继续拒绝。
- 应用层 DSL 适配器拒绝有歧义的跨挂载父目录模式，不修改上游编译器。
- 启动 canary 增加所有规范挂载，补 readonly 项目根检查。
- 写目录拒绝符号链接、既有硬链接、特殊文件，目录替换会使审批失效。

## 验收与剩余问题

确定性用例覆盖人工审批与显式应用分离、实例/代次/身份漂移、原路径与短路径、越界拒绝、父目录保护、测试不变及 fd 无泄露。真实原生 kernel 合成实验与隔离界面证据见本日 REVIEW。
