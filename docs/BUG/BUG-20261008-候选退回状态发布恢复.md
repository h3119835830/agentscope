# BUG：候选退回作业与状态发布间的恢复窗口

日期：2026-10-08。状态：故障注入已复现并验证修复，独立复评与完整后端回归通过。未在真实 RQ5 任务触发该故障。

## 问题与影响

新待确认候选退回接口先提交包含事实反馈及 retry_of 的生成作业，再在另一事务发布 managed startup_job 和事件。后者 save 失败或 API 崩溃时，作业可能已经持久化，但界面仍指向旧待审候选。原候选、上下文及执行权限未变，不得把该窗口说成整体原子成功，也不能无依据再次启动模型。

## 整改与边界

按精确 task、旧 job、候选与上下文双 hash、反馈类型唯一关联已持久化新作业；发布失败/重启后恢复同一作业指针与幂等事件。启动和确认前先协调，防止旧候选在新的事实重生成请求已存在时继续确认。没有唯一可核验关联则保持拒绝，不跨任务、不猜测、不删除作业。

须覆盖队列提交后状态保存失败、重启恢复、终态作业恢复、重复请求以及旧候选确认拒绝。实现与故障注入结果后续追加，不声明已真实故障恢复或权限加载验收。

## 修复验收

瞬时和持续 save 失败、重启扫描、重复请求、queued/running/四种终态、旧候选确认、损坏/重复 lineage 与不同 reason 冲突均有专项覆盖。退回 70 项与失败重试 40 项联合通过；完整后端 865 项通过。状态和两事件单事务发布，不声称队列加状态整体原子；持久作业唯一关联可恢复。主 startup 在 workers 启动前协调，安全摘要不记录反馈正文或凭据。独立复评通过。
