# 工作区任务入口缺少先读后识别

状态：已修复并验收。

复现：在策略工作台选择包含 task.md 的工作区，任务名称与目标均为空，旧 TaskHub 按钮禁用；原 API 和 registry.create_task 也要求两项手填。Pi 仅在任务创建后读取材料，因此无法替用户先读取任务说明。

同样复现的无目标场景：工作区 423a957c41f2b7be 的 README 仅说明本地工作区返回验收夹具，不能据此编造修复任务。

修复：先建立只读场景识别作业；Agent 实际读来源，自动名称并返回目标、约束、依据；缺目标才补充。确认采用后继续现有策略生成与人工审核。不会自动启动 DSH 或授予写权限。

验收结果：有目标RQ5与文本统计工作区由真实Pi读取后ready；无目标README先needs_clarification，补充一句后ready。三个独立读取作业前后权威任务、策略、凭据、执行记录计数不变且原生PID未变。唯一采用、409重复/过期/hash、404跨工作区、refresh仅GET和423px已回归；详细回执见REVIEW-20261007-workspace-scene-read.md。
