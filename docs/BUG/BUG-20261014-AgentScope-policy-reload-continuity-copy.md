# Agent 文档停用弹窗错误暗示应用全程连续执行

状态：开放；本轮只读核对发现，未修改页面或运行逻辑。日期：2026-10-14。

## 已确认问题

当前部署同源前端 `frontend/src/ActPlanePolicies.jsx:102` 的“停用策略文档”确认弹窗显示：“下一步查看差异、人工批准，再单独应用。重新加载核验完成前，当前策略继续执行。”后一表述把候选/批准阶段与应用阶段混淆，可能让用户以为正式点击应用也不会中断 Agent。

实际 `instances/dsl_policy.py:159-195` 关闭 Broker 门禁，等待已登记租约最多 8 秒，停止旧执行器，保存文档后仅重启原本运行的实例，全部加载核验通过才开放。审批详情的应用阶段页脚已提示“暂停并重建受影响实例”，但前一弹窗仍有矛盾表述。已保存的 18186 隔离停用实验确认旧 PID 退出、新域加载，见 [验收](../REVIEW/REVIEW-20261014-AgentScope-policy-controls-and-session-names.md)；本轮没有停用正式策略进行复现。

## 影响与正确表述

待审批、已批准但未应用时，现行保护继续执行。显式应用时会暂停并重建受影响运行实例，影响全部原生会话/子进程；已停止实例不会自动启动。不能承诺在途任务无中断或自动续跑。

建议文案：“停用候选与批准不会改变当前保护。确认应用时会暂停并重建受影响运行实例，核验通过后恢复。”在批准和应用前均展示运行/停止实例数及影响范围。

## 关闭条件

1. 修正文案，明确候选、批准、应用各阶段，不能把“继续执行”覆盖重建阶段。
2. 在正式只读页面检查原有正常/异常状态与窄屏布局；增删停用的实际执行仅在隔离实例验收。
3. 若未来改为无重启加载，须有独立实现、内核效果和失败一致性证据，再修改此合同，不能仅调整表述宣称热更新。

本轮不执行修复发布，不改变当前候选、批准回执、策略或 Agent 运行状态。
