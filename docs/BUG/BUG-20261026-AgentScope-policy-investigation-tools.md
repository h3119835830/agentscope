# BUG：目录参数形式合法但实际不覆盖子文件

日期：2026-10-26。状态：已复现并完成隔离修复验收；未正式部署。

## 复现
基线 actplane-test-gate 要求 src 与 tests 内任一文件变化使旧检查失效。模型填写 /w/0/src 与 /w/0/tests；用户进一步说明递归目录范围后仍输出相同参数。真实编译后匹配函数对子文件及嵌套文件均不匹配；独立递归对照匹配成功。原记录不修改。

## 原因与边界
输出错误确定，但不能只归咎模型。原场景仅有说明文件、缺少真实源码目录；参数工具把所有类型降成字符串，目录匹配语义不足；工具返回 validated=true 仅表示参数合法，却没有效果验证反馈。不存在该次文件读取权限拒绝。权限、上下文和工具合同需分别评估，不能把所有失败说成模板不足。

## 修复
补项目搜索、资源检查、真实编译匹配预览；工具 Schema 保留真实类型。原生 Pi 不得用未预览或失败预览的候选完成提交，参数修改需再次验证。不得自动替换模型结果、静默扩大匹配范围或加入该场景专用提示词。

## 验收要求
保留原失败，覆盖字面目录漏匹配、递归匹配、正负样本、操作分组、参数变更后旧验证失效、边界拒绝与真实 Pi 工具循环。迁移 open+lineage 模板缺口、云盘/邮件执行适配缺口须继续如实报告，不能以本修复宣称已支持。

## 实测闭环
首轮 e1 暴露“只要匹配了模型自选样本便提交部分结果”的不足：猜测目标，以及最终集合遗漏已验证候选。新增目标事实绑定与累计正向覆盖账本后，e3 在相同原场景上输出两条正确递归范围；抽象迁移和外部对象场景保留空候选与缺口。真实源码定位与目录检查亦通过。独立编译/匹配回放通过，1618 项后端测试通过；原失败与首轮新失败全部保留，未手工改正模型结果。
