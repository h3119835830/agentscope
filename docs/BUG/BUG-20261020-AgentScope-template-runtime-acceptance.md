# BUG：模板能力信息不完整与历史 Git 入口残留

## 已复现

1. 非 Git 模板详情没有统一运行能力/限制事实，编译结果容易被误认为已做运行验收。
2. 历史 Git 模板仍可通过直接保存/编辑接口新增或更新；旧检查默认 block git commit 不支持，且旧检查条件不校验成功退出码。
3. 原始 ActPlane CLI run 接受不支持的 argv block，真实 git commit 仍成功且 HEAD 改变。现有 AgentScope Broker.compile_policy 会检查 backend_support 并拒绝该子句。此为上游执行边界，本次未改 ActPlane。
4. 网络 kill 确实终止匹配子进程，但独立接收端已接受 TCP，不能承诺事前拒绝。

## 修复与验收

所有模板的详情由服务端展示支持、暂不支持、执行边界及真实运行/拒绝验证记录。旧模板和旧子配置只读，服务端禁止新增、编辑、重新提交/校验/应用；已生效配置保持，批准后单独应用停用的路径继续可用。旧检查实测失败检查仍满足旧 gate 的结果保留为历史缺陷说明，不修改旧 DSL。

164 个独立引擎用例覆盖 33 个有 DSL 的模板（含 2 个历史兼容对象），另外 4 个无 DSL 的模板测试草案、单项/批量提交及重新校验拒绝。原始 CLI 的反例与真实 Broker 拒绝结果均保存在 rejection-results.json，不把反例包装成成功拦截。

第一次验收脚本错误地要求 kill 没有建立网络连接，已依据独立接收端结果修正动作合同并明确显示该限制；两个脚本曾并行触发 CLI singleton drain 保护，已串行重跑受影响用例并加入验收专用互斥锁。preliminary-results.json 保留初次失败，最终清单引用复验结果。
