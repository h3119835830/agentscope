# BUG：RQ5 最小写权限缺少入口且当前布局超出表达能力

日期：2026-10-20。状态：人工申请入口已实现；场景授权阻塞未闭环。

原系统只有 DSL 管理，没有将实例默认只读基线调整为精确子目录写权限的客户入口。
已新增准确 Agent 的目录写权限人工申请；只提交现有审批合同，不自动批准/加载。

代码核验还发现：

- policy.canonical 与 Broker protected_targets 均只接受每个资源根一个连续可写范围。
- 原生 Clause.unless 只允许单个目标条件；多条阻断叠加不能表达多个允许区间的并集。
- RQ5 实际深层执行路径超过 63 字节时被 path_parameter / canonical 拒绝。

安全处置：不改核心，不开放共同父目录，不修改测试，不截短路径；
拒绝请求不得改变 policy_hash、generation、运行进程或已有保护。
此入口并未解决两个独立可写目录在当前映射中的表示问题，不能标记该场景授权通过。

界面发现的新回归：初版只添加原 API GET，前端统一映射到 console GET 后返回非 JSON 页面。
已补 console 可见性检查投影，并将产品 URL 纳入后端验收；第二轮界面结果见本轮 REVIEW。
