# 会话缺少名称且进程展示无法直接对应

日期：2026-10-09。状态：已复现、已修复、正式 UI 与接口验收通过。

原“会话与进程”同时堆叠资源目录表、无名称的会话表、新建会话控件和全实例进程表。用户难以直接判断哪个会话对应哪个 PID；另一个“实例与进程”弹层重复连接记录，缺少会话名称。根因是原生桥接未投影名称，前端又按底层数据来源拆分展示。

修复为名称、完整 ID、状态、对应 PID 的单一表格，移除重复弹层与入口；保留全部受控连接的配置可达性。DSH 名称从原生只读接口取得，并按原会话与目录双重关联；已保存会话不借用运行实例 PID。

候选验收覆盖 7 个真实 DSH 会话，2 行共享 PID、5 行无运行进程。未命名会话保留未命名说明。未连接 Hermes 不填充 DSH 进程。正式 API 与页面已核对相同的 7 个会话及 PID 关联，11 项正式浏览器检查通过；423/320px 复验通过。详见 REVIEW。

此修复只涉及会话元数据与界面，不关闭任何内核保护、策略执行或权限回收问题。

## 2026-10-10：会话缺少项目工作区，连接历史界面冗余

用户截图中 DSH 会话表只有名称、ID、状态与 PID，无法分辨共享执行器下的会话属于哪个项目；连接历史页签不符合当前简化需求。

只读核对当前 sessions 接口后发现工作区映射已存在：7 条会话中 3 条属于 /s/instance-resources/second-dsh，4 条属于 /s/instance-resources/rq5-dsh。原页面遗漏了 resource 展示，不是接口缺失，不需要重启 DSH、创建会话或改变提示词。

修复：会话表增加目录标签与完整路径；Hermes 隐藏该列，其他有目录数据的 Agent 可显示。已保存会话不借用实例 PID。移除当前/旧工作区界面的连接历史内容、页签及任务详情跳转，旧历史 URL 回到当前连接；保留审计数据与接口。

验收：165 项前端测试、Vite 构建、4 项实际浏览器检查通过；DSH 7 条会话路径与接口逐 ID 一致，Hermes 暂停状态下列头为 4 列且无工作区，旧 URL 正常回退；默认 1007px 视口无页面横向溢出，表格自身可滚动。未验收新的窄屏视口或运行中的 Hermes。发布前后 DSH PID=1343、generation、policy_hash、domain_id 与 API/Broker PID 均保持。详见 [验收](../REVIEW/REVIEW-20261010-session-workspaces.md)。
