# 会话缺少名称且进程展示无法直接对应

日期：2026-10-09。状态：已复现、已修复、正式 UI 与接口验收通过。

原“会话与进程”同时堆叠资源目录表、无名称的会话表、新建会话控件和全实例进程表。用户难以直接判断哪个会话对应哪个 PID；另一个“实例与进程”弹层重复连接记录，缺少会话名称。根因是原生桥接未投影名称，前端又按底层数据来源拆分展示。

修复为名称、完整 ID、状态、对应 PID 的单一表格，移除重复弹层与入口；保留全部受控连接的配置可达性。DSH 名称从原生只读接口取得，并按原会话与目录双重关联；已保存会话不借用运行实例 PID。

候选验收覆盖 7 个真实 DSH 会话，2 行共享 PID、5 行无运行进程。未命名会话保留未命名说明。未连接 Hermes 不填充 DSH 进程。正式 API 与页面已核对相同的 7 个会话及 PID 关联，11 项正式浏览器检查通过；423/320px 复验通过。详见 REVIEW。

此修复只涉及会话元数据与界面，不关闭任何内核保护、策略执行或权限回收问题。
