# AgentScope because 反馈技术决策

日期：2026-10-11。状态：已采纳并实现，两个真实 DSH 场景验收通过；仅发布到隔离 18005 实验实例，未推送。关联 [RFC](../RFC/RFC-20261011-AgentScope-because-feedback.md)。

| 决策 | 理由与取舍 |
|---|---|
| 保持现有 ActPlane DSL 与内核 ABI，because 作为可独立阅读的指导，RecoverySpec 放在获批包元数据中 | 复用现有 reason/Hook；结构化步骤可校验。代价是需要管理文字与元数据的一致性和版本 |
| 反馈事实由可信事件提供，指导由获批元数据提供，LLM 不裁决 blocked/killed | 避免伪造阻断或自动授权；动态解释必须注明证据性质 |
| 原边界正确时走 no_change 指导快路径，Pi 只处理新证据或候选 | 降低不必要生成和执行域重建；缺失指导时仍需保持边界并澄清 |
| 使用持久 outbox、至少一次传输与幂等上下文接纳，分开 offer/persisted/context_admitted | 对崩溃与后台迟到可恢复，不虚构跨进程 exactly-once；接纳不等于模型采纳 |
| 未接纳必要反馈时暂停后续工具分派，保留 OS 保护 | 防止旧批次继续；必须解决 SDK 批次与 post-hook 死锁，不能简单延长 execution lane 锁 |
| 权限或继承边界变化仍经人工确认与原有可信应用编排 | because、Pi 建议和普通 Agent 回执不构成授权；替换域后重新核验 |
| RQ5 安全保持、合规恢复、功能完成分开统计 | 合理升级可算恢复，不能冒充功能完成；原始 oracle 与补充检查分开报告 |
| 保护对象复用 scene 的映射清单，不按 basename 或 tests/** 重新猜测 | 覆盖根目录副本与短路径映射；新增目录级限制需展示并审核 |

未采纳：每次失败补专用系统提示词；让执行 Agent 自行关闭规则；每次拒绝都调用 Pi；仅以 EPERM 或模型自报作安全证据；用原始 oracle 指导模型；宣称所有共享原生会话具有独立域。

设计阶段仅编写方案、运行离线验证与既有行为复现。实施阶段已修改反馈链路并启动独立实验实例，未重启共享实例、未推送远端。

新增采纳决策：以 ActPlane 实际 accepted append 审计的 rule_provenance 关联子域规则；校验逐条编译子句而不猜测 rule_id 偏移。为固定 RQ5 场景登记预授权保护集合，拒绝自动加载集合之外的限制，避免把需要修复的实现变成只读。两项决定分别由真实运行中的规则编号重排和过度保护候选触发，保留失败记录，不以调整提示词掩盖问题。

最终依据：测试场景 551 → 556、清理场景 587 → 591 均完成内核事实到原生上下文接纳，后续实际修复实现/删除缓存；独立原始 13 项测试全部通过，全部 8 个受保护原件不变，策略和执行域不变。后台事件 710 通过同一 outbox 和幂等接纳机制，原生磁盘 context 记录独立核验。详见 [验收与局限](../REVIEW/REVIEW-20261011-AgentScope-because-feedback.md)。

当前 v1 将 RecoverySpec 固定在获批候选与每版本 recovery bundle 中，没有独立元数据热更新接口；额外保护也不能通过固定场景自动加载合同直接覆盖，须另行评审合同。对超长反馈不截断禁止项，投递失败保持屏障；分页为后续能力。上述取舍保留可审计边界，也意味着完整发布前仍需异常投递容量与真实 kill/notify 故障验收。

## 2026-10-11 增量决策：默认原因与原生 Skill

采纳：系统目录按规则提供具体默认原因，已保存用户原因与原始 DSL 保持优先。默认只进入编辑候选，不静默修改当前策略。取舍是已有配置不会自动获得新文字，须明确编辑并确认应用。

采纳：新增可选 atoms[].feedback，独立于 statement 和证据适用性 reason；旧候选缺省兼容。反馈与可信恢复元数据在哈希前组合。运行时 explanation 仍只是候选评估，避免将解释误当作已批准原因。

采纳：Pi 原生显式 Skill 加载与命令展开，环境发现保持关闭，使用固定只读挂载、哈希和原生发现/上下文校验，无需增加通用文件工具。代价是绑定 Pi 1.0.1 的 get_commands/get_messages 和 /skill 合同，升级须复验；只在内存比较公开 user 输入，不落盘模型输出。

未采纳：只写无法被 --no-skills 运行时加载的文档；把适用性 reason 直接发给执行 Agent；让 Skill 改变权限；用目录覆盖用户配置；未经整合替换其他任务使用的共享发布目录。

## 2026-10-11：共享实例整合、编号与验收结论

采纳：从实际在运行的 API、Broker 与静态 UI 分别识别来源，以完成的 b2a62d8 合并保留审批进程/来源会话定位；使用唯一 95 号 systemd drop-in 发布整合版本，保留旧指针和静态资源；切换前用源码/UI/策略/服务快照进行比较，避免覆盖并行任务。回退只恢复本次指针与 UI，不覆盖共享数据库新记录。

采纳：内部模板 ID 继续兼容，产品展示与新 DSL 使用中文名称/用途规则名，研究原点单独保留；已保存反馈原因不自动被新默认值替换。采纳：真实 DSH 的安全反馈闭环与业务功能结果分别验收。原生上下文接纳和独立磁盘记录是本次即时 post-hook 反馈的证据；没有后台反馈 persistence ACK 时不伪造该事件。

不采纳：把安全原始 oracle 的 0 分等同于任务完成，或把这次修复场景的 10/13 写成全部测试通过。原始测试剩余 3 项失败保留，Agent 已在不修改保护测试的路径上继续执行并报告未解决问题；尚不能认定完整功能修复完成。

不采纳：通过调整业务提示词让 Agent 特判本次规则。初始只读回合的原生提问等待、排队消息和验收脚本重发单独记录；本次重发造成两个诊断回合，重复诊断不属于自然攻击率样本。验收脚本改用固定原生 request_key，避免后续重试形成第二条请求。
