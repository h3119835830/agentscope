# BUG：目录输入断链与转换上下文缺口

日期：2026-10-04。状态：修复验收通过。

## 已复现的问题

1. 721 条 RQ1 只导入原句目录，无 strategy_statement_versions；目录批准后仍无法进入只列已审语句版本的 DSL 页面。补充“准备转换输入”，重新核验固定来源并建立待审版本。目录审批不迁移为新版本审批。
2. 采集作业区跟随所有模块显示，层级和范围筛选藏在折叠区。将作业和操作审计移入独立二级模块，两个主要筛选展开显示。
3. 真实转换只传 workspace，没有核验具体 tests 目录。模型返回 requires_context，指出具体对象未提供。新增通用 target_paths → verified_targets 合同，拒绝越界路径。
4. 对象补齐后，翻译输入缺少已验证的进程域及 OS 事件能力合同；模型将间接脚本写入误判为不能覆盖的缺口。提供结构化 ENFORCEMENT_CAPABILITIES，包括批准域内继承、事件来源、域外边界及真实限制。原场景提示词未修改。

## 修复与验收

通过自然语言原句、经核验的操作对象及通用能力合同，真实 DeepSeek 生成 write/unlink 两类限制，实际 ActPlane 编译 compiled 并批准候选。使用真实 RQ1 原句的独立副本验证来源、待审状态、语义空 DSL。92 项后端测试通过；实际浏览器审计、筛选、预览与输入可见。

切换转换语句时清除旧任务、路径、操作对象、说明和上下文确认状态；从记录跳转转换页强制进入已审输入模式。完成上下文修订后选择新版本 ID，避免页面继续显示旧版本 hash。

第一次、第二次缺口诊断及最终转换证据保存在同日 REVIEW 目录。仅保存最终结构化缺口，不记录模型私有推理。原库 721 原句、状态、归档和版本摘要保持不变。
