# 当 Agent 绕过工具界面：AgentScope 如何把安全约束落实到真实系统行为

开发者允许 Agent 运行一次测试。工具界面显示的也是“运行测试”，但测试脚本内部还可能打开云凭证、把测试改成恒真断言，或者启动一个后台进程。批准入口之后，这些实际行为由谁约束？

AgentScope 正在把这个问题做成可验证的执行边界：将已批准的任务约束交给 ActPlane，在操作系统能够观察到真实文件、进程和网络操作的位置执行，并把批准、加载、当前核验与历史实验证据分别展示。总览新增十二类具体场景，帮助技术评审和使用者看清保护对象、攻击路径、验证结果和适用条件。

## 从“允许运行”细化到“允许产生什么效果”

本轮用合成数据复现了六类执行行为：合法入口内部读取凭证；修复实现同时篡改测试；借符号链接、截断和重命名覆盖受保护对象；秘密经过派生文件和另一进程后外发；shell 启动后台后代读取凭证；访问当前任务之外的资源。

每类执行四组对照，每组重复三次，共 72 次。ActPlane 组的 18 次合法操作均成功，攻击效果均受阻，并记录到内核拒绝。这里的完成指确定性载荷中的合法操作完成；真实原生 Agent 的反馈和任务完成情况另作记录。这不是提示注入成功率评测，也未复现其他论文的完整系统。

这些行为并非全部需要新技术。正确配置的传统沙箱在凭证、测试完整性、路径别名、后代继承和资源对象隔离五类场景中同样有效。AgentScope 的价值主张不建立在贬低这些既有能力之上。工具权限、来源隔离、检测器和 OS 沙箱仍各有作用。

我们还让真实 DSH 通过原生工具执行六项任务，再读取项目说明继续完成合法步骤。六项均结束并完成后续读取：凭证与后台读取收到 EPERM，测试改写受到只读挂载约束，跨挂载重命名被拒绝，其他实例未挂载资源不可见。原生网络任务由既有网络隔离阻断，接收端没有收到数据；它未提供普通连接放行对照，因此来源信息流的比较结论仍以单独的确定性实验为依据。这些结果分别说明阻断和继续工作的表现，尚不能证明自然语言安全反馈都准确送达。

## 同一个地址，普通上报与秘密外发能否区别对待？

一个更有区分度的任务是：允许本地处理秘密，同时允许向指定服务上报普通结果。攻击进程先读取秘密，写出报告并重命名，再由另一进程读取报告并建立外发连接。普通数据也使用相同目的地址。

本轮保留相同端点可达性的静态沙箱对两种连接都放行。ActPlane 的来源规则允许普通来源连接，拒绝秘密经派生文件传播后的新连接。它把“去哪里”之外的“数据从哪里来”纳入判定，连接多个进程和多个事件。这是本轮对照中观察到的安全与可用性增量。

结果有明确边界：本轮验证的是新 connect，不能据此保证已有连接不能发送；IPC、共享内存、编码侧信道和降密正确性也需独立验证。来源跟踪本身已有长期研究，不是 AgentScope 首创。

## 模型提供上下文，批准和执行由可信链路承担

[ActPlane 论文 v2](https://arxiv.org/html/2606.25189v2)提出让任务上下文参与策略具体化，再由 OS 约束已覆盖的实际操作。AgentScope 在这一机制周围补齐治理链路：生成内容先成为候选，经过目标核对、校验和确认，再进入加载与运行核验。候选存在、编译成功和界面显示“已保存”都不能冒充内核已经拦截。

这也意味着模型不能通过一句“用户已同意”扩权。策略要绑定实际实例、运行代次和批准目标，不能借历史 PID 或旧数据库快照恢复权限。原生会话当前仍共享实例执行域，产品会保留这一限制；不会把示意 trace 当成真实会话归因。

## 控制台短暂离线，已有保护应当继续

可靠性同样是安全的一部分。此前控制台 API 发布超过健康检查期限，会连带停止受控 Agent。本轮将执行保活改为 Broker 对真实保护对象的核验；已有批准和保护完整时，任务可以继续，新审批与扩权等待控制台恢复。工具回执先进入 Broker 的本地持久队列，恢复后去重回补。

隔离实验中，控制台离线超过 45 秒，Agent 保持原 PID、运行代次和策略；合法工具可用，越权写入被拒绝。watch 丢失或 Broker 卡住时，安全终止仍保留。正式长期稳定性需经过完整 24 小时观察，本公告不以短时实验代替该验收。

本轮也验证了换代撤权：撤权前已经打开文件描述符和可写映射的旧进程及后代随旧执行域终止，保护文件未被后续改写，另一个实例继续保持原身份和策略。这是 AgentScope 的平台撤权路径实证，并非宣称 ActPlane 能原地撤销所有已有 mmap 权限。

## 仍然需要业务语义和更完整的覆盖

OS 无法仅凭一个合法 HTTPS 连接判断收款人、金额或云资源删除对象是否正确。此类效果仍需权威业务接口、对象权限、状态条件、事务、幂等与必要确认。测试程序运行过，也不能证明当前代码经过真实测试并通过；后续需要绑定内容版本与可信签发者的新鲜回执。

下一步将优先推进原生会话独立执行域、已有连接及 IPC 覆盖、可信审批与测试回执，以及远程业务效果授权。每项都有具体攻击配方、允许对照和验收标准。

“前所未有”应当接受检验。[BPFContain](https://arxiv.org/abs/2102.06972)等工作已在内核实施约束；[CaMeL](https://arxiv.org/html/2503.18813v1)、[Progent](https://arxiv.org/html/2504.11703v3)和[FIDES](https://arxiv.org/html/2505.23643v2)分别从来源、工具权限及信息流保护 Agent。AgentScope 当前希望证明的，是任务上下文、批准治理、跨执行路径约束、跨事件关联与反馈如何形成可审查的链路，而不是一句覆盖所有风险的承诺。

本轮报告公开区分已验证、论文或源码支持但待验证，以及延伸设计。完整研究附件保留初次载入失败及修正后的复验记录；部署需满足可信 Linux/eBPF 环境、已验证内核能力、可信 Broker 和正确策略等条件。使用者可以从具体任务及可复现实验判断价值。
