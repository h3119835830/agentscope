应用日志之外：AgentScope 如何追踪并约束 Agent 的真实行为

看见应用日志遗漏的行为，关联跨进程风险。
让内核侧的策略执行可审计、可反馈、可监控。

一个 Agent 应用完成了本地报告，应用日志记录着任务启动、报告生成和执行结束。在这些记录之间，第三方组件可能读取了凭证，脚本可能启动了后台进程，敏感内容也可能被写入另一份文件，再由另一个程序发送出去。任务级日志并不一定完整呈现这些内部操作。

AgentScope 以 ActPlane 为内核侧策略执行基础，把已批准的任务约束落实到受管进程实际发生的文件访问和网络操作上。它关注应用入口之后的真实行为：哪个进程访问了什么对象，操作是否符合授权，命中了哪条规则，以及应当如何处置。围绕这些关键事件，执行过程可以被审计、反馈和持续观察。

场景一：测试照常启动，插件却在读取凭证

开发者让 Agent 运行项目测试。测试框架加载第三方插件，插件在初始化时尝试读取本机云凭证。用户批准的是测试任务，凭证文件并不因此成为插件可以使用的资源。

应用日志可能只记录测试入口和执行结果；插件内部的读取也不会自动产生一条新的 Agent 工具调用。内核侧检查的是实际文件访问，因此即便读取发生在合法测试进程内部，仍能按凭证保护规则作出判断。

在对应的行为验证中，项目文件读取成功，合成凭证读取被拒绝。这里的价值是把允许运行某个程序细化到它可以访问哪些资源，减少第三方组件隐藏在正常任务中的越界空间。

场景二：脚本启动了后台进程，约束也要跟过去

一个构建脚本先调用 shell，再启动后台 Python 程序。后续文件访问由后台程序发起，而应用的任务记录可能仍只有顶层脚本。一个阶段已经返回结果，也不代表它启动的每个后代都已停止。

如果保护只围绕应用入口检查，解释器切换和后台后代就容易成为观察缺口。AgentScope 将受管进程与执行范围关联，使后代进程的实际访问继续接受对应规则检查。在后代进程验证中，合法项目读取成功，后台程序读取凭证被拒绝。

这让约束能够覆盖程序真实展开的执行路径。应用可以使用脚本和子进程完成工作，同时保留对敏感资源访问的控制。

场景三：写的是项目路径，碰到的却是受保护文件

Agent 准备修改项目目录中的一个文件，但这个文件其实是符号链接，指向受保护的测试。另一个变体先生成新文件，再尝试通过重命名覆盖原测试；还有脚本会直接截断文件内容。

应用参数中的路径看上去正常，真正受影响的对象却可能已经改变。内核侧的访问检查把判断推进到实际对象与操作，分别处理写入、截断和重命名等行为。对应验证中，允许的源码修改成功，这些针对受保护测试的变体被拒绝。

这种保护对代码修复、配置维护和文件处理都有直接意义：看见一条看似合法的路径，还需要检查它最终会改变什么。

场景四：报告换了名字、换了进程，仍带着秘密来源

一个分析任务获准在本地处理机密材料，也可以向指定服务上报普通结果。进程 A 读取秘密后生成报告，将报告重命名；随后进程 B 读取这份报告，准备连接同一个上报服务。

单独看这些动作，读取文件、生成报告、重命名和连接服务都很常见。风险来自它们的组合：原本仅限本地使用的内容，经派生文件进入另一进程，准备越过外发边界。任务级日志或只看目的地址的规则，容易遗漏这段数据来源关系。

ActPlane 的来源规则将文件来源及其派生传播纳入判断。在本轮同地址对照中，普通来源的新连接成功；秘密经过派生文件、重命名和另一进程之后，新建外发连接被拒绝。这样可以同时保留正常上报能力，并对秘密来源作更细的约束。

这是内核侧关联的一个具体价值：让数据从哪里来参与安全判断，使多个进程、多个操作组合出的风险能够被识别和约束。

场景五：允许修复源码，验收依据仍要保留

Agent 被要求修复实现。一个偏离任务的脚本却可能把失败断言改成永远成立的条件，或者直接删除测试，让结果看起来已经通过。

只记录修复脚本执行过，难以说明它究竟改了实现还是改了验收标准。将源码和测试分别授权后，同一个进程可以修改允许的实现文件，同时被禁止重写或删除受保护的测试。对应验证中，源码写入成功，测试改写和删除被拒绝，测试文件保持不变。

这种约束保护的是任务的验证依据：Agent 仍有完成修复的空间，原有测试不会轻易被同一条执行路径改掉。

内核侧执行，可以审计、反馈和监控

可审计。 命中规则的事件可以保留时间、进程、目标对象、匹配规则及处置结果。审查者能够核对一次越界操作实际发生在哪里，以及它为什么受到约束。任务入口与真实资源操作之间，因此多了一层可检查的执行证据。

可反馈。 被拒绝的访问或连接会向发起操作的程序返回明确结果；内核报告的事件还可以结合用户态规则说明，整理为可读的安全反馈。应用或 Agent 可以据此选择获准资源和合法路径，人员也能核对拒绝原因。反馈把安全处置转化为执行过程中可以处理的信息。

可监控。 运行期间可以核对受管进程的保护绑定，观察规则命中与处置结果，使当前策略与实际执行对象保持对应。保护状态和关键违规事件能够被持续检查，便于发现任务过程中的异常行为。

这三种能力把约束落实为可检查的运行过程：决策有证据，执行有返回，保护状态可以观察。

从任务授权，走向真实行为的安全控制

应用层权限与日志负责表达任务和业务意图，内核侧约束补充程序内部关键操作的可见性与执行控制。AgentScope 希望连接这两个层次：把任务允许做什么，落实到程序实际可以访问什么、后代进程可以继续做什么，以及哪些来源的数据可以建立外发连接。

在采用合成数据的六类场景、72 次执行对照中，ActPlane 组的 18 次合法操作均成功，越界效果均受阻，并有内核拒绝记录。真实 Agent 任务的补充验证中，也观察到收到拒绝结果后继续进行合法读取的行为。相关过程与记录可通过实验报告核查。

文件隔离和只读沙箱本身已经能阻止多种越界。这里更值得关注的增量，是任务约束与真实操作的衔接、跨执行路径的持续保护，以及在需要正常上报时利用来源信息作更细的判断。

研究机制可进一步阅读 ActPlane 论文与固定版本源码。从具体场景出发，应用日志之外的系统行为能够成为安全治理中可观察、可约束、可核查的一部分。
